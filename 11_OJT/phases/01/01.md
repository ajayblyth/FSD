The key thing to notice

There are 4 actual MongoDB collections:

┌─────────────────────────────┐
│ 1. users                    │
│ 2. events                   │
│ 3. bookings                 │
│ 4. promoCodes               │
└─────────────────────────────┘

But inside those collections, we have embedded structures:

events
  └── ticketTiers[]


bookings
  └── tickets[]

And we have references:

events.organizer
       ↓
     users


bookings.user
       ↓
     users


bookings.event
       ↓
     events


bookings.promoCode
       ↓
   promoCodes

So don't think:

User, Organizer, Attendee, Event, Ticket, Ticket Tier, Booking, Payment, Promo Code = 9 tables.

Instead think:

                 REAL-WORLD CONCEPTS
                         │
        ┌────────────────┼────────────────┐
        │                │                │
     Collection       Embedded         Reference
        │                │                │
        ▼                ▼                ▼
   User/Event/       TicketTier/      User/Event/
   Booking/          Ticket/          PromoCode
   PromoCode         Payment info

Organizer and Attendee are roles of User.
Ticket Tier belongs inside Event.
Purchased Ticket belongs inside Booking.
Payment information belongs inside Booking for our current scope.
Promo Code is its own collection and is referenced by Booking.

EVENT
 ├── N:1 → USER (organizer)
 ├── 1:N → BOOKINGS

BOOKING
 ├── N:1 → USER
 ├── N:1 → EVENT
 ├── N:1 → PROMO CODE
 └── 1:N → tickets[] [embedded]

PROMO CODE
 └── 1:N → BOOKINGS

2 embedded arrays: events.ticketTiers[], bookings.tickets[].
