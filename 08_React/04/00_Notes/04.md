=============================================================
React Context API + Props Notes
=============================================================
Props are data passed from a parent component to a child component.

FLOW:
Props → Prop Drilling → Context API → createContext()
→ Provider → useContext() → Custom Hook

=============================================================
1. PROPS
=============================================================

Props = "properties"

Used to pass data:
Parent → Child

In React, props are passed like key = value pairs:

<Component propName={value} />

+----------------------+----------------------------------+
| Features             | Meaning                          |
+----------------------+----------------------------------+
| One-way              | Parent → Child only              |
| Read-only            | Child should not modify props    |
| Reusable             | Same component, different data   |
+----------------------+----------------------------------+

--------------------------------------------------

Greeting.jsx

function Greeting({ name }) {

    return
     <h1>Hello, {name}!</h1>;

}

export default Greeting;

--------------------------------------------------

App.jsx

import Greeting from "./Greeting";

function App() {

    const username = "Alice";

    return <Greeting name={username} />;

}

export default App;

--------------------------------------------------

Output:

Hello, Alice!

--------------------------------------------------

+-------------------------+-------------------------------+
| How it works            | Props can pass                |
+-------------------------+-------------------------------+
| App has data            | String                        |
| name={username}         | Number                        |
| Greeting receives prop  | Array                         |
| function Greeting()     | Object                        |
|                         | Function                      |
+-------------------------+-------------------------------+

Examples:

<Product title="Phone" />
<Product price={30000} />
<Product features={["fast","secure"]} />
<Product data={{ brand:"Apple" }} />

=============================================================
2. WHY PROPS ARE GOOD
=============================================================

+--------------------------+-------------------------------+
| Best for                 | Example                       |
+--------------------------+-------------------------------+
| 1-2 levels of nesting    | App → Navbar → Button         |
| Direct communication     | Parent → Child                |
| Easy structure           | Small-medium apps             |
+--------------------------+-------------------------------+

=============================================================
3. PROP DRILLING
=============================================================

Passing props through components that DO NOT need them.

--------------------------------------------------

Problem Structure:

App (has username)
↓
Layout
↓
Page
↓
UserCard (needs username)

--------------------------------------------------

Problem:
- Layout/Page don't use username
- They only forward it
- Rename prop → change everywhere
- Deep trees become messy

--------------------------------------------------

Example:

function App() {
const username = "Ajay";
return <Layout username={username} />;
}

function Layout({ username }) {
return <Page username={username} />;
}

function Page({ username }) {
return <UserCard username={username} />;
}

function UserCard({ username }) {
return <p>Logged in as: {username}</p>;
}

--------------------------------------------------

Why Prop Drilling is Bad:
- Repetitive code
- Hard maintenance
- Rename prop everywhere
- Deep component chaos

Memory Line:

Props good for   → 1-2 levels
Context good for → Many levels

=============================================================
4. CONTEXT API
=============================================================

Context API = React solution for Prop Drilling.

Idea:
Any component can directly access shared data
without middle layers.

=============================================================
5. THREE MAIN THINGS
=============================================================

+------------------+--------------------------------+
| Thing            | Purpose                        |
+------------------+--------------------------------+
| createContext()  | Creates context channel        |
| Provider         | Broadcasts value               |
| useContext()     | Reads value anywhere           |
+------------------+--------------------------------+

=============================================================
6. STEP 1 → createContext()
=============================================================

UserContext.js

import { createContext } from "react";

const UserContext = createContext(null);

export default UserContext;

--------------------------------------------------

+------------------------------+------------------------------+
| What this does               | Important                    |
+------------------------------+------------------------------+
| Creates Context object       | Create outside component     |
| Creates communication channel| NOT inside App()             |
| Default value = null         | Avoid new context each render|
| Export for other files       |                              |
+------------------------------+------------------------------+

Naming Convention:
UserContext, ThemeContext, AuthContext

=============================================================
7. STEP 2 → Provider
=============================================================

App.jsx

import UserContext from "./UserContext";
import Home from "./Home";

function App() {

    const username = "Ajay";

    return (

        <UserContext.Provider value={username}>

            <Home />

        </UserContext.Provider>

    );

}

export default App;

---------------------------
Provider
   └── Home

or:

A box around child components

Why wrap?

Because every component INSIDE that wrapper
gets access to shared data.
--------------------------------------------------

Meaning:

value={username}
shared data = "Ajay"

All nested children can access it.

=============================================================
8. STEP 3 → useContext()
=============================================================

Profile.jsx

import { useContext } from "react";
import UserContext from "./UserContext";

function Profile() {

    const user = useContext(UserContext);

    return <h1>Hello {user}</h1>;

}

export default Profile;

--------------------------------------------------

Meaning:

useContext(UserContext)
reads value from Provider directly.

=============================================================
9. INTERMEDIATE COMPONENT
=============================================================

Home.jsx

import Profile from "./Profile";

function Home() {

    return <Profile />;

}

export default Home;

--------------------------------------------------

Notice:
Home did NOT receive props.

Still Profile received data.

12. WITH CONTEXT API
=============================================================

Provider stores data once.

Any child component can access directly.

13. GLOBAL CONTEXT PATTERN
=============================================================

Large apps usually create:

+----------------------+--------------------------------+
| File                 | Purpose                        |
+----------------------+--------------------------------+
| ThemeContext.js      | createContext()                |
| ThemeProvider.jsx    | Provider logic                 |
| useTheme.js          | Custom hook                    |
| App.jsx              | Wrap app                       |
| AnyComponent.jsx     | Consume context                |
+----------------------+--------------------------------+

--------------------------------------------------

Example Structure:

src/
│
├── context/
│   ├── ThemeContext.js
│   ├── ThemeProvider.jsx
│   └── useTheme.js

=============================================================
14. WHY CUSTOM HOOK?
=============================================================

Instead of repeating:

const value = useContext(ThemeContext);

Create reusable wrapper.

=============================================================
15. CUSTOM HOOK EXAMPLE
=============================================================

useTheme.js

import { useContext } from "react";
import ThemeContext from "./ThemeContext";

export function useTheme() {

    return useContext(ThemeContext);

}

--------------------------------------------------

Usage:

const theme = useTheme();

=============================================================
16. SAFETY GUARD
=============================================================

Avoid crashes if Provider missing.

useTheme.js

export function useTheme() {

const context = useContext(ThemeContext);

if (context === null) {

    throw new Error(
        "useTheme must be inside ThemeProvider"
    );

}

return context;

}

--------------------------------------------------

+-----------------------+-------------------------------+
| Without Guard         | With Guard                    |
+-----------------------+-------------------------------+
| useContext returns null| Clear readable error         |
| Confusing crashes      | Easier debugging             |
| null.theme crash       | "inside Provider" message    |
+-----------------------+-------------------------------+

=============================================================
17. COMMON MISTAKES
=============================================================

+--------------------------------+--------------------------------+
| Mistake                        | Fix                            |
+--------------------------------+--------------------------------+
| No Provider                    | Wrap app with Provider         |
| createContext inside component | Create outside component       |
| Not exporting hook             | export function useTheme()     |
| Passing single value only      | Pass object                    |
| Forgetting imports             | Import correctly               |
+--------------------------------+--------------------------------+

Better:

value={{
theme,
toggleTheme
}}

=============================================================
18. PROPS vs CONTEXT vs REDUX
=============================================================

+-------------+----------------------+----------------------+----------------------+
| Feature     | PROPS               | CONTEXT             | REDUX / RTK          |
+-------------+----------------------+----------------------+----------------------+
| Use for     | 1-2 levels          | Shared global data  | Large complex apps   |
| Best for    | Parent-child        | Theme/Auth/User     | Complex state        |
| Pros        | Simple, explicit    | No prop drilling    | Predictable          |
|             | Easy to understand  | Built into React    | DevTools             |
| Cons        | Prop drilling       | Re-renders          | More setup           |
+-------------+----------------------+----------------------+----------------------+

19. useState Previous State Assignment
=============================================================

Problem:

setCount(count + 1);

Sometimes uses OLD state value because state updates are async.

--------------------------------------------------

Correct:

setCount(prev => prev + 1);

--------------------------------------------------

Why?

React guarantees:
prev = latest updated state

--------------------------------------------------
