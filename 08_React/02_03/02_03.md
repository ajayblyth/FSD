## RETURNING MULTIPLE ELEMENTS

Rule:
A React component must return ONLY ONE parent/root element.

Wrong:

return (
<h1>Hello</h1>
<h1>World</h1>
)

Reason:
Two elements are side-by-side.

--------------------------------------------------

Correct Methods:
+----------------------+----------------------+
| Wrap inside div      | Use Fragment         |
+----------------------+----------------------+
| return (             | return (             |
| <div>                | <>                   |
|   <h1>Hello</h1>     |   <h1>Hello</h1>     |
|   <h1>World</h1>     |   <h1>World</h1>     |
| </div>               | </>                  |
| )                    | )                    |
+----------------------+----------------------+

Fragment:
- Groups multiple elements
- Does NOT create extra HTML tag
- Cleaner than unnecessary div
==================================================
+----------------------+------------------------------------------------------+
| Topic                | Details                                              |
+----------------------+------------------------------------------------------+
| JSX Rule 1           | Return single root element                           |
+----------------------+------------------------------------------------------+
| JSX Rule 2           | Close all tags                                       |
|                      | Correct: <img />                                     |
|                      | Wrong: <img>                                         |
+----------------------+------------------------------------------------------+
| JSX Rule 3           | Use camelCase                                        |
|                      | Examples: className, onClick, backgroundColor        |
+----------------------+------------------------------------------------------+
| className            | Used instead of class                                |
|                      | Reason: "class" is a JavaScript keyword              |
|                      | Example: <div className="box"></div>                 |
+----------------------+------------------------------------------------------+
| Curly Braces {}      | Inside {} code behaves like JavaScript               |
+----------------------+------------------------------------------------------+
| JSX Example          | <p>2 * 2 = {2 * 2}</p>                               |
|                      | Output: 2 * 2 = 4                                    |
+----------------------+------------------------------------------------------+
| Variable Example     | let msg = "Hello World";                             |
|                      | <p>Message says {msg}</p>                            |

## PROPS

Props = parameters/data passed to components.

--------------------------------------------------

Example:

<Product title="Phone"  price="30000" />   // string
<Product title="Laptop" price={40000} />  // number

--------------------------------------------------

Props can pass:
String, Number, Array, Object, Function

Examples:

features={["fast", "reliable"]}             // Array

features={{ a: "fast", b: "reliable" }}    // Object


--------------------------------------------------

Using Component:

App.jsx

import Product from "./Product";

function App() {

  return (

    <>

      <Product title="Phone" price="30000" features={["fast", "reliable"]}  />

      <Product title="Laptop" price={40000}  features={{ a: "fast", b: "reliable" }}  />
   
    </>

  );

}

export default App;

--------------------------------------------------

Receiving Props:

Product.jsx

export default function Product({ title, price, features }) {

  return (

    <div className="Product">

      <h4>{title}</h4>
      <p>{price}</p>

    </div>

  );

}

## CONDITIONAL RENDERING

Showing elements based on condition.

--------------------------------------------------

+------------------+-----------------------------------------------+------------------------------+
| Type             | Syntax                                        | Meaning                      |
+------------------+-----------------------------------------------+------------------------------+
| Ternary Operator | {condition ? <Element /> : null}              | true = show, false = nothing |
| AND Operator     | {condition && <Element />}                    | true = show, false = nothing |
+------------------+-----------------------------------------------+------------------------------+

Examples:

{price >= 10000 ? <p>Discount : 5%</p> : null}

{price >= 10000 && <p>Discount : 5%</p>}

STATE IN REACT
================================================================================

State
-----
• Built-in React mechanism to store dynamic (changing) data inside a component.
• State belongs to the component.
• When state changes, React automatically re-renders the component and updates
  the UI.

Interview Answer
----------------
"State is a built-in React mechanism used to store dynamic data inside a
component. Unlike normal JavaScript variables, when state changes through the
state setter function, React automatically re-renders the component so the UI
stays in sync with the latest data."

================================================================================
Why do we need State?
================================================================================

Problem:

function Counter() {

    let count = 0;

    function increment() {
        count++;
        console.log(count);
    }

    return (
        <>
            <h1>{count}</h1>

            <button onClick={increment}>
                Increment
            </button>
        </>
    );
}

Output:

Console:
1
2
3

UI:
0

Why?

• count is just a normal JavaScript variable.
• React does NOT track normal variables.
• Updating count does not trigger a re-render.
• On every render:

      let count = 0;

  executes again, so the variable is recreated and reset.

================================================================================
Solution : useState
================================================================================

import { useState } from "react";

function Counter() {

    const [count, setCount] = useState(0);

    function increment() {
        setCount(count + 1);
    }

    return (
        <>
            <h1>{count}</h1>

            <button onClick={increment}>
                Increment
            </button>
        </>
    );

}

Now whenever count changes:

• React updates the state.
• Component re-renders.
• UI automatically displays the latest value.

================================================================================
What is useState()?
================================================================================

useState is a React Hook that lets you add and manage state inside a functional
component.

Syntax:

const [state, setState] = useState(initialState);

Example:

const [count, setCount] = useState(0);

================================================================================
Understanding the Syntax
================================================================================

const [count, setCount] = useState(0);

count
    → Current state value

setCount()
    → Setter function used to update the state

0
    → Initial state value

Initially:

count = 0

After:

setCount(1);

React stores:

count = 1

Then React automatically re-renders the component.

================================================================================
What does useState() return?
================================================================================

useState() returns an array containing exactly two values:

1. Current state value

   count

2. Setter function

   setCount()

The setter function:
• Updates the state.
• Triggers a component re-render.
• Updates the UI with the latest state value.

================================================================================
Why use setCount() instead of count++ ?
================================================================================

Wrong:

count++;

Reason:

• Only changes the JavaScript variable.
• React does not know anything changed.
• No re-render.
• UI remains the same.

Correct:

setCount(count + 1);

Reason:

• Updates React state.
• React tracks the change.
• Component re-renders.
• UI updates automatically.

================================================================================
Flow
================================================================================

Component Renders
        ↓
State = 0
        ↓
User Clicks Button
        ↓
setCount(count + 1)
        ↓
React Updates State
        ↓
Component Re-renders
        ↓
UI Displays Updated Value
==================================================
Important About setCount()
==================================================

setCount() is asynchronous.

Example:

function handleIncrement() {

    setCount(count + 1);

    console.log(count);

}

--------------------------------------------------

Why old value prints?

Because:
- React schedules state update
- current function continues execution
- console.log runs before re-render finishes

So console may show previous value temporarily.

HOOKS IN REACT
================================================================================

What are Hooks?
--------------------------------------------------------------------------------

Interview Definition:

"Hooks are special built-in functions introduced in React 16.8 that allow
functional components to use React features such as state, lifecycle methods,
context, refs, and more, without writing class components."

Simple Definition:

Hooks are special React functions that let functional components "hook into"
React features.

Hooks allow us to use:
• State
• Lifecycle features
• React functionality

inside FUNCTIONAL COMPONENTS without writing class components.

================================================================================
Why were Hooks introduced?
================================================================================

Before React 16.8, there were mainly two types of components:

1. Class Components
2. Functional Components

--------------------------------------------------
Class Components
--------------------------------------------------

• Could manage state
• Could use lifecycle methods
• More complex syntax

--------------------------------------------------
Functional Components
--------------------------------------------------

• Simple JavaScript functions
• Could only return JSX
• Could NOT use state or lifecycle methods initially

--------------------------------------------------
After Hooks (React 16.8)
--------------------------------------------------

Hooks made Functional Components powerful.

Now Functional Components can:

• Manage state
• Handle side effects
• Access context
• Optimize performance
• Share reusable logic
• Access DOM elements using refs

Because of Hooks:

• Class Components became less common
• Modern React mainly uses Functional Components

================================================================================
Basic Hook Syntax
================================================================================

Example:

import { useState } from "react";

function Counter() {

    const [count, setCount] = useState(0);

}

Here, useState() is a Hook that adds state to a functional component.

================================================================================
Rules of Hooks
================================================================================

• Hook names always start with "use"
• Call Hooks only at the top level of a component
• Do NOT call Hooks inside loops, conditions, or nested functions
• Call Hooks only inside React Functional Components or Custom Hooks

================================================================================
Types of Hooks
================================================================================

1. State Hooks
2. Effect Hooks
3. Context Hooks
4. Performance Hooks
5. Ref Hooks
6. Other Built-in Hooks

================================================================================
1. State Hooks
================================================================================

Purpose:
• Store and update dynamic data

Common Hook:

useState()

Example:

const [count, setCount] = useState(0);

When state changes:

• React updates the state
• Component re-renders
• UI updates automatically

================================================================================
2. Effect Hooks
================================================================================

Purpose:
• Perform side effects

Common Hook:

useEffect()

Common Uses:

• API calls
• Fetching data
• Timers
• Subscriptions
• DOM operations
• Event listeners

================================================================================
3. Context Hooks
================================================================================

Purpose:
• Share data globally between components

Common Hook:

useContext()

Helps avoid:

• Prop Drilling (passing props through multiple intermediate components)

Common Uses:

• Theme
• Authentication
• Logged-in user
• Language settings

================================================================================
4. Performance Hooks
================================================================================

Purpose:
• Optimize application performance

Common Hooks:

• useMemo()
• useCallback()

Benefits:

• Avoid unnecessary calculations
• Reduce unnecessary function recreation
• Reduce unnecessary re-rendering
• Improve performance

================================================================================
5. Ref Hooks
================================================================================

Common Hook:

useRef()

Purpose:

• Directly access DOM elements
• Store mutable values without causing re-renders
• Focus input fields
• Persist values between renders

================================================================================
6. Other Important Hooks
================================================================================

• useReducer()
• useLayoutEffect()
• useImperativeHandle()
• useTransition()
• useId()

================================================================================
Why Hooks are Important
================================================================================

Benefits:

• Simpler code
• Cleaner components
• Reusable logic
• Easier maintenance
• Functional programming style
• Reduced need for Class Components

================================================================================
Examples of Common Hooks
================================================================================

useState()      → Manage state

useEffect()     → Perform side effects

useContext()    → Access shared/global data

useRef()        → Access DOM elements or store mutable values

useMemo()       → Memoize expensive calculations

useCallback()   → Memoize functions

================================================================================
Modern React
================================================================================

Modern React applications mainly use:

• Functional Components
• Hooks

instead of Class Components.
