A component contains:
* Structure (HTML/JSX)
* Logic (JavaScript)
* Sometimes styling

## RETURNING MULTIPLE ELEMENTS

Rule:
A React component must return ONLY ONE parent/root element.

Wrong:

return (
<h1>Hello</h1>
<h1>World</h1>
)

Reason:
Two elements are side-by-side.

--------------------------------------------------

Correct Methods:
+----------------------+----------------------+
| Wrap inside div      | Use Fragment         |
+----------------------+----------------------+
| return (             | return (             |
| <div>                | <>                   |
|   <h1>Hello</h1>     |   <h1>Hello</h1>     |
|   <h1>World</h1>     |   <h1>World</h1>     |
| </div>               | </>                  |
| )                    | )                    |
+----------------------+----------------------+

Fragment:
- Groups multiple elements
- Does NOT create extra HTML tag
- Cleaner than unnecessary div
==================================================
+----------------------+------------------------------------------------------+
| Topic                | Details                                              |
+----------------------+------------------------------------------------------+
| JSX Rule 1           | Return single root element                           |
+----------------------+------------------------------------------------------+
| JSX Rule 2           | Close all tags                                       |
|                      | Correct: <img />                                     |
|                      | Wrong: <img>                                         |
+----------------------+------------------------------------------------------+
| JSX Rule 3           | Use camelCase                                        |
|                      | Examples: className, onClick, backgroundColor        |
+----------------------+------------------------------------------------------+
| className            | Used instead of class                                |
|                      | Reason: "class" is a JavaScript keyword              |
|                      | Example: <div className="box"></div>                 |
+----------------------+------------------------------------------------------+
| Curly Braces {}      | Inside {} code behaves like JavaScript               |
+----------------------+------------------------------------------------------+
| JSX Example          | <p>2 * 2 = {2 * 2}</p>                               |
|                      | Output: 2 * 2 = 4                                    |
+----------------------+------------------------------------------------------+
| Variable Example     | let msg = "Hello World";                             |
|                      | <p>Message says {msg}</p>                            |
+----------------------+------------------------------------------------------+

## PROPS

Props = parameters/data passed to components.

--------------------------------------------------

Example:

<Product title="Phone"  price="30000" />   // string
<Product title="Laptop" price={40000} />  // number

--------------------------------------------------

Props can pass:
String, Number, Array, Object, Function

Examples:

features={["fast", "reliable"]}             // Array

features={{ a: "fast", b: "reliable" }}    // Object

--------------------------------------------------

Receiving Props:

Product.jsx

export default function Product({ title, price, features }) {

  return (

    <div className="Product">

      <h4>{title}</h4>
      <p>{price}</p>

    </div>

  );

}

--------------------------------------------------

Using Component:

App.jsx

import Product from "./Product";

function App() {

  return (

    <>
      <Product
        title="Phone"
        price="30000"
        features={["fast", "reliable"]}
      />

      <Product
        title="Laptop"
        price={40000}
        features={{ a: "fast", b: "reliable" }}
      />
    </>

  );

}

export default App;

## CONDITIONAL RENDERING

Showing elements based on condition.

--------------------------------------------------

+------------------+-----------------------------------------------+------------------------------+
| Type             | Syntax                                        | Meaning                      |
+------------------+-----------------------------------------------+------------------------------+
| Ternary Operator | {condition ? <Element /> : null}              | true = show, false = nothing |
| AND Operator     | {condition && <Element />}                    | true = show, false = nothing |
+------------------+-----------------------------------------------+------------------------------+

Examples:

{price >= 10000 ? <p>Discount : 5%</p> : null}

{price >= 10000 && <p>Discount : 5%</p>}

State in React
==================================================

State:
- built-in React object/data
- stores dynamic/changing data

When state changes:
- component re-renders automatically
- UI updates automatically

==================================================
Why Normal Variable Fails
==================================================

Problem:

function Counter() {

    let count = 0;

    function handleIncrement() {
        count++;
    }

}

--------------------------------------------------

Reason:

count is a NORMAL variable,
not a React state variable.

Every re-render runs:

    let count = 0;

again and resets value.

React does NOT track normal variables.

So:

    count++;

changes variable internally,
but UI does not update.

==================================================
Correct Solution : useState
==================================================

Example:

import { useState } from "react";

function Counter() {

    const [count, setCount] = useState(0);

    function handleIncrement() {

        setCount(count + 1);

    }

    return (

        <div>

            <p>Count: {count}</p>

            <button onClick={handleIncrement}>
                Increment
            </button>

        </div>

    );

}

--------------------------------------------------

Explanation:

useState(0)
- creates state variable
- initial value = 0

count
- current state value

setCount()
- updates state

When state changes:
- React re-renders component
- UI updates automatically

useState()

useState is a React Hook that lets you add a state variable to your component.

const [state, setState] = useState(initialState);

useState returns an array with exactly two values:

1. The current state. During the first render, it will match the initialState you have passed.
2. The set function that lets you update the state to a different value and trigger a re-render (UI updates again with new state value).
==================================================
Important About setCount()
==================================================

setCount() is asynchronous.

Example:

function handleIncrement() {

    setCount(count + 1);

    console.log(count);

}

--------------------------------------------------

Why old value prints?

Because:
- React schedules state update
- current function continues execution
- console.log runs before re-render finishes

So console may show previous value temporarily.

Hooks in React
==================================================

Hooks were introduced in React 16.8.

Hooks allow us to use:
- state
- lifecycle features
- React functionality

inside FUNCTIONAL COMPONENTS
without writing class components.

==================================================
Before Hooks
==================================================

Earlier React mainly used:

1. Class Components
2. Functional Components

--------------------------------------------------

Class Components:
- could use state
- could use lifecycle methods
- more complex syntax

Functional Components:
- simple functions
- could NOT use state initially

==================================================
After Hooks
==================================================

Hooks made Functional Components powerful.

Now functional components can:
- manage state
- handle side effects
- optimize performance
- share logic
- access context

Because of Hooks:
- class components became less common
- modern React mainly uses functional components

==================================================
Basic Hook Syntax
==================================================

Example:

import { useState } from "react";

function Counter() {

    const [count, setCount] = useState(0);

}

--------------------------------------------------

Rules:
- Hooks start with "use"
- Hooks are called inside components
- Hooks should not be called inside loops/conditions

==================================================
Types of Hooks
==================================================

1. State Hooks
2. Effect Hooks
3. Context Hooks
4. Performance Hooks
5. Ref Hooks
6. Other Built-in Hooks

==================================================
1. State Hooks
==================================================

Used for storing/changing data.

Common Hook:

- useState()

Example:

const [count, setCount] = useState(0);

--------------------------------------------------

Purpose:
- stores dynamic data
- updates UI automatically

==================================================
2. Effect Hooks
==================================================

Used for side effects.

Common Hook:

- useEffect()

Used for:
- API calls
- timers
- fetching data
- subscriptions
- DOM operations

==================================================
3. Context Hooks
==================================================

Used for sharing data globally.

Common Hook:

- useContext()

Helps avoid:
- prop drilling

Used for:
- theme
- authentication
- user data
- language settings

==================================================
4. Performance Hooks
==================================================

Used for optimization.

Common Hooks:
- useMemo()
- useCallback()

Purpose:
- avoid unnecessary calculations
- improve performance
- reduce re-rendering

==================================================
5. Ref Hooks
==================================================

Common Hook:

- useRef()

Used for:
- directly accessing DOM
- storing mutable values
- focusing inputs

==================================================
6. Other Important Hooks
==================================================

- useReducer()
- useLayoutEffect()
- useImperativeHandle()
- useTransition()
- useId()

==================================================
Why Hooks are Important
==================================================

Benefits:
- simpler code
- reusable logic
- cleaner components
- easier maintenance
- functional programming style
- reduced class component usage

==================================================
Modern React
==================================================

Modern React applications mainly use:

- Functional Components
- Hooks

instead of Class Components.
