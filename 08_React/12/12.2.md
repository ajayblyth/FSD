
#########################################################################################
3. useMemo
#########################################################################################

Until now we learned

useRef

It stores values between renders without causing re-render.

Now let's learn another performance hook:

useMemo.


=========================================================================================
Why do we need useMemo?
=========================================================================================

Remember what happens during every render.

Component renders
        │
        ▼

Variables recreated

Functions recreated

Objects recreated

Calculations run again

Even if nothing changed,
React executes the component function again.

Problem:

Suppose we have a calculation that takes

1 second

or even

5 seconds.

Every render,

that calculation executes again.

Very inefficient.


Example

```jsx
const total = expensiveCalculation();

Even if

only theme changes,

React still runs

expensiveCalculation()

again.

This is what we want to avoid.


=========================================================================================
Definition
=========================================================================================

useMemo

does NOT redo an expensive calculation.

Instead,

it remembers (caches) the previous result.

If dependencies DO NOT change,

React simply returns the saved result.

If dependencies change,

React calculates again,

then stores the new result.


Think of it like

Question already solved?

        │
        ▼

YES

↓

Return saved answer.


Dependency changed?

↓

YES

↓

Calculate again.

↓

Save new answer.

↓

Return new result.


=========================================================================================
Syntax
=========================================================================================

```jsx
const value = useMemo(() => {

    return expensiveCalculation();

}, [dependency]);

Short version

```jsx
const doubled = useMemo(
    () => slowDouble(number),
    [number]
);

Meaning

↓

Run

slowDouble()

ONLY

when

number

changes.


=========================================================================================
Folder Structure
=========================================================================================

src
│
└── useMemo
      │
      └── SlowEx.jsx


Import it inside

App.jsx


#########################################################################################
Slow Example
#########################################################################################

SlowEx.jsx

```jsx
import React, { useState } from "react";

const slowDouble = (num) => {

  console.log("Running the slow calc");

  const start = Date.now();

  while (Date.now() - start < 1000) {}

  return num * 2;
};

const SlowEx = () => {

  const [number, setNumber] = useState(1);

  const [dark, setDark] = useState(false);

  const doubled = slowDouble(number);

  const theme = {
    backgroundColor: dark ? "#333" : "#FFFFFF",
    color: dark ? "#FFFFFF" : "#000000",
    padding: "1rem",
  };

  return (

    <div style={theme}>

      <input
        type="number"
        value={number}
        onChange={(e) =>
          setNumber(Number(e.target.value))
        }
      />

      <button onClick={() => setDark(!dark)}>
        Toggle Theme
      </button>

      <h2>Doubled : {doubled}</h2>

    </div>

  );
};

export default SlowEx;


#########################################################################################
What happens here?
#########################################################################################

Suppose

number = 5

React runs

slowDouble(5)

↓

Waits

1 second

↓

Returns

10

Everything looks fine.

Now,

click

Toggle Theme.

Did

number

change?

NO.

Did

slowDouble()

run again?

YES.

WHY?

Because

the component

re-rendered.

React executes

the entire component

again.

That includes

slowDouble(number).

Even though

number

didn't change.

This is inefficient.


Flow

Theme Changed

↓

Component Rendered Again

↓

slowDouble()

↓

Wait 1 second

↓

Same Answer Again

↓

Waste of time.


#########################################################################################
How useMemo fixes this
#########################################################################################

Instead of

```jsx
const doubled = slowDouble(number);

we write

```jsx
const doubled = useMemo(() => {

    return slowDouble(number);

}, [number]);

Now,

if only

theme

changes,

React checks

Did

number

change?

↓

NO

↓

Return cached value.

↓

Do NOT call

slowDouble()

again.


Only when

number

changes,

React will

Run calculation

↓

Save result

↓

Return new value.


#########################################################################################
Flow Comparison
#########################################################################################

Without useMemo

Render

↓

slowDouble()

↓

Runs EVERY render

↓

Slow


-------------------------------------------------------


With useMemo

Render

↓

Dependency changed?

↓

NO

↓

Return saved answer


Dependency changed?

↓

YES

↓

Run calculation

↓

Save answer

↓

Return result


#########################################################################################
What exactly is cached?
#########################################################################################

Very Important

useMemo

does NOT save

the function.

It saves

the RESULT

returned by the function.

Example

```jsx
const doubled = useMemo(() => {

    return slowDouble(number);

}, [number]);

If

number = 5

Result

10

is stored.

Later,

theme changes.

React simply returns

10

without calling

slowDouble()

again.


#########################################################################################
Another Problem - Objects
#########################################################################################

Remember from the beginning.

Every render,

objects are recreated.

Example

```jsx
const theme = {

    backgroundColor: dark ? "#333" : "#FFF",

    color: dark ? "#FFF" : "#000",

    padding: "1rem"

};

Looks harmless.

But

EVERY render

creates

a NEW object.

Even if values are identical.

Example

Render 1

theme

↓

Object A


Render 2

theme

↓

Object B

Different object.

Same values.

Different memory location.


This becomes a problem when

theme

is passed as props

to child components.

React thinks

it's a new object,

so child components

may re-render unnecessarily.


Later,

we'll solve this using

useMemo.


Example

```jsx
const theme = useMemo(() => {

    return {

        backgroundColor: dark ? "#333" : "#FFF",

        color: dark ? "#FFF" : "#000",

        padding: "1rem"

    };

}, [dark]);

Now,

theme

is recreated

ONLY

when

dark

changes.


#########################################################################################
Important Notes
#########################################################################################

useMemo is useful for

✔ Expensive calculations

✔ Large filtering

✔ Large sorting

✔ Heavy loops

✔ Large object creation

✔ Objects passed as props


Don't use it everywhere.

Memoization also has a small cost.

Only use it

when optimization is actually needed.
