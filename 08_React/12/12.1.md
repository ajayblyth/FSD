=========================================================================================
React Performance - Why useRef, useMemo & useCallback exist
=========================================================================================

Problem
-------
Whenever state or props change, React re-renders.

State/Prop change means:
- Whole component function executes again.
- Child components also re-render (unless optimized).
- During every render:
    • Variables are recreated.
    • Functions are recreated.
    • Objects are recreated.
    • Calculations happen again.

React re-renders when:
1. State changes inside a component.
2. Props received by a component change.
3. Parent component re-renders (its child components also re-render).

Problems caused:
---------------
- Expensive calculations run again.
- New objects are created every render.
- New functions are created every render.
- Unnecessary rendering happens.
- Performance decreases as application grows.

Example:

function App(){

    const obj = {};

    function greet(){
        console.log("Hello");
    }

    const total = 10 + 20;

    return ...
}

When App re-renders,
everything above is created again.

Even though total is still 30,
React executes that line again.


=========================================================================================
How do we solve this?
=========================================================================================

High level:

On every render, everything is rebuilt.

To optimize this, React provides mainly these hooks:

1. useRef
2. useMemo
3. useCallback

We also have

React.memo()

React.memo is a Higher Order Component (HOC).

It prevents unnecessary child component re-renders.

(Not covered yet. Just know it exists and continue with the flow.)


#########################################################################################
1. useRef
#########################################################################################

Definition
----------
useRef is like a box that survives renders and never triggers a re-render,
unlike useState.

Syntax
------

const myRef = useRef(initialValue);

It always returns an object.

Example:

const myRef = useRef(10);

console.log(myRef);

Output

{
    current: 10
}

Access value using

myRef.current


=========================================================================================
Why does useRef survive re-renders?
=========================================================================================

Very Important

The useRef object itself is created only once.

On every render,
React gives back the SAME object.

Only the value inside

.current

changes.

Example

Render 1

myRef
 ↓

{
   current: 5
}

Later

myRef.current = 20

Render 2

myRef
 ↓

Same object

{
   current: 20
}

Notice:

Object is same.

Only current changes.

That's why useRef remembers values between renders.


=========================================================================================
Why doesn't useRef trigger re-render?
=========================================================================================

React watches

✔ State
✔ Props

React DOES NOT watch

✖ ref.current

So,

myRef.current = 500;

changes the value,

but React doesn't know or care.

Therefore,

NO RE-RENDER.

This is why useRef is perfect for storing background values.


=========================================================================================
useState vs useRef
=========================================================================================

Need UI to update?

→ useState

Need value only in background?

→ useRef


Comparison

useState                              useRef
--------------------------------------------------------------------------------
Stores UI state                       Stores mutable values
Causes re-render                      Doesn't re-render
Used for UI updates                   Used for background values
Returns value + setter                Returns object
count                                 ref.current
React tracks it                       React ignores .current updates


Rule
----

If user should SEE the updated value on screen,
use useState.

If value changes only for logic/background,
use useRef.


Examples of useRef
------------------

✔ Previous value
✔ Timer ID
✔ DOM element
✔ Focus input
✔ Stopwatch
✔ Mutable variables


#########################################################################################
Example 1 : Render Counter
#########################################################################################

Folder Structure

src
│
└── useRef
      │
      └── RenderCounter.jsx


RenderCounter.jsx

import React, { useState, useEffect, useRef } from "react";

const RenderCounter = () => {

  const [text, setText] = useState("");

  const renderCount = useRef(1);

  useEffect(() => {
    renderCount.current = renderCount.current + 1;
  });

  return (
    <div>

      <input
        type="text"
        value={text}
        onChange={(e) => setText(e.target.value)}
      />

      <h3>Typing : {text}</h3>

      <h3>
        Component rendered {renderCount.current} times
      </h3>

    </div>
  );
};

export default RenderCounter;


Explanation
-----------

renderCount is NOT state.

If we wrote

const [renderCount, setRenderCount] = useState(1);

and inside useEffect

setRenderCount(renderCount + 1);

Then,

Render
   ↓
useEffect
   ↓
setState
   ↓
Render
   ↓
useEffect
   ↓
setState
   ↓
Forever...

Infinite loop.

Instead,

renderCount.current changes silently.

React does NOT re-render.


#########################################################################################
Example 2 : Previous Value Tracker (Very Important)
#########################################################################################

This is one of the most common useRef interview questions.

import { useEffect, useRef, useState } from "react";

function PreviousValueTracker() {

  const [text, setText] = useState("");

  const previousValue = useRef("");

  useEffect(() => {
    previousValue.current = text;
  }, [text]);

  return (
    <div>

      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
      />

      <h3>Current : {text}</h3>

      <h3>Previous : {previousValue.current}</h3>

    </div>
  );
}

export default PreviousValueTracker;

How does this work?
-------------------

Initially

Render 1

text = ""

previous = ""

UI

Current :
Previous :


-----------------------------------------

User types

A

React renders again.

During Render 2

text = "A"

previousValue.current

is STILL

""

because useEffect has NOT executed yet.

UI shows

Current : A

Previous :

After rendering finishes,

useEffect runs

previousValue.current = "A"

-----------------------------------------

User types

B

React renders again.

During Render 3

text = "B"

previousValue.current

is still

"A"

because useEffect from the previous render already stored it.

UI shows

Current : B

Previous : A

After rendering,

useEffect executes

previousValue.current = "B"

-----------------------------------------

User types

C

UI shows

Current : C

Previous : B

Now it becomes obvious why useRef stores previous values.

It remembers the value from the previous render.


#########################################################################################
Summary of useRef
#########################################################################################

✔ Stores mutable values.

✔ Survives re-renders.

✔ Doesn't trigger rendering.

✔ Perfect for:
    - DOM references
    - Previous values
    - Timer IDs
    - Background variables
    - Values React doesn't need to display

Think of it like:

A small storage box that React keeps alive between renders,
without telling React to render again.

#########################################################################################
2. useRef - DOM Manipulation
#########################################################################################

Until now we used useRef to store values.

Another very common use of useRef is

DOM Manipulation.

Normally in React we DO NOT manually touch HTML elements.

But sometimes we need to:

✔ Focus an input
✔ Scroll to an element
✔ Play/Pause a video
✔ Select text
✔ Measure element width/height

For these cases, useRef gives us direct access to the DOM element.


How does it work?
-----------------

HTML Element
      │
      ▼
<input ref={inputRef} />

      │
      ▼

React stores that DOM element inside

inputRef.current

So,

inputRef.current

is NOT just a value.

It is the actual HTML input element.


#########################################################################################
Example 1 : Focus Input
#########################################################################################

Folder Structure

src
│
└── useRef
      │
      └── FocusInput.jsx


FocusInput.jsx

import React, { useRef } from "react";

const FocusInput = () => {

  const inputRef = useRef(null);

  const handleFocus = () => {
    inputRef.current.focus();
  };

  return (
    <div>

      <input
        ref={inputRef}
        type="text"
        placeholder="Click the button"
      />

      <button onClick={handleFocus}>
        Focus Input
      </button>

    </div>
  );
};

export default FocusInput;


Explanation
-----------

Initially

inputRef.current = null

because the input element has not been created yet.

After React renders,

React automatically stores

the actual input element

inside

inputRef.current

So now,

inputRef.current

becomes something like

<input ... />

(Actual DOM element)

When we click

Focus Input

this line executes

inputRef.current.focus();

focus()

is a built-in JavaScript DOM method.

Result:

Cursor immediately moves inside the textbox.


Flow

Button Click
      │
      ▼

handleFocus()

      │
      ▼

inputRef.current.focus()

      │
      ▼

Input gets focused


Why useRef here?
----------------

If we stored the input element inside useState,

every change would cause re-render.

That makes no sense.

We simply need a reference to the DOM element.

So,

useRef is the correct choice.


Other DOM methods
-----------------

Once you have

inputRef.current

you can call many DOM methods.

Example

inputRef.current.focus()

inputRef.current.blur()

inputRef.current.select()

inputRef.current.value

etc.


#########################################################################################
Example 2 : Stopwatch
#########################################################################################

Folder Structure

src
│
└── useRef
      │
      └── Stopwatch.jsx


Purpose
-------

Create a stopwatch that

✔ Starts timer
✔ Stops timer
✔ Resets timer

Question:

Should timerId be state?

No.

Because user never sees timerId.

User only sees

seconds.

So,

seconds

should be state.

timerId

should be useRef.


Code

import React, { useEffect, useRef, useState } from "react";

const Stopwatch = () => {

  const [seconds, setSeconds] = useState(0);

  const timerId = useRef(null);

  const start = () => {

    if (timerId.current !== null) return;

    timerId.current = setInterval(() => {

      setSeconds((prev) => prev + 1);

    }, 1000);

  };

  const stop = () => {

    clearInterval(timerId.current);

    timerId.current = null;

  };

  const reset = () => {

    stop();

    setSeconds(0);

  };

  useEffect(() => {

    return () => {
      clearInterval(timerId.current);
    };

  }, []);

};

export default Stopwatch;


Explanation
-----------

timerId stores something like

7

15

23

etc.

These IDs are returned by

setInterval().

User never sees them.

So they don't belong in state.


Flow
----

Click Start

↓

setInterval()

↓

Returns timer ID

↓

Store inside

timerId.current

↓

Every second

↓

setSeconds()

↓

UI updates


Notice

Only

seconds

causes rendering.

timerId

never causes rendering.


#########################################################################################
Why not useState for timerId?
#########################################################################################

Suppose we wrote

const [timerId, setTimerId] = useState(null);

Now,

Every time timer starts,

setTimerId()

would cause

another render.

Completely unnecessary.

We only need timerId

internally.

Therefore,

useRef is the correct solution.


#########################################################################################
Cleaning Up
#########################################################################################

Very Important

When component unmounts,

the timer should stop.

Otherwise,

setInterval()

keeps running in memory.

This is called

Memory Leak.

So we clean it up.

useEffect(() => {

  return () => {
    clearInterval(timerId.current);
  };

}, []);

The returned function is called

Cleanup Function.

It runs

✔ Before component is removed.

✔ Before effect runs again (if dependencies change).

Summary of useRef
#########################################################################################

useRef has TWO major purposes.

1.

Store mutable values

Examples

✔ Timer ID

✔ Previous value

✔ Counter

These values survive renders

2.

Access DOM Elements

Examples

✔ Focus input

✔ Measure width

Remember

Need background storage?

Need DOM element?
