=====================================================================
NPM (NODE PACKAGE MANAGER) - NODE.JS (CLEAN + STRUCTURED)
=====================================================================

DEFINITION
---------------------------------------------------------------------
• NPM → Default package manager for Node.js
• Used to install, manage, share packages (npmjs.com)

---------------------------------------------------------------------
KEY COMPONENTS
---------------------------------------------------------------------

1. PACKAGE
   • Reusable code (library/module)
   • Example → express, axios

---------------------------------------------------------------------

2. package.json (MAIN FILE)
   • Stores project info, 
   dependencies, scripts

DEPENDENCIES
---------------------------------------------------------------------
• A dependency is an external package/library that your project needs
  to work properly.• examples → express, axios
• install → npm install <pkg>
• uninstall → npm uninstall <pkg>   (e.g., npm uninstall express)

DEVDEPENDENCIES
---------------------------------------------------------------------
• devDependencies → Only for development
• Example → nodemon, jest (JavaScript testing framework )
• Install → npm install <pkg> --save-dev

nodemon- • Tool that automatically restarts Node.js server when files change  
• Used in development (not production)

1) GLOBAL INSTALL (OLD / SIMPLE WAY)
=====================================================================

npm install -g nodemon
RUN:
nodemon app.js

✔ Works from anywhere in system  
❌ Not project-specific (not recommended in modern projects)


=====================================================================
2) LOCAL INSTALL (RECOMMENDED)
=====================================================================

npm install --save-dev nodemon
WHAT IT DOES:
• installs nodemon into your project (node_modules)
• saves it as dev dependency

---------------------------------------
npx nodemon app.js

✔ Installed inside project  
✔ Works per project  
✔ Best practice

Note: npx (Node Package Execute)
npx is a Node tool that runs npm packages directly without installing
them globally, by temporarily fetching and executing them.

HOW IT WORKS
=====================================================================
1) Checks if package is installed locally  
2) If not → downloads temporarily  
3) Runs it  
4) Deletes temporary copy (if not installed)

DIFFERENCE
---------------------------------------------------------------------
• dependencies → runtime
• devDependencies → development
• Production skips devDependencies

---------------------------------------------------------------------

3. SCRIPTS
---------------------------------------------------------------------
• Custom commands inside package.json
• Format → "key": "command"

{
  "name": "my-app",
  "version": "1.0.0",
  "scripts": {
    "start": "node app.js",
    "dev": "nodemon app.js",
    "hello": "Hello Ajay"
  }
}


=====================================================================
HOW TO RUN
=====================================================================

npm start
→ runs: node app.js

npm run dev
→ runs: nodemon app.js

npm run hello
→ output: Hello Ajay

Note:
• "start" is special → can run without "run"  
• Others need → npm run <name>

---------------------------------------------------------------------

4. node_modules
---------------------------------------------------------------------
• Folder storing all installed packages
• Auto-created by npm

---------------------------------------------------------------------

5. package-lock.json
---------------------------------------------------------------------
• Auto-generated file
• Stores exact versions (no changes)
• Ensures same install everywhere

=====================================================================
package.json vs node_modules (DEPENDENCIES)
=====================================================================

📦 package.json
------------------------------------------------
• Your project’s dependency list (blueprint)
• Only shows WHAT you need

Example:
"dependencies": {
  "express": "^4.18.0"
}

👉 It does NOT contain actual code

📦 node_modules
------------------------------------------------
• Actual downloaded packages (real code)
• Contains express + ALL its internal dependencies

👉 This is WHERE code actually lives


=====================================================================
HOW THEY ARE CONNECTED
=====================================================================

package.json
     ↓
npm install
     ↓
node_modules gets created

👉 npm reads package.json and installs everything into node_modules


=====================================================================
IMPORTANT CONCEPT (INTERVIEW)
=====================================================================

✔ package.json → direct dependencies (your choice)
✔ node_modules → full dependency tree (your + their dependencies)

=====================================================================
KEY POINT
=====================================================================

👉 You never manually manage node_modules  
👉 npm builds it automatically using package.json

------------------------------------------------------------------
NPM COMMANDS (EXPLAINED)
------------------------------------------------------------

1. npm init
• First command to run in any Node project ✔
• Creates package.json by asking questions (name, version, etc.)
• Sets up project configuration

------------------------------------------------------------

2. npm init -y
• Same as npm init but skips all questions
• Automatically creates package.json with default values
• Faster way to start project

------------------------------------------------------------

3. npm install <pkg>
• Installs package locally (inside node_modules)
• Adds it to dependencies in package.json
• Used when package is needed only for this project

------------------------------------------------------------

4. npm install -g <pkg>
• Installs package globally (usable anywhere in system)
• Not added to project’s package.json
• Used for tools like nodemon, typescript

------------------------------------------------------------

5. npm uninstall <pkg>
• Removes package from node_modules
• Also removes from package.json dependencies
• Keeps project clean from unused packages

------------------------------------------------------------

6. npm install pkg@version
• Installs a specific version of a package
• Useful to avoid breaking changes from latest version
• Example: npm install express@4.18.2

------------------------------------------------------------

SUMMARY
------------------------------------------------------------
Start → npm init ✔
Then install/remove/manage packages using npm commands

---------------------------------------------------------------------
LOCAL vs GLOBAL (IMPORTANT)
---------------------------------------------------------------------
• Default → local install (node_modules)
• Works only inside that project
• Running app.js outside → module not found
• Global → npm install -g <pkg>
• Can run anywhere (e.g., nodemon)

---------------------------------------------------------------------
WORKFLOW
---------------------------------------------------------------------
1. npm init
2. npm install <pkg>
3. Use in code
4. Run using scripts

---------------------------------------------------------------------
PACKAGE.JSON vs PACKAGE-LOCK.JSON
---------------------------------------------------------------------
• package.json → what to install
• package-lock.json → exact installed version

Note:
✔ node → runs JavaScript outside browser  
✔ npm → installs packages (libraries)  
✔ npx → runs packages without installing globally  
=====================================================================
NPM LINK (CONNECT LOCAL PACKAGE TO APP)
=====================================================================
Create a local package (library) and connect it to another app
using npm link (live connection)
=====================================================================
FOLDER STRUCTURE
=====================================================================

📁 my-utils (LOCAL PACKAGE / LIBRARY)
------------------------------------------------
my-utils/
   ├── index.js
   ├── package.json


📁 my-app (MAIN PROJECT)
------------------------------------------------
my-app/
   ├── app.js
   ├── package.json


=====================================================================
STEP 1: CREATE LOCAL PACKAGE (my-utils)
=====================================================================

📄 index.js
------------------------------------------------
function add(a, b) {
    return a + b;
}

module.exports = { add };


📄 package.json
------------------------------------------------
{
  "name": "my-utils",  //necessary
  "version": "1.0.0",
  "main": "index.js"
}


=====================================================================
STEP 2: LINK LOCAL PACKAGE (GLOBAL LINK)
=====================================================================

Open terminal inside:

my-utils/

Run:
------------------------------------------------
npm link

👉 This creates a GLOBAL link for my-utils


=====================================================================
STEP 3: CONNECT TO APP
=====================================================================

Go to:

my-app/

Run:
------------------------------------------------
npm link my-utils

👉 Now my-app is connected to my-utils


=====================================================================
STEP 4: USE IN APP
=====================================================================

📄 app.js
------------------------------------------------
const utils = require("my-utils");

console.log(utils.add(2, 3));


OUTPUT:
------------------------------------------------
5


=====================================================================
HOW IT WORKS
=====================================================================

my-utils   → npm link (creates global reference)
my-app     → npm link my-utils (connects to it)

👉 No copying of code
👉 Direct live connection

=====================================================================
TEST LIVE CHANGE
=====================================================================

If you change:

add function in my-utils

👉 my-app automatically uses updated code

=====================================================================
⚠️ IMPORTANT RULE
=====================================================================

For this to work:

✔ package.json inside my-utils MUST have:

{
  "name": "my-utils"
}

👉 Name must match exactly "npm link my-utils"

==IMPORT / EXPORT (NODE.JS)
=============================================================================

DEFINITION
-----------------------------------------------------------------------------
• Export   → Make variables/functions available from a file
• Import   → Use them in another file
• Purpose  → Modular, reusable code

=============================================================================
COMMONJS (DEFAULT NODE.JS)
=============================================================================

METHODS
-----------------------------------------------------------------------------
• module.exports → Main export object
• exports        → Shorthand reference to module.exports

-----------------------------------------------------------------------------
1) EXPORT SINGLE VALUE
-----------------------------------------------------------------------------

math.js

function add(a, b) {
    return a + b;
}
module.exports = add;

app.js

const add = require("./math");
console.log(add(2, 3));   // 5

-----------------------------------------------------------------------------
2) EXPORT MULTIPLE VALUES (OBJECT)
-----------------------------------------------------------------------------

math.js

function add(a, b) { return a + b; }
function sub(a, b) { return a - b; }

module.exports = { add, sub };

app.js

const math = require("./math");

console.log(math.add(5, 2));   // 7
console.log(math.sub(5, 2));   // 3

-----------------------------------------------------------------------------
3) IMPORT USING DESTRUCTURING
-----------------------------------------------------------------------------

const { add, sub } = require("./math");

console.log(add(10, 5));   // 15
console.log(sub(10, 5));   // 5

Note:
• Order doesn't matter: {add, sub} == {sub, add}
• Matching happens by object key name

-----------------------------------------------------------------------------
4) USING exports (SHORTHAND)
-----------------------------------------------------------------------------

exports.add = (a, b) => a + b;
exports.sub = (a, b) => a - b;

Equivalent to:

module.exports.add = ...
module.exports.sub = ...

-----------------------------------------------------------------------------
5) EXPORT CUSTOM OBJECT
-----------------------------------------------------------------------------

config.js

module.exports = {
    name: "Ajay",
    version: "1.0"
};

app.js

const config = require("./config");

console.log(config.name);      // Ajay

-----------------------------------------------------------------------------
6) IMPORT BUILT-IN MODULE
-----------------------------------------------------------------------------

const http = require("http");

=============================================================================
COMMONJS NOTES
=============================================================================

• "./" refers to current folder
• require() is synchronous (blocking)
• require() runs at runtime (dynamic)

Flow:

require("./math")
      ↓
load module
      ↓
wait until complete
      ↓
execute next line

-----------------------------------------------------------------------------
exports vs module.exports
-----------------------------------------------------------------------------

exports -----> module.exports

Both initially point to the same object.

❌ Wrong

exports = { a: 1 };

Reason:
• Breaks reference to module.exports

✔ Correct

module.exports = { a: 1 };

Rule:
• Reassigning whole object  → use module.exports
• Adding properties         → exports.x = value is fine

=============================================================================
DYNAMIC (require)
=============================================================================

• Module path can be decided at runtime
• Can be used inside if, loops, functions

if (isAdmin) {
    require("./admin");
} else {
    require("./user");
}

=============================================================================
ES MODULES (MODERN JAVASCRIPT)
=============================================================================

DEFINITION
-----------------------------------------------------------------------------
• Modern module system
• Used in Node.js and Browsers
• Uses import/export syntax

=============================================================================
ENABLE IN NODE.JS
=============================================================================

package.json

{
    "type": "module"
}

OR

Use .mjs extension

=============================================================================
IMPORTANT RULES
=============================================================================

• File extension required

✔ import x from "./file.js";
❌ import x from "./file";

• Only one default export per file
• Named exports can be many

=============================================================================
EXPORTING
=============================================================================

1) DEFAULT EXPORT
-----------------------------------------------------------------------------

math.js

function add(a, b) {
    return a + b;
}

export default add;

-----------------------------------------------------------------------------
2) NAMED EXPORTS
-----------------------------------------------------------------------------

export function add(a, b) {
    return a + b;
}

export const sub = (a, b) => a - b;

=============================================================================
IMPORTING
=============================================================================

1) DEFAULT IMPORT
-----------------------------------------------------------------------------

import add from "./math.js";

console.log(add(2, 3));

-----------------------------------------------------------------------------
2) NAMED IMPORT
-----------------------------------------------------------------------------

import { add, sub } from "./math.js";

console.log(add(2, 3));
console.log(sub(5, 2));

-----------------------------------------------------------------------------
3) IMPORT ALL
-----------------------------------------------------------------------------

import * as math from "./math.js";

console.log(math.add(2, 3));
console.log(math.sub(5, 2));

-----------------------------------------------------------------------------
4) DEFAULT + NAMED
-----------------------------------------------------------------------------

import add, { sub } from "./math.js";

=============================================================================
DEFAULT EXPORT vs NAMED EXPORT
=============================================================================

export default
• Import with any name

export default add;

import sum from "./math.js";
import xyz from "./math.js";

Both work.

-----------------------------------------------------------------------------
export (named)
-----------------------------------------------------------------------------

export const add = () => {};

import { add } from "./math.js";

Must use same name
(or alias)

import { add as sum } from "./math.js";

=============================================================================
STATIC (import)
=============================================================================

• Imports known before execution starts
• Dependency graph built before running code
• Must be at top level

✔ import add from "./math.js";

❌

const moduleName = "./math.js";
import add from moduleName;

=============================================================================
DYNAMIC IMPORT (ES MODULES)
=============================================================================

const math = await import("./math.js");

• Loads module during execution
• Returns Promise
• Asynchronous
• Similar purpose to require(), but async

=============================================================================
COMMONJS vs ES MODULES
=============================================================================

CommonJS                  | ES Modules
-----------------------------------------------------------------------------
require()                 | import
module.exports            | export / export default
synchronous               | async loading
dynamic                   | static
default in Node (legacy)  | modern standard
extension optional        | .js required
runtime loading           | pre-analyzed imports

=============================================================================
WHEN TO USE
=============================================================================

• Old/simple Node.js apps      → CommonJS
• Modern Node.js projects      → ES Modules
• React/Frontend applications  → ES Modules

=============================================================================
COMMON MISTAKES
=============================================================================

❌ Mixing require and import incorrectly
❌ Forgetting .js extension in ES Modules
❌ Reassigning exports instead of module.exports
❌ Forgetting "type": "module"

=============================================================================
INTERVIEW SUMMARY
=============================================================================

✔ Export = Share code from a file
✔ Import = Use code from another file

✔ CommonJS  = require + module.exports
✔ ES Module = import + export

require()
• Dynamic
• Synchronous
• Runtime loading

import
• Static
• Async loading
• Analyzed before execution

import()
• Dynamic
• Async
• Returns Promise

=====================================================================
WHY YOU SHOULD NOT MIX THEM
=====================================================================

👉 Node must decide BEFORE execution:
   “Is this file CommonJS or ES Module?”

DECISION BASED ON:
---------------------------------------------------------------------
• "type": "module"  → ES Modules (inside package.json)
• No "type" field   → CommonJS (default)


=====================================================================
WHAT HAPPENS IF YOU MIX
=====================================================================

const x = require("./file");   // CommonJS
import y from "./file.js";     // ES Module

❌ Error:
---------------------------------------------------------------------
SyntaxError: Cannot use import outside a module


=====================================================================
IMPORTANT RULE
=====================================================================

✔ Use ONLY ONE system in a project

• CommonJS → require + module.exports  
• ES Modules → import + export  

==============================================================================
LIBRARY vs FRAMEWORK
==============================================================================

LIBRARY
------------------------------------------------------------------------------
• Collection of reusable functions/classes/code
• Used for specific tasks
• You decide when and how to use it
• More flexible
• Your code controls the flow

EXAMPLES:
• Axios   → API calls
• Lodash  → utility functions
• Moment  → date handling
• React   → UI library

------------------------------------------------------------------------------
FRAMEWORK
------------------------------------------------------------------------------
• Complete structure/skeleton for building applications
• Provides:
    - Architecture
    - Rules
    - Flow control
    - Built-in features

• You write code inside framework structure
• Framework controls execution flow
• More opinionated and structured

BUILT-IN FEATURES:
• Routing
• Middleware
• Lifecycle handling
• Project structure

EXAMPLES:
• Express     → Backend framework
• Angular     → Frontend framework
• Django      → Python framework
• Spring Boot → Java framework

==============================================================================
INVERSION OF CONTROL (VERY IMPORTANT)
==============================================================================

• In a library:
    Your code calls the library

Example:
--------------------------------------------------
axios.get("/users");
--------------------------------------------------

👉 You control the execution flow.

------------------------------------------------------------------------------
• In a framework:
    Framework calls your code when needed

Example:
--------------------------------------------------
app.get("/", (req, res) => {
   res.send("Home");
});
--------------------------------------------------

👉 Express decides WHEN this function runs.

------------------------------------------------------------------------------
THIS IS CALLED:
------------------------------------------------------------------------------
Inversion of Control (IoC)

Definition:
• Control of execution flow is inverted/transferred from developer
  to framework.
