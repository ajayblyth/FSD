1. EXPRESS.JS
---------------------------------------------------------------------
• Express.js is a minimal and flexible web framework for Node.js
• Used to build web servers and REST APIs
• Simplifies routing, request/response handling and middleware

Server:
• Receives requests → processes them → sends responses

Without Express:
• Manual routing using Node's http module
• More boilerplate code

With Express:
• Simple routing
• Easy request/response handling
• Faster development

2. API & REQUEST FLOW
---------------------------------------------------------------------
API (Application Programming Interface)

• Allows two software systems/applications to communicate
• One system sends a request, another returns a response

Example:
• Browser/Frontend ↔ Server/Backend

Parse:
• Converting raw data into structured data (object/array)

REQUEST FLOW
---------------------------------------------------------------------
User / Client
      ↓
HTTP Request
      ↓
Express Route
      ↓
Business Logic / Database
      ↓
HTTP Response

ANOTHER VIEW
---------------------------------------------------------------------
Frontend
      ↓
API Endpoint (/users)
      ↓
Port 3000
      ↓
Backend Logic
      ↓
Response

3. PORTS & LISTENING
---------------------------------------------------------------------
app.listen(port, () => {
    console.log("Server running on port 3000");
});

• Server waits for incoming client requests

Example URL:
http://localhost:3000

PORT
---------------------------------------------------------------------
• Port = logical endpoint of a network connection
• Port = number on a device (0 - 65535)
• Identifies which application/service receives data
• Used for client-server communication

Examples:
• 3000 → Express server
• 80   → HTTP
• 443  → HTTPS

WHY NOT JUST IP ADDRESS?
---------------------------------------------------------------------
• IP address identifies a device ✔

One device can run multiple applications:
• Web Server
• Database
• Email Service

• IP alone cannot determine which application should
  receive data ❌

ROLE OF PORT
---------------------------------------------------------------------
IP + PORT = Exact Destination ✔

Analogy:
• IP Address = House
• Port       = Room Number

4. LOCALHOST (127.0.0.1)
---------------------------------------------------------------------
• Special IP that refers to the current machine

LOOPBACK
---------------------------------------------------------------------
• Request never goes to the internet
• OS routes it back to the same system

HOW IT WORKS
---------------------------------------------------------------------
1. Request sent to localhost
2. OS intercepts it
3. Sends it back to same machine
4. Local server handles request

WHY USED?
---------------------------------------------------------------------
• Local testing
• No internet required
• Fast and secure

Examples:
• localhost:3000
• localhost:8080

Analogy:
• Like calling your own phone

5. JSON
---------------------------------------------------------------------
JSON (JavaScript Object Notation)

• Lightweight text-based format used to represent and
  exchange structured data between software systems
• Based on key-value pairs (similar to JavaScript objects)
• Commonly used in APIs

Example:
{
  "name": "Ajay",
  "age": 25
}

RULES
---------------------------------------------------------------------
• Keys must use double quotes
• String values use double quotes
• No functions
• No trailing commas

Invalid JSON:
{
   "name": "Rohit",
   "age": 22,
}

6. MIDDLEWARE & app.use()
---------------------------------------------------------------------
Middleware:
• Functions that run between request and response

app.use():
• Registers middleware
• Runs for every incoming request
  (or matching routes)

WHY USE MIDDLEWARE?
---------------------------------------------------------------------
• Common logic for multiple routes
• Avoid code repetition
• Parsing
• Logging
• Authentication

FLOW
---------------------------------------------------------------------
Request
   ↓
Middleware
   ↓
next()
   ↓
Route Handler
   ↓
Response

SYNTAX
---------------------------------------------------------------------
app.use((req, res, next) => {
    console.log("Middleware running");
    next();
});

IMPORTANT
---------------------------------------------------------------------
• next() passes control to next middleware/route
• Without next() request may get stuck

COMMON MIDDLEWARE EXAMPLES
---------------------------------------------------------------------

1) JSON PARSER

app.use(express.json());

• Built-in Express middleware
• Converts JSON text into JavaScript objects
• Makes request body available in req.body

Raw JSON
    ↓
express.json()
    ↓
JavaScript Object
    ↓
req.body

------------------------------------------------------------

2) LOGGING

app.use((req, res, next) => {
    console.log(req.method, req.url);
    next();
});

------------------------------------------------------------

3) AUTHENTICATION

app.use((req, res, next) => {
    // validate token
    next();
});

------------------------------------------------------------

4) PATH-BASED MIDDLEWARE

app.use('/user', (req, res, next) => {
    next();
});

7. ROUTING
---------------------------------------------------------------------
Routing:
• Process of deciding how application responds
  to client requests

Routes:
• Actual paths/functions that handle requests

Routing (process) uses Routes (implementation)

BASIC IDEA
---------------------------------------------------------------------
URL + HTTP Method
          ↓
     Express Route
          ↓
       Response

SYNTAX
---------------------------------------------------------------------
app.METHOD(PATH, HANDLER)

METHOD  → get, post, put, patch, delete
PATH    → URL
HANDLER → function(req, res)

Example:
app.get('/home', (req, res) => {
    res.send("Home Page");
});

HOW ROUTING WORKS
---------------------------------------------------------------------
1. Client sends request
2. Express matches URL + Method
3. Matching route found
4. Route handler executes
5. Response sent

WHY ROUTES?
---------------------------------------------------------------------
• Organize application functionality

Examples:
• Login
• Register
• Get Users
• Delete Users

ROUTE TYPES (OVERVIEW)
---------------------------------------------------------------------
1) Simple Route

app.get('/home', ...)

2) Route Parameter Route

app.get('/user/:id', ...)

3) Query Parameter Route

app.get('/search', ...)

Example:
 /search?name=ajay&city=delhi

---------------------------------------------------------------------

---------------------------------------------------------------------

10. ROUTE PARAMETERS (PATH PARAMETERS)
---------------------------------------------------------------------
Definition:
• Dynamic values inside URL path
• Used for required identifiers

SYNTAX
---------------------------------------------------------------------
/user/:id

Example:
app.get('/user/:id', (req, res) => {
    res.send(req.params.id);
});

URL:
 /user/101

Express extracts:
 id = 101

Access:
 req.params.id

MULTIPLE PARAMETERS
---------------------------------------------------------------------
app.get('/user/:id/order/:orderId', (req, res) => {
    res.send({
        userId: req.params.id,
        orderId: req.params.orderId
    });
});

URL:
 /user/10/order/500

IMPORTANT
---------------------------------------------------------------------
• Defined using :
• Part of URL path
• Values are strings by default
• Usually identify a resource

USE CASES
---------------------------------------------------------------------
• /user/101
• /product/55
• /item/20

=====================================================================
11. QUERY PARAMETERS (QUERY STRINGS)
---------------------------------------------------------------------
Definition:
• Optional key-value data after URL

HOW IT WORKS
---------------------------------------------------------------------
URL:
 /search?name=ajay&age=22

app.get('/search', (req, res) => {
    const name = req.query.name;
    const age = req.query.age;

    res.send({
        name: name,
        age: age
    });
});

IMPORTANT
---------------------------------------------------------------------
• Starts with ?
• Multiple values separated by &
• Values are strings by default
• Optional

USE CASES
---------------------------------------------------------------------
• Filtering
• Searching
• Sorting
• Pagination

Examples:
• /products?category=mobile
• /search?name=ajay
• /users?page=2

=====================================================================
12. ROUTE PARAMS vs QUERY PARAMS
---------------------------------------------------------------------
ROUTE PARAMS (:)

• Required
• Part of URL path
• Used to identify specific resource

Example:
 /user/101

------------------------------------------------------------

QUERY PARAMS (?)

• Optional
• Extra/filter/search data

Example:
 /user?id=101

------------------------------------------------------------

SUMMARY

Route Params (:) → Dynamic URL path values
Query Params (?) → Optional URL key-value pairs

13. STARTING A PROJECT
---------------------------------------------------------------------
1. Create project

npm init -y

2. Install Express

npm install express

3. Create app

const express = require('express');
const app = express();

const port = 3000;

app.use(express.json());

app.get('/', (req, res) => {
    res.send("Hello from GET route");
});

app.post('/', (req, res) => {
    res.send("Hello from POST route");
});

app.listen(port, () => {
    console.log("Server running on port 3000");
});

4. Run application

node app.js

14. NODEMON
---------------------------------------------------------------------
Problem:
• After every code change, server must be restarted manually

Solution:
• Nodemon automatically restarts server when files change

Install:
npm install --save-dev nodemon / npm i -D nodemon

Run:
nodemon app.js

Benefit:
• No manual restart
• Faster development
