EXPRESS.JS NOTES (STRUCTURED)
=====================================================================

1. DEFINITION
---------------------------------------------------------------------
• Express.js is a lightweight web framework for Node.js
• Used to build web servers and APIs
• Simplifies handling requests and responses

API (Application Programming Interface)
------------------------------------------------------------
• API is a way for two software applications to communicate with each other.  
• It acts as a bridge where one system sends a request and another returns data or response.  
• Example: Your frontend calls an API to get data from a server (like weather, users, etc.).

=====================================================================
WHY EXPRESS IS USED
=====================================================================

Without Express:
------------------------------------------------
• Need to manually handle routes, requests, responses  
• More complex code using Node http module  

With Express:
------------------------------------------------
• Simple routing  
• Easy request/response handling  
• Cleaner and faster development  
=====================================================================

2.HOW IT WORKS?
---------------------------------------------------------------------
• User sends request → Express matches route → runs function → sends response  


Note:• Parse = convert raw/unstructured data into usable JavaScript format  
👉 Simple:
Raw data → structured data (object)
=====================================================================

3. LISTEN FOR INCOMING REQUESTS
---------------------------------------------------------------------
• Server waits for client requests

Example:
const express = require('express');
const app = express();

let port = 3000;

app.listen(port, () => {
    console.log("Server running on port 3000");
});

http://localhost:3000

localhost → your computer  
3000      → port number  

👉 Request goes to app running on port 3000

---------------------------------------------------------------------
PORTS
---------------------------------------------------------------------
• Ports are logical endpoints of a network connection
• Used for communication between client and server
• Help identify which service/app should receive data

Example:
• 3000 → Express server
• 80   → HTTP
• 443  → HTTPS

---------------------------------------------------------------------
WHY NOT JUST IP ADDRESS?
---------------------------------------------------------------------
• IP address identifies a device (computer) ✔
• One device can run multiple applications:
  → Web server
  → Database
  → Email service

• IP alone cannot decide WHICH app should get data ❌

---------------------------------------------------------------------
ROLE OF PORT
---------------------------------------------------------------------
IP + PORT → Exact destination ✔

👉 Think:
IP address = house  
Port       = room/door number

• One computer runs multiple apps (browser, server, DB)  
• Ports help identify WHICH app should handle the request  
=====================================================================

4. PARSE INPUT REQUEST(app.use(express.json());)
---------------------------------------------------------------------
• Reads data from client (body, params, query)

Example:
app.use(express.json()); // for JSON data

without it:
• Express CANNOT read JSON request body  
• req.body will be undefined  
• Incoming JSON stays as raw data (not converted)
WHY?
---------------------------------------------------------------------
• Express does not automatically parse JSON  
• It needs middleware to convert raw JSON → JS object  

Note:• JSON is a lightweight format used to store and exchange data  
• It is based on key-value pairs (like JavaScript objects)  
• Used in APIs to send data between client and server  

rules:
JSON is a strict key-value data format with double quotes, no functions, and no trailing commas.

=====================================================================

5. MATCH REQUEST WITH ROUTES
---------------------------------------------------------------------
• Based on URL + HTTP method

Example:
app.get('/', (req, res) => {
    res.send("Home Page");
});

 req = request object (incoming data)  
 res = response object (send data back) 

=====================================================================

6. PROCESS LOGIC
---------------------------------------------------------------------
• Perform operations (DB, calculations, etc.)

Example:
app.get('/user', (req, res) => {
    const user = { name: "Ajay" };
    res.send(user);

7. SEND RESPONSE

=====================================================================
ROUTING (EXPRESS JS)
=====================================================================

WHAT IS ROUTING?
---------------------------------------------------------------------
• Routing means defining how an application responds to a client request  
• It connects URL + HTTP method → specific function  


=====================================================================
BASIC IDEA
=====================================================================

User Request → URL + Method → Express Route → Response


=====================================================================
SYNTAX
=====================================================================

app.METHOD(PATH, HANDLER)

METHOD → get, post, put, delete  
PATH   → URL route  
HANDLER → function(req, res)


=====================================================================
EXAMPLE
=====================================================================

const express = require("express");
const app = express();

app.get("/", (req, res) => {
    res.send("Home Page");
});

app.get("/about", (req, res) => {
    res.send("About Page");
});


=====================================================================
TYPES OF ROUTING
=====================================================================

1) Simple Route
---------------------------------------------------------------------
app.get("/home", (req, res) => {})


2) Dynamic Route (params)
---------------------------------------------------------------------
app.get("/user/:id", (req, res) => {})


3) Query Route
---------------------------------------------------------------------
app.get("/search", (req, res) => {})


=====================================================================
WHY ROUTING IS USED
=====================================================================

• To handle different URLs  
• To build multiple pages / APIs  
• To organize backend logic  


=====================================================================
ONE LINE
=====================================================================

Routing in Express defines how the server responds to different URLs
and HTTP methods using specific handler functions.

=====================================================================

WHY ROUTES?
---------------------------------------------------------------------
• Real apps have multiple functionalities:
  → Login, Register, Get users, Delete user

• One route ❌ → messy code
• Multiple routes ✔ → clean & organized

---------------------------------------------------------------------
ANALOGY
---------------------------------------------------------------------
• Like bank counters:
  Routing = deciding which counter to go
  Route   = actual counter handling work

=====================================================================

HOW ROUTING WORKS
---------------------------------------------------------------------
1. Client sends request (URL + method)
2. Express performs routing (matching)
3. Matching route is found
4. That route’s handler runs
5. Response sent back

=====================================================================

BASIC SYNTAX (ROUTES)
---------------------------------------------------------------------
app.METHOD(PATH, HANDLER)

Example:
app.get('/home', (req, res) => {
    res.send("Home Page");
});

=====================================================================

HTTP METHODS
---------------------------------------------------------------------
• GET    → Fetch data
• POST   → Send data
• PUT    → Update data
• DELETE → Remove data

=====================================================================

ROUTE MATCHING
---------------------------------------------------------------------
• Same path can behave differently based on method

Example:
app.get('/user', ...)   → fetch user
app.post('/user', ...)  → create user

=====================================================================
TWO TYPES OF PARAMETERS IN EXPRESS

DYNAMIC ROUTES (PARAMETERS)/ ":" → ROUTE PARAMETERS (URL PARAMS)
---------------------------------------------------------------------
• Defined inside the route path  
• Used for required/dynamic values  

app.get('/user/:id', (req, res) => {
    res.send(req.params.id);
});

• params = parameters in the URL path  
• Used to capture dynamic values from route 

=====================================================================

"?" -> QUERY PARAMETERS
---------------------------------------------------------------------
? (query)   → extra data after URL (optional)

/search?name=ajay

app.get('/search', (req, res) => {
    res.send(req.query.name);
});

COMPARISON ? AND :
REAL LIFE ANALOGY
=====================================================================

Route Param (:id)
→ Address of house (fixed)

Query Param (?)
→ Extra instructions like “deliver fast”, “call before”


=====================================================================
ONE LINE
=====================================================================

Route params (:) define dynamic URL paths like IDs, while query params (?)
are used for optional data like filters and search values.
=====================================================================

SUMMARY
---------------------------------------------------------------------
• Routing = decision process ✔
• Route   = actual handler ✔
• Route = METHOD + PATH + HANDLER ✔

11. app.use() (MIDDLEWARE)
---------------------------------------------------------------------
DEFINITION
---------------------------------------------------------------------
• Used to register middleware
• Middleware runs between request & response

---------------------------------------------------------------------
WHY USE?
---------------------------------------------------------------------
• Common logic for multiple routes
• Avoid repetition
• Used for parsing, logging, auth

---------------------------------------------------------------------
HOW IT WORKS
---------------------------------------------------------------------
1. Request comes
2. Middleware runs
3. Passes to next
4. Response sent

---------------------------------------------------------------------
SYNTAX
---------------------------------------------------------------------
app.use((req, res, next) => {
    console.log("Middleware running");
    next();
});

---------------------------------------------------------------------
COMMON USES
---------------------------------------------------------------------
app.use(express.json());

app.use((req, res, next) => {
    console.log(req.method, req.url);
    next();
});

---------------------------------------------------------------------
PATH BASED
---------------------------------------------------------------------
app.use('/user', (req, res, next) => {
    console.log("User middleware");
    next();
});

---------------------------------------------------------------------
IMPORTANT
---------------------------------------------------------------------
• next() is required to pass control ✔
• Without next() → request gets stuck ❌

---------------------------------------------------------------------
SUMMARY
---------------------------------------------------------------------
app.use() → middleware handler ✔
Used before routes for common processing ✔

PATH PARAMETERS (EXPRESS)
------------------------------------------------------------

DEFINITION
------------------------------------------------------------
• Path parameters are dynamic values in the URL
• Used to send specific data as part of the path

------------------------------------------------------------

SYNTAX
------------------------------------------------------------
/path/:parameterName

Example:
app.get('/user/:id', (req, res) => {
    res.send(req.params.id);
});

------------------------------------------------------------

HOW IT WORKS
------------------------------------------------------------
• URL:
  /user/101

• Express extracts:
  id = 101

• Access using:
  req.params.id

------------------------------------------------------------

MULTIPLE PARAMETERS
------------------------------------------------------------
app.get('/user/:id/order/:orderId', (req, res) => {
    res.send({
        userId: req.params.id,
        orderId: req.params.orderId
    });
});

URL:
 /user/10/order/500

------------------------------------------------------------

IMPORTANT POINTS
------------------------------------------------------------
• Defined using colon (:) ✔
• Always part of URL path (not query)
• Values are strings by default
• Useful for identifying specific resources

------------------------------------------------------------

USE CASES
------------------------------------------------------------
• Get user by ID → /user/101
• Get product → /product/55
• Delete item → /item/20

------------------------------------------------------------

SUMMARY
------------------------------------------------------------
Path parameter = dynamic value in URL ✔
Access using req.params ✔

QUERY STRINGS (EXPRESS)
------------------------------------------------------------

DEFINITION
------------------------------------------------------------
• Query strings are key-value pairs sent in URL
• Used to pass optional/filter data to server

------------------------------------------------------------

SYNTAX
------------------------------------------------------------
/path?key=value

Example:
 /search?name=ajay&age=22

------------------------------------------------------------

HOW IT WORKS
------------------------------------------------------------
• URL:
  /search?name=ajay&age=22

• Express extracts:
  name = ajay
  age  = 22

• Access using:
  req.query.name
  req.query.age

------------------------------------------------------------

EXAMPLE IN CODE
------------------------------------------------------------
app.get('/search', (req, res) => {
    const name = req.query.name;
    const age = req.query.age;

    res.send({
        name: name,
        age: age
    });
});

------------------------------------------------------------

IMPORTANT POINTS
------------------------------------------------------------
• Starts with ? in URL ✔
• Multiple params separated by & ✔
• Values are strings by default
• Optional (route works even without them)

------------------------------------------------------------

USE CASES
------------------------------------------------------------
• Filtering → /products?category=mobile
• Searching → /search?name=ajay
• Pagination → /users?page=2

------------------------------------------------------------

PATH PARAM vs QUERY STRING
------------------------------------------------------------
• Path param → required (part of URL)
  /user/101

• Query string → optional
  /user?id=101

------------------------------------------------------------

SUMMARY
------------------------------------------------------------
Query string = optional data in URL ✔
Access using req.query ✔
