FRAMEWORK vs LIBRARY vs PACKAGE vs MODULE (NOTEPAD FORMAT)
=============================================================================

📌 MODULE
-----------------------------------------------------------------------------
A module is the smallest unit of code in a program.
It is usually a single file that contains specific functionality.
In Node.js, every file is treated as a module.
Modules help in dividing large applications into smaller reusable parts.
Example: fs (file system), path, http modules in Node.js.

👉 Key Idea:
Small, focused piece of functionality used inside an application.


📌 PACKAGE
-----------------------------------------------------------------------------
A package is a collection of one or more modules bundled together.
It is usually distributed via package managers like npm.
Packages often include additional files like package.json for metadata.
They are reusable and can be installed into any project easily.
Example: express, lodash, mysql2.

👉 Key Idea:
Reusable bundle of code (modules + configuration) available via npm.


📌 LIBRARY
-----------------------------------------------------------------------------
A library is a collection of pre-written functions/classes that you can use.
You control when and where to use the library functions in your code.
It solves specific problems like data manipulation, DOM handling, etc.
Library does NOT control your application flow.
Example: lodash, jQuery, React (commonly treated as library).

👉 Key Idea:
You are in control → you call the library when needed.


📌 FRAMEWORK
-----------------------------------------------------------------------------
A framework provides a complete structure for building applications.
It defines rules, architecture, and flow of your application.
The framework calls your code (this is called Inversion of Control).
You just fill in the required logic in predefined places.
Example: Express, Angular, Spring Boot.

👉 Key Idea:
Framework is in control → it calls your code at runtime.


=============================================================================
🔹 MAIN DIFFERENCE (VERY IMPORTANT)
=============================================================================

MODULE     → Small building block (single file functionality)
PACKAGE    → Collection of modules bundled together
LIBRARY    → You call it when needed (you control flow)
FRAMEWORK  → It controls your code execution flow

1. DEFINITION
---------------------------------------------------------------------
Express.js is a minimal and flexible web framework for Node.js
used to build web servers and APIs.
It simplifies handling HTTP requests, routing, and middleware.
Provides methods like app.get(), app.post() for handling routes.
Supports middleware for logging, authentication, error handling, etc.

API (Application Programming Interface)
------------------------------------------------------------
• API is a way for two software applications to communicate with each other.  
• It acts as a bridge where one system sends a request and another returns data or response.  
• Example:
Client/frontend calls an API to get data from a server/backend (like weather, users, etc.).

Without Express:
------------------------------------------------
• Need to manually handle routes, requests, responses  
• More complex code using Node http module  

With Express:
------------------------------------------------
• Simple routing  
• Easy request/response handling  
• Cleaner and faster development

ROUTING (EXPRESS JS)
=====================================================================

WHAT IS ROUTING?
---------------------------------------------------------------------
• Routing means defining how an application responds to a client request  
• It connects URL + HTTP method → specific function

example:
app.get('/home', (req, res) => {
    res.send("Welcome to Home Page");
});

👉 Meaning:

URL: /home
Method: GET
Action: send response “Welcome to Home Page”

=====================================================================
BASIC IDEA
=====================================================================

User Request → URL + Method → Express Route → Response


=====================================================================
SYNTAX
=====================================================================

app.METHOD(PATH, HANDLER)

METHOD → get, post, put, delete  
PATH   → URL route  
HANDLER → function(req, res)


=====================================================================
EXAMPLE
=====================================================================

const express = require("express");
const app = express();

app.get("/", (req, res) => {
    res.send("Home Page");
});

app.get("/about", (req, res) => {
    res.send("About Page");
});


=====================================================================
TYPES OF ROUTING
=====================================================================

1) Simple Route
---------------------------------------------------------------------
app.get("/home", (req, res) => {})


2) Dynamic Route (params)
---------------------------------------------------------------------
app.get("/user/:id", (req, res) => {})


3) Query Route
---------------------------------------------------------------------
app.get("/search", (req, res) => {})

Note:
Routing in Express defines how the server responds to different URLs
and HTTP methods using specific handler functions.


WHY ROUTES?
---------------------------------------------------------------------
• Real apps have multiple functionalities:
  → Login, Register, Get users, Delete user

• One route ❌ → messy code
• Multiple routes ✔ → clean & organized


HOW ROUTING WORKS
---------------------------------------------------------------------
1. Client sends request (URL + method)
2. Express performs routing (matching)
3. Matching route is found
4. That route’s handler runs
5. Response sent back


HTTP METHODS
---------------------------------------------------------------------
• GET    → Fetch data
• POST   → Send data
• PUT    → Update data
• DELETE → Remove data

=====================================================================

ROUTE MATCHING
---------------------------------------------------------------------
• Same path can behave differently based on method

Example:
app.get('/user', ...)   → fetch user
app.post('/user', ...)  → create user

=====================================================================
TWO TYPES OF PARAMETERS IN EXPRESS

DYNAMIC ROUTES (PARAMETERS)/ ":" → ROUTE PARAMETERS (URL PARAMS)
---------------------------------------------------------------------
• Defined inside the route path  
• Used for required/dynamic values  

app.get('/user/:id', (req, res) => {
    res.send(req.params.id);
});

• params = parameters in the URL path  
• Used to capture dynamic values from route 

=====================================================================

"?" -> QUERY PARAMETERS
---------------------------------------------------------------------
? (query)   → extra data after URL (optional)

/search?name=ajay

app.get('/search', (req, res) => {
    res.send(req.query.name);
});


Route params (:) define dynamic URL paths like IDs, while query params (?)
are used for optional data like filters and search values.

11. app.use() (MIDDLEWARE)
---------------------------------------------------------------------
DEFINITION
---------------------------------------------------------------------
• Used to register middleware
• Middleware runs between request & response

---------------------------------------------------------------------
WHY USE?
---------------------------------------------------------------------
• Common logic for multiple routes
• Avoid repetition
• Used for parsing, logging, auth

---------------------------------------------------------------------
HOW IT WORKS
---------------------------------------------------------------------
1. Request comes
2. Middleware runs
3. Passes to next
4. Response sent

---------------------------------------------------------------------
SYNTAX
---------------------------------------------------------------------
app.use((req, res, next) => {
    console.log("Middleware running");
    next();
});

---------------------------------------------------------------------
COMMON USES
---------------------------------------------------------------------
app.use(express.json());

---------------------------------------------------------------------
PATH BASED
---------------------------------------------------------------------
app.use('/user', (req, res, next) => {
    console.log("User middleware");
    next();
});

---------------------------------------------------------------------
IMPORTANT
---------------------------------------------------------------------
• next() is required to pass control ✔
• Without next() → request gets stuck ❌

---------------------------------------------------------------------
SUMMARY
---------------------------------------------------------------------
app.use() → middleware handler ✔
Used before routes for common processing ✔

PATH PARAMETERS (EXPRESS)
------------------------------------------------------------

DEFINITION
------------------------------------------------------------
• Path parameters are dynamic values in the URL
• Used to send specific data as part of the path

------------------------------------------------------------

SYNTAX
------------------------------------------------------------
/path/:parameterName

Example:
app.get('/user/:id', (req, res) => {
    res.send(req.params.id);
});

------------------------------------------------------------

HOW IT WORKS
------------------------------------------------------------
• URL:
  /user/101

• Express extracts:
  id = 101

• Access using:
  req.params.id

------------------------------------------------------------

MULTIPLE PARAMETERS
------------------------------------------------------------
app.get('/user/:id/order/:orderId', (req, res) => {
    res.send({
        userId: req.params.id,
        orderId: req.params.orderId
    });
});

URL:
 /user/10/order/500

------------------------------------------------------------

IMPORTANT POINTS
------------------------------------------------------------
• Defined using colon (:) ✔
• Always part of URL path (not query)
• Values are strings by default
• Useful for identifying specific resources

------------------------------------------------------------

USE CASES
------------------------------------------------------------
• Get user by ID → /user/101
• Get product → /product/55
• Delete item → /item/20

------------------------------------------------------------

SUMMARY
------------------------------------------------------------
Path parameter = dynamic value in URL ✔
Access using req.params ✔

QUERY STRINGS (EXPRESS)
------------------------------------------------------------

DEFINITION
------------------------------------------------------------
• Query strings are key-value pairs sent in URL
• Used to pass optional/filter data to server

------------------------------------------------------------

SYNTAX
------------------------------------------------------------
/path?key=value

Example:
 /search?name=ajay&age=22

------------------------------------------------------------

HOW IT WORKS
------------------------------------------------------------
• URL:
  /search?name=ajay&age=22

• Express extracts:
  name = ajay
  age  = 22

• Access using:
  req.query.name
  req.query.age

------------------------------------------------------------

EXAMPLE IN CODE
------------------------------------------------------------
app.get('/search', (req, res) => {
    const name = req.query.name;
    const age = req.query.age;

    res.send({
        name: name,
        age: age
    });
});

------------------------------------------------------------

IMPORTANT POINTS
------------------------------------------------------------
• Starts with ? in URL ✔
• Multiple params separated by & ✔
• Values are strings by default
• Optional (route works even without them)

------------------------------------------------------------

USE CASES
------------------------------------------------------------
• Filtering → /products?category=mobile
• Searching → /search?name=ajay
• Pagination → /users?page=2

------------------------------------------------------------

PATH PARAM vs QUERY STRING
------------------------------------------------------------
• Path param → required (part of URL)
  /user/101

• Query string → optional
  /user?id=101

------------------------------------------------------------

SUMMARY
------------------------------------------------------------
Query string = optional data in URL ✔
Access using req.query ✔
