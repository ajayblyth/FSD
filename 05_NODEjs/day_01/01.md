2) COMPILER vs INTERPRETER
==============================================================================

COMPILER
------------------------------------------------------------------------------
• Converts entire source code into machine code at once
• Generates executable file before execution
• Errors shown after full compilation
• Faster execution after compilation

FLOW:
Source Code ---> Compiler ---> Machine Code ---> Execute

INTERPRETER
------------------------------------------------------------------------------
• Executes code line-by-line during runtime
• No executable file generated
• Stops immediately when error occurs
• Easier for testing/debugging

FLOW:
Source Code ---> Interpreter ---> Execute Line-by-Line

------------------------------------------------------------------------------
COMPILER vs INTERPRETER
------------------------------------------------------------------------------

+----------------------+-----------------------------+------------------+
| FEATURE              | COMPILER                    | INTERPRETER      |
+----------------------+-----------------------------+------------------+
| Translation          | Entire code at once         | Line-by-line     |
| Speed                | Faster execution            | Slower           |
| Error Detection      | After compilation           | Immediate        |
| Executable File      | Generated                   | Not generated    |
| Runtime Performance  | Better                      | Slower           |
| Examples             | C, C++                      | JS, Python       |
+----------------------+-----------------------------+------------------+

3) JIT (JUST-IN-TIME COMPILATION)
==============================================================================

• JIT = Just-In-Time Compilation
• Compiles code during runtime
• Combines advantages of compiler + interpreter

KEY IDEA:
Interpreter  ---> Fast startup
Compiler     ---> Fast execution
JIT          ---> Fast startup + fast execution

------------------------------------------------------------------------------
HOW JIT WORKS
------------------------------------------------------------------------------

Source Code
     ↓
Interpreter executes code first
     ↓
Frequently used code detected
     ↓
JIT Compiler optimizes code
     ↓
Optimized Machine Code
     ↓
Faster future execution

------------------------------------------------------------------------------
REAL EXAMPLE
------------------------------------------------------------------------------

function add(a, b) {
    return a + b;
}

• First execution:
    - Interpreted normally

• Repeated executions:
    - JIT optimizes function
    - Converts to optimized machine code
    - Future executions become faster

------------------------------------------------------------------------------

BROWSER JS RUNTIME COMPONENTS
---------------------------

---------------------------------------------------

Call Stack + Web APIs + Callback Queue + Event Loop

FLOW:
• JS runs inside Call Stack
• Async tasks (fetch, timers, DOM events) → sent to Web APIs
• After completion → callback enters Callback Queue
• Event Loop pushes callback back to Call Stack

Note: WHAT CALL STACK DOES

• Keeps track of which function is currently running
• Pushes function when called
• Pops function when execution is finished
------------------------------------------------------------------------------
IMPORTANT BROWSER COMPONENTS
------------------------------------------------------------------------------

1. Call Stack
 • Executes JavaScript code line by line.
   • Keeps track of which function is currently running.
   • Works like a stack (Last In, First Out).
2. Memory Heap
   • Stores variables, objects, arrays, and functions in memory.

3. Web APIs
   • Browser-provided async features
      • Handle tasks that may take time.

   • Example:
       setTimeout()
       fetch()
       DOM events
       storage

4. Callback / Task Queue
   • Stores completed async callbacks
      • Also called Macrotask Queue.
 Sources:
   - setTimeout
   - setInterval
   - DOM events
   - Message events

5. Microtask Queue
   • Higher priority queue
   Sources:
   - Promise.then()
   - Promise.catch()
   - Promise.finally()
   - queueMicrotask()

6. Event Loop
   • Traffic controller of JavaScript.
   • Continuously checks:

       Is Call Stack empty?

   If YES:
       1. Execute all Microtasks first.
       2. Then execute one Callback Queue task.
       3. Repeat forever.

WHY STORE VALUES OUTSIDE CODE (ENV VARIABLES)
=====================================================================

1) SECURITY → Keeps secrets (API keys, passwords) out of code so they are not exposed in GitHub or shared codebase

NODE JS EVENT LOOP – TOP 10 TRICKY QUESTIONS (NOTEPAD FORMAT)
=====================================================================

1. BASIC ORDER
---------------------------------------------------------------------
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");

OUTPUT:
A
D
C
B

REASON:
Sync → A, D
Microtask → C
Macrotask → B


=====================================================================

2. MULTIPLE PROMISES
---------------------------------------------------------------------
Promise.resolve().then(() => console.log("A"));
Promise.resolve().then(() => console.log("B"));
console.log("C");

OUTPUT:
C
A
B

REASON:
Microtasks run in FIFO order


=====================================================================

3. NESTED PROMISE
---------------------------------------------------------------------
Promise.resolve().then(() => {
    console.log("A");
    Promise.resolve().then(() => console.log("B"));
});

OUTPUT:
A
B

REASON:
Inner microtask added → executed in same cycle


=====================================================================

4. setTimeout vs Promise
---------------------------------------------------------------------
setTimeout(() => console.log("Timeout"), 0);
Promise.resolve().then(() => console.log("Promise"));

OUTPUT:
Promise
Timeout

REASON:
Microtask > Macrotask priority


=====================================================================

5. ASYNC / AWAIT ORDER
---------------------------------------------------------------------
async function test() {
    console.log("A");
    await Promise.resolve();
    console.log("B");
}

test();
console.log("C");

OUTPUT:
A
C
B

REASON:
await pauses → remaining becomes microtask


=====================================================================

6. setImmediate vs setTimeout
---------------------------------------------------------------------
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));

OUTPUT:
NOT GUARANTEED

REASON:
Depends on poll phase state


=====================================================================

7. I/O + setImmediate
---------------------------------------------------------------------
const fs = require("fs");

fs.readFile(__filename, () => {
    setTimeout(() => console.log("timeout"), 0);
    setImmediate(() => console.log("immediate"));
});

OUTPUT:
immediate
timeout

REASON:
Inside I/O → check phase runs first


=====================================================================

8. process.nextTick (NODE SPECIAL)
---------------------------------------------------------------------
process.nextTick(() => console.log("nextTick"));
Promise.resolve().then(() => console.log("promise"));

OUTPUT:
nextTick
promise

REASON:
nextTick > Promise (higher priority)


=====================================================================

9. nextTick STARVATION
---------------------------------------------------------------------
function loop() {
    process.nextTick(loop);
}
loop();

setTimeout(() => console.log("timeout"), 0);

OUTPUT:
timeout may NEVER run

REASON:
nextTick blocks event loop continuously


=====================================================================

10. MIXED EVERYTHING
---------------------------------------------------------------------
console.log("Start");

setTimeout(() => console.log("Timeout"), 0);

Promise.resolve().then(() => {
    console.log("Promise1");
    setTimeout(() => console.log("Timeout2"), 0);
});

Promise.resolve().then(() => console.log("Promise2"));

console.log("End");

OUTPUT:
Start
End
Promise1
Promise2
Timeout
Timeout2

REASON:
Sync → Start, End
Microtasks → Promise1, Promise2
Macrotasks → Timeout, Timeout2


=====================================================================

FINAL CHEAT RULE
---------------------------------------------------------------------
1. Run synchronous code
2. Run ALL microtasks (Promises, await)
3. Run ONE macrotask (setTimeout, I/O)
4. Repeat
