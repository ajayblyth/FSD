Javascript:
JavaScript is a high-level programming language used to make web pages interactive and dynamic.
It runs in the browser (and also on servers using Node.js).
It handles things like user events, API calls, and DOM manipulation.
It is asynchronous and single-threaded, using the event loop for handling tasks.

=====================================================================
CORE PROGRAMMING CONCEPTS (INTERVIEW NOTES)
=====================================================================

1) COMPILER
---------------------------------------------------------------------
• Converts entire source code(java) into machine code(binary) at once
• Generates executable file before execution
• Errors shown after full compilation
Example: C, C++

---------------------------------------------------------------------
2) INTERPRETER
---------------------------------------------------------------------
• Executes code line-by-line at runtime
• No separate executable file is created
• Stops immediately when error occurs
Example: JavaScript, Python

---------------------------------------------------------------------
3) HIGH-LEVEL LANGUAGE
---------------------------------------------------------------------
• Human-readable and easy to understand
• Closer to natural language
• Easy to write, debug, maintain
Example: Java, Python, JavaScript

---------------------------------------------------------------------
4) LOW-LEVEL LANGUAGE
---------------------------------------------------------------------
• Close to hardware (machine/assembly)
• Hard to understand
• Very fast and efficient
Example: Assembly language

---------------------------------------------------------------------
5) MACHINE LANGUAGE
---------------------------------------------------------------------
• Binary code (0s and 1s)
• Directly understood by computer
• Fastest but not human-friendly

---------------------------------------------------------------------
6) JIT (JUST-IN-TIME)
---------------------------------------------------------------------
• Compiles code during execution (runtime)
• Combines compiler + interpreter benefits
• Improves performance
Example: V8 engine (JavaScript)

JIT combines interpreter and compiler by executing code immediately
like an interpreter and later compiling frequently used code into
optimized machine code for faster performance.

Interpreter → quick start  
Compiler    → fast execution  

JIT → fast start + fast execution

---------------------------------------------------------------------
REAL EXAMPLE (JS ENGINE)
---------------------------------------------------------------------
• First time function runs → slower
• Repeated calls → faster (optimized by JIT)

---------------------------------------------------------------------
7) COMPILER vs INTERPRETER
---------------------------------------------------------------------
Compiler:
• Whole code compiled first
• Faster execution
• Errors after compilation

Interpreter:
• Line-by-line execution
• Slower execution
• Errors immediately

=====================================================================
FINAL SUMMARY
=====================================================================
• High-level code → converted to machine code
• Done using Compiler / Interpreter / JIT
• Machine code is executed by CPU

=====================================================================

DEFINITION
---------------------------------------------------------------------
• Node.js is a runtime environment that allows you to run JavaScript
  outside the browser (on server side).
• Built on Chrome's V8 engine to execute JavaScript.

-V8 is the JavaScript engine of Chrome that compiles and executes JavaScript
 code efficiently by converting it into machine code.

Note: • 👉 A runtime environment is a system that executes your code

WHY USE NODE.JS
---------------------------------------------------------------------
• Fast execution (uses V8 engine)
• Non-blocking / asynchronous (handles multiple requests efficiently)
• Lightweight and scalable
• Used for building APIs, backend services, real-time apps

EVENT LOOP: BROWSER JS vs NODE.JS
=====================================================================

1) BROWSER JS
---------------------------------------------------------------------
COMPONENTS:
Call Stack + Web APIs + Callback Queue + Event Loop

FLOW:
- JS runs in Call Stack
- Async tasks (setTimeout, fetch, DOM events) → sent to Web APIs
- After completion → callback goes to Callback Queue
- Event Loop checks → pushes callback back to Call Stack

Web APIs are browser-provided features that extend JavaScript beyond its core capabilities.
They allow things like timers (setTimeout), network requests (fetch), DOM access, events, and storage.

=====================================================================

2) NODE.JS
---------------------------------------------------------------------
COMPONENTS:
Call Stack + libuv + Callback Queue + Event Loop

FLOW:
- JS runs in Call Stack
- Async tasks → handled by libuv
- libuv uses:
  • OS (network, system calls)
  • Thread Pool (fs, heavy tasks)
- After completion → callback goes to Callback Queue
- Event Loop → pushes back to Call Stack

libuv: pronounced as: “lib-you-vee”
- Core async engine of Node.js (written in C++)

EXAMPLES:
- fs.readFile
- network requests
- timers


=====================================================================

3) KEY DIFFERENCE
---------------------------------------------------------------------
Browser → uses Web APIs (provided by browser environment)
Node.js → uses libuv (internal async handling library)


=====================================================================

4) ANALOGY
---------------------------------------------------------------------
Browser → uses built-in tools (Web APIs)
Node.js → uses its own engine (libuv)


=====================================================================

5) ONE-LINE SUMMARY
---------------------------------------------------------------------
Both use Event Loop, but:
Browser → Web APIs handle async work
Node.js → libuv handles async work

👉 Purpose → modular code (split into multiple files, reusable)

COMMONJS (DEFAULT NODE.JS)

METHODS
---------------------------------------------------------------------
1) module.exports  → main export
2) exports         → shortcut (reference to module.exports)


---------------------------------------------------------------------
1) EXPORT SINGLE VALUE 
---------------------------------------------------------------------
• Export entire file as one value (function/object/string)

math.js
function add(a, b) {
    return a + b;
}

IMPORT (app.js)
const sum = require("./math");

---------------------------------------------------------------------
• Export multiple functions/values as object

math.js

module.exports = { add, sub };

IMPORT (app.js)

const math = require("./math");
console.log(math.add(5, 2)); // 7
console.log(math.sub(5, 2)); // 3

3) IMPORT USING DESTRUCTURING
---------------------------------------------------------------------
• Directly extract required functions

const { add, sub } = require("./math");  //name orders doesnt matter ,

console.log(add(10, 5)); // 15
console.log(sub(10, 5)); // 5


---------------------------------------------------------------------
4) USING exports (SHORTCUT)
---------------------------------------------------------------------
• Shortcut to add properties

math.js

exports.sub = (a, b) => a - b;

---------------------------------------------------------------------

NODE JS EVENT LOOP – TOP 10 TRICKY QUESTIONS (NOTEPAD FORMAT)
=====================================================================

1. BASIC ORDER
---------------------------------------------------------------------
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");

OUTPUT:
A
D
C
B

REASON:
Sync → A, D
Microtask → C
Macrotask → B


=====================================================================

2. MULTIPLE PROMISES
---------------------------------------------------------------------
Promise.resolve().then(() => console.log("A"));
Promise.resolve().then(() => console.log("B"));
console.log("C");

OUTPUT:
C
A
B

REASON:
Microtasks run in FIFO order


=====================================================================

3. NESTED PROMISE
---------------------------------------------------------------------
Promise.resolve().then(() => {
    console.log("A");
    Promise.resolve().then(() => console.log("B"));
});

OUTPUT:
A
B

REASON:
Inner microtask added → executed in same cycle


=====================================================================

4. setTimeout vs Promise
---------------------------------------------------------------------
setTimeout(() => console.log("Timeout"), 0);
Promise.resolve().then(() => console.log("Promise"));

OUTPUT:
Promise
Timeout

REASON:
Microtask > Macrotask priority


=====================================================================

5. ASYNC / AWAIT ORDER
---------------------------------------------------------------------
async function test() {
    console.log("A");
    await Promise.resolve();
    console.log("B");
}

test();
console.log("C");

OUTPUT:
A
C
B

REASON:
await pauses → remaining becomes microtask

6. setImmediate vs setTimeout
---------------------------------------------------------------------
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));

OUTPUT:
NOT GUARANTEED

REASON:
Depends on poll phase state

7. I/O + setImmediate
---------------------------------------------------------------------
const fs = require("fs");

fs.readFile(__filename, () => {
    setTimeout(() => console.log("timeout"), 0);
    setImmediate(() => console.log("immediate"));
});

OUTPUT:
immediate
timeout

REASON:
Inside I/O → check phase runs first

8. process.nextTick (NODE SPECIAL)
---------------------------------------------------------------------
process.nextTick(() => console.log("nextTick"));
Promise.resolve().then(() => console.log("promise"));

OUTPUT:
nextTick
promise

REASON:
nextTick > Promise (higher priority)

9. nextTick STARVATION
---------------------------------------------------------------------
function loop() {
    process.nextTick(loop);
}
loop();

setTimeout(() => console.log("timeout"), 0);

OUTPUT:
timeout may NEVER run

REASON:
nextTick blocks event loop continuously

10. MIXED EVERYTHING
---------------------------------------------------------------------
console.log("Start");

setTimeout(() => console.log("Timeout"), 0);

Promise.resolve().then(() => {
    console.log("Promise1");
    setTimeout(() => console.log("Timeout2"), 0);
});

Promise.resolve().then(() => console.log("Promise2"));

console.log("End");

OUTPUT:
Start
End
Promise1
Promise2
Timeout
Timeout2

REASON:
Sync → Start, End
Microtasks → Promise1, Promise2
Macrotasks → Timeout, Timeout2
