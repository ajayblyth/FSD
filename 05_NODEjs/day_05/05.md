HTTP REQUESTS (HYPERTEXT TRANSFER PROTOCOL) – NOTES
=============================================================================

DEFINITION
-----------------------------------------------------------------------------
• HTTP Request is a message sent by client (browser/app) to server.
• It is Used to request data, send data(route/query parameters), or 
perform operations on server.
• Works on Request → Response model.

BASIC STRUCTURE
-----------------------------------------------------------------------------
1. Request Line
2. Headers
3. Blank Line
4. Body (optional)

Example:
-----------------------------------------------------------------------------
GET /api/users HTTP/1.1
Host: example.com
User-Agent: Chrome

FULL FLOW
===================================================================

Client request to server  → HTTP Request (params/body/header)
      → Server processes
 server send data to client → Server sends response (JSON/HTML)
      → Browser/UI renders
-----------------------------------------------------------------------------

HTTP METHODS (VERY IMPORTANT)
-----------------------------------------------------------------------------
METHOD     PURPOSE
-----------------------------------------------------------------------------
GET        Retrieve data from server
POST       Send new data to server (create)
PUT        Update/replace existing data (full update)
PATCH      Update partial data
DELETE     Remove data
HEAD       Same as GET but returns only headers
OPTIONS    Shows allowed methods for resource

-----------------------------------------------------------------------------

GET vs POST (INTERVIEW POINT)
-----------------------------------------------------------------------------
GET
• Used to retrieve data from server.
• Data is sent in URL (query parameters).
• Visible in browser URL.
• Can be cached and bookmarked.
• No request body is used.

POST
• Used to send/create data on server.
• Data is sent in request body.
• Not visible in URL.
• Not cached or bookmarked.
• Supports large amount of data.

Handling Post requests
Set up POST request route to get some response

Parse POST request data

JavaScript

app.use(express.json());

IMPORTANT INTERVIEW POINTS
-----------------------------------------------------------------------------
• Difference: PUT vs PATCH
• Difference: GET vs POST
• What is stateless protocol?
A stateless protocol is one where the server does NOT remember
previous requests. Each request is treated as a completely new request.

In HTTP:
- No memory of past interaction
- Every request must contain all required information

• What are status codes? they indicate the  result of a request.
• What are headers?
• What is REST API?
REST (Representational State Transfer) is a way to design APIs
using standard HTTP methods.

Key features:
- Stateless communication
- Uses HTTP methods (GET, POST, PUT, PATCH, DELETE)
- Resource-based URLs (/users, /products)
- Usually returns JSON

Example:
GET /users      → fetch users
POST /users     → create user
PATCH /users/1  → update user
DELETE /users/1 → delete user

STATELESS vs STATEFUL + SESSION (SHORT)
===================================================================

Stateless → Server does NOT store client data between requests
Each request must contain all required information

How it works:
- Every request is independent
- Server does not remember previous requests or login state

Stateful → Server stores user data (state) using sessions
- Remembers user across requests

Session:
- Server-side storage to keep user data (like login info)
- Server creates session → sends session ID (cookie)
- Client sends session ID in every request → server identifies user

Example:
Login → session created → user stays logged in (stateful)

Stateless (REST):
- No session memory
- Client sends token (JWT) every time

One-line:
Stateless = no memory, Stateful = server remembers using sessions

URL ENCODED IN SERVER (EXPRESS JS)
=============================================================================

WHY NEEDED
-----------------------------------------------------------------------------
• Browser sends form data in urlencoded format.
• Server cannot read it directly.
• Middleware is required to parse it into usable object.

-----------------------------------------------------------------------------

EXPRESS MIDDLEWARE
-----------------------------------------------------------------------------
app.use(express.urlencoded({ extended: true }));

-----------------------------------------------------------------------------

WHAT IT DOES
-----------------------------------------------------------------------------
• Converts incoming data into JavaScript object.
• Makes data available inside: req.body

Example Input (from form):
-----------------------------------------------------------------------------
name=Ajay&age=25

After parsing:
-----------------------------------------------------------------------------
req.body = {
  name: "Ajay",
  age: "25"
}

-----------------------------------------------------------------------------

EXTENDED: TRUE vs FALSE
-----------------------------------------------------------------------------
extended: true
• Uses "qs" library
• Supports nested objects

Example:
user[name]=Ajay&user[age]=25

→ req.body:
{
  user: {
    name: "Ajay",
    age: "25"
  }
}

-----------------------------------------------------------------------------

extended: false
• Uses "querystring" (simple parsing)
• Does NOT support nested objects

Same input:
user[name]=Ajay

→ req.body:
{
  "user[name]": "Ajay"
}

-----------------------------------------------------------------------------

FULL EXPRESS EXAMPLE
-----------------------------------------------------------------------------
const express = require('express');
const app = express();

app.use(express.urlencoded({ extended: true }));

app.post('/submit', (req, res) => {
    console.log(req.body);
    res.send("Data received");
});

app.listen(3000); //app.listen() starts the server and listens for incoming requests on a port

-----------------------------------------------------------------------------

HTML FORM EXAMPLE
-----------------------------------------------------------------------------
<form action="/submit" method="POST">
    <input type="text" name="name">
    <input type="number" name="age">
    <button type="submit">Send</button>
</form>

-----------------------------------------------------------------------------

IMPORTANT POINTS
-----------------------------------------------------------------------------
• Works only for urlencoded data (forms)
• For JSON → use express.json()
• Must be used BEFORE routes
• req.body is undefined without middleware

-----------------------------------------------------------------------------

FLOW (END TO END)
-----------------------------------------------------------------------------
1. User submits form
2. Browser sends urlencoded data
3. express.urlencoded() parses it
4. Data available in req.body
5. Server processes it

-----------------------------------------------------------------------------


1. OBJECT PROTOTYPES
-----------------------------------------------------------------------------

• Prototype is an object in JavaScript from which other objects inherit properties & methods.
• Every JS object has an internal link to a prototype object.
• If property/method not found in object → JS checks prototype (prototype chain).

-----------------------------------------------------------------------------


PROTOTYPE CHAIN (HOW LOOKUP WORKS)
-----------------------------------------------------------------------------
obj → obj.__proto__ → Object.prototype → null

Step Flow:
1. JS checks obj → found? ✔ use it
2. Else → obj.__proto__ (parent)
3. Else → Object.prototype (top level)
4. Else → undefined (ends at null)

Example:
-----------------------------------------------------------------------------
let obj = { name: "Ajay" };
console.log(obj.__proto__); // Object prototype

-----------------------------------------------------------------------------


WAYS TO ACCESS PROTOTYPE
=============================================================================

1. __proto__                → Direct reference (old, not recommended)
2. Object.getPrototypeOf()  → Get prototype (recommended)
3. Object.setPrototypeOf()  → Set prototype

-----------------------------------------------------------------------------


WHY getPrototypeOf IS PREFERRED
-----------------------------------------------------------------------------
• __proto__ = accessor property (getter/setter on Object.prototype)
• Can be modified/removed → unstable in some environments

• Object.getPrototypeOf() = built-in standard function
✔ Not affected by tampering
✔ More reliable + safe

-----------------------------------------------------------------------------


ADVANTAGES OF PROTOTYPE
-----------------------------------------------------------------------------
• Saves memory (shared methods)
• Code reusability
• Supports inheritance (prototype chain)
• Better performance (no duplication)
• Dynamic method addition possible
• Base of JS OOP system

-----------------------------------------------------------------------------


CREATING PROTOTYPES
=============================================================================


📌 1. CONSTRUCTOR FUNCTION (OLD CORE WAY)
-----------------------------------------------------------------------------
Used to create multiple objects with same structure.

function Person(name, age) {
  this.name = name;
  this.age = age;
}

👉 this.name means:
"store value inside object property called name"

• name = parameter (local input variable)

let p1 = new Person("Ajay", 25);


new is used with constructor to create objects.

WHAT new DOES:
1. Creates empty object {}
2. Links prototype (constructor.prototype)
3. Binds this → new object
4. Returns object
-----------------------------------------------------------------------------

📌 2. OBJECT.CREATE() (DIRECT LINKING)
-----------------------------------------------------------------------------
let personPrototype = {
  greet() {
    console.log("Hello");
  }
};

let user = Object.create(personPrototype);

user.greet(); // Hello

👉 user is empty object but linked to personPrototype

-----------------------------------------------------------------------------


📌 3. ES6 CLASS (SYNTACTIC SUGAR)
-----------------------------------------------------------------------------
class Person {
  greet() {
    console.log("Hello");
  }
}

let p1 = new Person();
p1.greet();

👉 Internally: methods go to Person.prototype

-----------------------------------------------------------------------------


4. CLASSES (ES6 MODERN WAY)
-----------------------------------------------------------------------------
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    console.log("Hello " + this.name);
  }
}

const p1 = new Person("Ajay", 22);
p1.greet();

-----------------------------------------------------------------------------


MULTIPLE OBJECTS USING MAP
-----------------------------------------------------------------------------
const data = [
  ["Ajay", 22],
  ["Vijay", 25],
  ["Suresh", 30]
];

const users = data.map(d => new Person(d[0], d[1]));

users.forEach(u => u.greet());

-----------------------------------------------------------------------------


5. KEYWORDS (IMPORTANT)
=============================================================================

extends → Used for inheritance
super   → Calls parent constructor

-----------------------------------------------------------------------------


// PARENT CLASS
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    console.log("Hello " + this.name);
  }
}


// CHILD CLASS
class Student extends Person {
  constructor(name, age, marks) {
    super(name, age);   // call parent constructor
    this.marks = marks; // new property
  }

  showMarks() {
    console.log(this.name + " has " + this.marks + " marks");
  }
}

-----------------------------------------------------------------------------


IMPORTANT NOTE
-----------------------------------------------------------------------------
name and marks are NOT local variables here.
They are object properties → so we must use this.

-----------------------------------------------------------------------------


USAGE
-----------------------------------------------------------------------------
const s1 = new Student("Ajay", 22, 90);

s1.greet();      // Hello Ajay
s1.showMarks();  // Ajay has 90 marks

-----------------------------------------------------------------------------


SUMMARY
-----------------------------------------------------------------------------
• Prototype → base inheritance system
• Constructor → object blueprint
• new → creates object + links prototype
• Classes → cleaner syntax
• extends/super → inheritance system

Object.getPrototypeOf(value)
=============================================================================

DEFINITION
-----------------------------------------------------------------------------
• Returns immediate prototype (direct parent) of value
• Shows from where object inherits methods/properties

IMPORTANT:
→ Only direct parent, NOT full chain

SYNTAX:
Object.getPrototypeOf(value)

-----------------------------------------------------------------------------


EXAMPLE 1 (STRING)
-----------------------------------------------------------------------------
let str = "hello";
console.log(Object.getPrototypeOf(str));

→ String.prototype (methods: toUpperCase, slice, etc.)

-----------------------------------------------------------------------------


EXAMPLE 2 (ARRAY)
-----------------------------------------------------------------------------
let arr = [1, 2, 3];
console.log(Object.getPrototypeOf(arr));

→ Array.prototype (methods: push, pop, map, etc.)

-----------------------------------------------------------------------------


PROTOTYPE SHARING EXAMPLE
=============================================================================


❌ WITHOUT PROTOTYPE (problem)
-----------------------------------------------------------------------------
let arr1 = [1,2,3];
let arr2 = [4,5,6];

arr1.sayHello = function() {
  console.log("Hello");
};

arr1.sayHello(); // works
arr2.sayHello(); // ERROR

→ duplication + memory waste

-----------------------------------------------------------------------------


✔ WITH PROTOTYPE (solution)
-----------------------------------------------------------------------------
Array.prototype.sayHello = function() {
  console.log("Hello from prototype");
};

arr1.sayHello(); // works
arr2.sayHello(); // works

-----------------------------------------------------------------------------


HOW IT WORKS
-----------------------------------------------------------------------------
arr1 → Array.prototype → Object.prototype → null
arr2 → Array.prototype → Object.prototype → null

✔ same shared prototype

-----------------------------------------------------------------------------


ADVANTAGE
-----------------------------------------------------------------------------
• No duplication
• Memory efficient
• Shared methods
• Used by built-in JS methods

-----------------------------------------------------------------------------


FINAL UNDERSTANDING
-----------------------------------------------------------------------------
• arr1 doesn’t directly have method
• JS searches prototype chain
• finds method in prototype
→ This is prototype inheritance

FACTORY FUNCTION vs CONSTRUCTOR FUNCTION (WITH PROTOTYPE)
=============================================================================

1. FACTORY FUNCTION (NORMAL FUNCTION), a function that creates object
-----------------------------------------------------------------------------
function Student(name, age, id) {
  return {
    name: name,
    age: age,
    id: id,
    getDetails: function() {
      console.log(this.name, this.age, this.id);
    }
  };
}

let s1 = Student("Nithin", 22, 12);

-----------------------------------------------------------------------------

CHARACTERISTICS
-----------------------------------------------------------------------------
• No "new" keyword used
• Returns object manually
• Each object gets its own copy of methods ❌
• More memory usage (function recreated every time)

-----------------------------------------------------------------------------

=============================================================================
2. CONSTRUCTOR FUNCTION + PROTOTYPE 
=============================================================================

CODE
-----------------------------------------------------------------------------
function Student(name, age, id) {
  this.name = name;
  this.age = age;
  this.id = id;
}

Student.prototype.getDetails = function() {
  console.log(this.name, this.age, this.id);
};
// ⚠️ Do NOT use arrow function here

let s1 = new Student("Nithin", 22, 12);

console.log(s1);

-----------------------------------------------------------------------------

WHAT "new" DOES
-----------------------------------------------------------------------------
• Creates empty object {}
• Sets prototype → Student.prototype
• Binds this → new object
• Returns the object

-----------------------------------------------------------------------------

WHY NOT ARROW FUNCTION
-----------------------------------------------------------------------------
❌ Wrong:
Student.prototype.getDetails = () => {
  console.log(this.name);
};

• Arrow function has no own "this"
• It takes "this" from outer scope (not s1)
• So this.name will be undefined

✔️ Correct:
Use normal function → gets "this" from caller (s1)

-----------------------------------------------------------------------------

PROTOTYPE LINK
-----------------------------------------------------------------------------
s1 → Student.prototype → Object.prototype → null

-----------------------------------------------------------------------------

WHAT console.log(s1) SHOWS
-----------------------------------------------------------------------------
{
  name: "Nithin",
  age: 22,
  id: 12
}

• getDetails() is NOT inside object directly
• It exists in prototype (shared)

-----------------------------------------------------------------------------

HOW METHOD WORKS
-----------------------------------------------------------------------------
s1.getDetails()

• JS checks inside s1 → not found
• Goes to prototype → finds getDetails()
• Executes with this = s1

-----------------------------------------------------------------------------

FINAL SUMMARY
-----------------------------------------------------------------------------
• Use "new" → to create object + link prototype
• Store methods in prototype → memory efficient
• Use normal function → correct "this"
• Prototype enables inheritance

-----------------------------------------------------------------------------

-----------------------------------------------------------------------------

CHARACTERISTICS
-----------------------------------------------------------------------------
• Used with "new" keyword
• Object created automatically
• Methods stored in prototype (shared) ✅
• Memory efficient

-----------------------------------------------------------------------------

KEY DIFFERENCE
-----------------------------------------------------------------------------
FACTORY FUNCTION
• Method created for every object ❌
• Higher memory usage

CONSTRUCTOR + PROTOTYPE
• Method shared across objects ✅
• Lower memory usage

-----------------------------------------------------------------------------

THIS KEYWORD BEHAVIOR
-----------------------------------------------------------------------------
WITH new
• this → points to newly created object

WITHOUT new
• this → global object (window) OR undefined (strict mode)

-----------------------------------------------------------------------------

FINAL SUMMARY
-----------------------------------------------------------------------------
• Factory → simple but not memory efficient
• Constructor + Prototype → scalable and efficient
• Always use prototype for shared methods
• Always use "new" with constructor

__proto__ vs prototype vs constructor
===================================================================

📌 1. __proto__  (OBJECT LEVEL)
-------------------------------------------------------------------
- Exists on every JavaScript object
- Points to its prototype (parent object)

👉 Used for: inheritance lookup

Example:
user.__proto__ === obj  // true (if created via Object.create(obj))


===================================================================
📌 2. prototype  (FUNCTION LEVEL)
-------------------------------------------------------------------
- Exists ONLY on functions (especially constructor functions/classes)
- Used to define properties/methods for all instances

👉 All objects created using a constructor share its prototype

Example:
function User() {}
User.prototype.greet = function() { console.log("Hello"); };

let u1 = new User();

u1.__proto__ === User.prototype  // true


===================================================================
📌 3. constructor
-------------------------------------------------------------------
- A reference to the function that created the object

Example:
function User() {}
let u1 = new User();

u1.constructor === User  // true


===================================================================
🔥 RELATION BETWEEN ALL THREE
===================================================================

u1 → __proto__ → User.prototype → constructor → User

👉 Flow:
- Object’s __proto__ points to function’s prototype
- prototype has constructor pointing back to function


===================================================================
📌 SIMPLE EXAMPLE
===================================================================

function User(name) {
    this.name = name;
}

User.prototype.sayHi = function() {
    console.log("Hi " + this.name);
};

let u1 = new User("Ajay");


===================================================================
📌 CHECKS (VERY IMPORTANT)
===================================================================

u1.__proto__ === User.prototype       // true
User.prototype.constructor === User  // true


===================================================================
📌 SIMPLE ANALOGY
===================================================================

constructor → factory (creates objects)
prototype   → shared toolbox (methods)
__proto__   → link from object to toolbox


===================================================================
🎯 INTERVIEW ONE-LINE
-------------------------------------------------------------------
“__proto__ is the internal link of an object to its prototype,
prototype is a property of constructor functions used for sharing methods,
and constructor refers to the function that created the object.”
