METHOD OVERRIDE (PATCH + DELETE) - NOTES (EXPRESS + EJS)
=============================================================================

📌 WHAT IS METHOD OVERRIDE?
-----------------------------------------------------------------------------
HTML forms support only:
- GET
- POST

But REST APIs require:
- • PUT (full update)
- PATCH ( partial update)
- DELETE (delete)

So we use "method-override" middleware to convert POST → PATCH/DELETE.

📌 INSTALLATION
-----------------------------------------------------------------------------
npm install method-override


📌 SETUP IN EXPRESS
-----------------------------------------------------------------------------
const methodOverride = require('method-override');

app.use(methodOverride('_method'));

NOTE:
methodOverride(...) → Middleware function from the method-override package
- '_method' is the query parameter name used to override HTTP method


📌 HOW IT WORKS
-----------------------------------------------------------------------------
Form sends request as:
POST /posts/1?_method=PATCH
POST /posts/1?_method=DELETE

method-override converts it to:
PATCH /posts/1
DELETE /posts/1

👉 So Express treats it as real PATCH / DELETE requests.


📌 FRONTEND (EJS / HTML FORM)
-----------------------------------------------------------------------------
🔹 UPDATE (PATCH)
<form action="/posts/<%= post.id %>?_method=PATCH" method="POST">
    <input type="text" name="content" />
    <button type="submit">Update</button>
</form>

🔹 DELETE
<form action="/posts/<%= post.id %>?_method=DELETE" method="POST">
    <button type="submit">Delete</button>
</form>


📌 BACKEND ROUTES
-----------------------------------------------------------------------------
🔹 PATCH (UPDATE)

app.patch('/posts/:id', (req, res) => {

  try {

    let { id } = req.params;
    let { content } = req.body;

    let post = posts.find(p => p.id === id);

    <!-- posts → array of objects
         p → each object (one by one)
         p.id === id → condition -->

    post.content = content;

    <!-- Left side → property to update
         Right side → new value -->

    res.redirect('/posts');

  } catch (err) {

    console.log(err);
    res.status(500).send("Something went wrong");
  }
});

🔹 DELETE

app.delete('/posts/:id', (req, res) => {

  try {

    let { id } = req.params;

    posts = posts.filter(p => p.id !== id);

    res.send("Post deleted successfully");

    <!-- 
    What happens:
Loop through all posts
Keep only those where id is NOT equal 
filter() → returns new array without that object (perfect for delete)
-->

        res.redirect('/posts');


  } catch (err) {

    console.log(err);
    res.status(500).send("Something went wrong");
  }
});

📌 FLOW (INTERVIEW IMPORTANT)
-----------------------------------------------------------------------------
1. User submits form (POST)
2. URL contains ?_method=PATCH or DELETE
3. method-override middleware runs
4. Converts POST → PATCH / DELETE
5. Express handles app.patch() / app.delete()
6. Data is updated or deleted
7. Redirect response sent


📌 PATCH vs PUT vs DELETE
-----------------------------------------------------------------------------
PATCH   → Partial update (only specific field)
PUT     → Full replace (entire object)
DELETE  → Remove resource


📌 COMMON MISTAKES
-----------------------------------------------------------------------------
1. Forgot middleware setup:
   app.use(methodOverride('_method'))

2. Using method="PATCH" or "DELETE" in form ❌

3. Missing ?_method=PATCH / DELETE in form action

4. Route mismatch or wrong path

5. Using find() for delete ❌ (should use filter())


📌 SUMMARY
-----------------------------------------------------------------------------
POST + _method=PATCH   => behaves like PATCH request
POST + _method=DELETE  => behaves like DELETE request

Used to update/delete data from HTML forms in Express apps

Connecting Node.js with SQL databases (like MySQL) allows building

=============================================================================
📌 PACKAGE (MYSQL2)
-----------------------------------------------------------------------------
mysql2 → used to connect Node.js with MySQL, mysql2 is modern and faster than old mysql 

Install:
npm install mysql2

Import:
const mysql = require('mysql2');

📌 1. createConnection
=============================================================================

const connection = mysql.createConnection({
  host: 'localhost',
  user: 'root',
  password: 'your_password',
  database: 'test_db'
});

connection.connect((err) => {
  if (err) throw err;
  console.log("Connected");
});

connection.query("SELECT * FROM users", (err, result) => {
  if (err) throw err;
  console.log(result);
});

connection.end(); → used to close DB connection


📌 WHAT HAPPENS IF YOU DON’T CLOSE IT
-----------------------------------------------------------------------------
- Connection stays open in memory
- Consumes resources (RAM, DB connections)
- Too many open connections → ❌ database can crash / refuse new requests


=============================================================================
SINGLE CONNECTION FLOW
=============================================================================

📌 FLOW
-----------------------------------------------------------------------------
connect → query → end

connection.connect();

connection.query("SELECT * FROM users", ...);

connection.end();  // close after work


📌 PROBLEMS
-----------------------------------------------------------------------------

❌ Not scalable

CONNECTION POOLING (MYSQL2) not covered in class
=============================================================================

👉 Maintain a pool (group) of reusable connections

Pool = [conn1, conn2, conn3, conn4...]


=============================================================================
USING CONNECTION POOL (CALLBACK STYLE)
=============================================================================

📌 EXAMPLE
-----------------------------------------------------------------------------
const mysql = require('mysql2');

const pool = mysql.createPool({
  host: 'localhost',
  user: 'root',
  password: 'your_password',
  database: 'test_db',
  connectionLimit: 10,
    queueLimit: 0

});

// use pool directly
pool.query("SELECT * FROM users", (err, result) => {
  console.log(result);
});

=============================================================================
HOW CONNECTION POOL ACTUALLY WORKS
=============================================================================

1. Pool creates a SET of connections (e.g. 10)
2. These are READY (idle connections)
3. When query comes: → one connection is borrowed
4. After query  → connection is returned to pool (NOT closed)


=============================================================================
WHEN TO USE
=============================================================================

Learning / testing        → Single connection  
Production / real apps    → Connection pool ✅


=============================================================================
CONNECTION POOL WITH ASYNC/AWAIT (MODERN STYLE)
=============================================================================

📌 1. IMPORT
-----------------------------------------------------------------------------
import mysql from 'mysql2/promise';


📌 2. CREATE POOL
-----------------------------------------------------------------------------
const pool = mysql.createPool({
  host: 'localhost',
  user: 'root',
  password: 'your_password',
  database: 'test_db',
  waitForConnections: true,
  connectionLimit: 10,   // max connections
  queueLimit: 0          // unlimited queue
});


📌 3. RUN QUERY (SIMPLE)
-----------------------------------------------------------------------------
try {
  const [rows, fields] = await pool.query("SELECT * FROM users");
  console.log(rows);
} catch (err) {
  console.log(err);
}

👉 Pool automatically:
- gives connection
- runs query
- releases connection


📌 4. PREPARED STATEMENTS (BEST PRACTICE)
-----------------------------------------------------------------------------
try {
  const [rows] = await pool.execute(
    "SELECT * FROM users WHERE id = ?",
    [1]
  );
  console.log(rows);
} catch (err) {
  console.log(err);
}

👉 Safe from SQL injection ✅


📌 5. MANUAL CONNECTION (ADVANCED)
-----------------------------------------------------------------------------
const connection = await pool.getConnection();

try {
  const [rows] = await connection.query("SELECT * FROM users");
  console.log(rows);
} finally {
  connection.release(); // IMPORTANT
}

FLOW
=============================================================================

Request → Pool → Get connection → Execute query → Release → Reuse

WHAT ARE person, internet, location IN FAKER?
=============================================================================

They are NOT actual data.

They are ORGANIZATIONAL GROUPS (namespaces/modules).

=============================================================================
STRUCTURE OF FAKER
=============================================================================

faker
 ├── person
 │     └── fullName()
 │     └── firstName()
 │
 ├── internet
 │     └── email()
 │     └── username()
 │
 ├── location
       └── city()
       └── country()

=============================================================================
WHAT THEY REALLY ARE
=============================================================================

• person   → group of name-related functions
• internet → group of web-related functions
• location → group of place-related functions

USING PROMISES (MODERN WAY - ASYNC/AWAIT)
=============================================================================

📌 IMPORT
-----------------------------------------------------------------------------
import mysql from 'mysql2/promise';


📌 EXAMPLE
-----------------------------------------------------------------------------
import mysql from 'mysql2/promise';

async function main() {
  try {
    const connection = await mysql.createConnection({
      host: "localhost",
      user: "root",
      database: "test"
    });

    const [results, fields] = await connection.execute(
      "SELECT * FROM table WHERE name = ? AND age > ?",
      ['Devesh', 53]
    );

    console.log(results);

    await connection.end();
  }
   catch (err) {
    console.log(err);
  }
}

main();

async function main()

→ allows use of await inside function

await means:
→ "pause here until DB gives result",  but DOES NOT block entire program

📌 connection.execute()
-----------------------------------------------------------------------------
• ? gets safely replaced
• prevents SQL injection
• better for placeholders (? values)

📌 NOTE (IMPORTANT)
-----------------------------------------------------------------------------
- execute() uses prepared statements internally
- Protects against SQL Injection
- Uses placeholders (?) for safe values

TIP:
If same query runs again → cached (LRU cache)
→ better performance (no re-prepare)


=============================================================================
PREPARED STATEMENTS (SECURITY)
=============================================================================

📌 WHAT
-----------------------------------------------------------------------------
Prepared statements separate SQL query and data.

Example:
"SELECT * FROM users WHERE name = ?"

👉 Values passed separately → prevents SQL injection


📌 WHY IMPORTANT
-----------------------------------------------------------------------------
- Protects against SQL injection attacks
- Improves performance (query reuse)
