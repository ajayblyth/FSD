
================================================================================
EVENT BUBBLING – COMPACT NOTE (HORIZONTAL LAYOUT)
================================================================================

DEFINITION
--------------------------------------------------------------------------------
When an event fires on a DOM element, it doesn't stop there —
it travels upward through every ancestor in the tree.

👉 “The event object doesn’t stop at the target element; it propagates upward through the DOM tree.”

FLOW
----
Event Fires
   ↓
Bubbles Up
   ↓
Document (Root)


Bubbling is the default behavior for most DOM events.

Knowing when to use it, and when to stop it,
gives you precise control over your UI logic.

FLOW STRUCTURE (Example DOM Tree)
--------------------------------------------------------------------------------
document
   ↑
body
   ↑
div
   ↑
button  ← (User Clicks Here)

Execution Order:
button → div → body → document

CODE EXAMPLE
--------------------------------------------------------------------------------
let div = document.querySelector("div");
let btn = document.querySelector("button");

div.addEventListener("click", function() {
    console.log("Div clicked");
});

btn.addEventListener("click", function() {
    console.log("Button clicked");
});

If button is clicked:
Output:
Button clicked
Div clicked


WHY BUBBLING IS USEFUL
--------------------------------------------------------------------------------
✔ Enables Event Delegation
✔ Fewer event listeners needed
✔ Better performance
✔ Cleaner logic


STOPPING BUBBLING
--------------------------------------------------------------------------------
Use: event.stopPropagation();

btn.addEventListener("click", function(e) {
    e.stopPropagation();
    console.log("Button only");
});

Now event will NOT move to parent elements.


CORE IDEA
--------------------------------------------------------------------------------
Target Element
        ↓
Parent
        ↓
Ancestor
        ↓
document

Note: bubble doesnt reaches the body element, because it doesnt have callback function.

EVENT DELEGATION – COMPLETE NOTES
================================================================================

DEFINITION
--------------------------------------------------------------------------------
Event Delegation is a technique where we attach a single event listener to a 
parent element to handle events for its child elements.

It works because of Event Bubbling.


WHY USE EVENT DELEGATION?
--------------------------------------------------------------------------------
✔ Fewer event listeners
✔ Better performance
✔ Cleaner code
✔ Works for dynamically added elements


CORE IDEA
--------------------------------------------------------------------------------
Child event
      ↓ (bubbles up)
Parent listener handles it
      ↓
Use e.target to detect which child triggered the event


HOW IT WORKS (STEP-BY-STEP)
--------------------------------------------------------------------------------
1) User clicks child element (e.g., button)
2) Event fires on that element
3) Event bubbles up through DOM
4) Parent listener receives the event
5) e.target identifies the actual clicked element


IMPORTANT PROPERTIES
--------------------------------------------------------------------------------
e.target         → actual element that triggered the event
e.currentTarget  → element on which listener is attached


================================================================================
NORMAL APPROACH (WITHOUT DELEGATION)
================================================================================
let buttons = document.querySelectorAll("button");

buttons.forEach(function(btn) {
    btn.addEventListener("click", function() {
        console.log("Button clicked");
    });
});

PROBLEMS
--------
❌ Adds listener to every element
❌ Poor performance for large lists
❌ New elements won't have listeners


================================================================================
EVENT DELEGATION APPROACH
================================================================================
let parent = document.querySelector("#container");

parent.addEventListener("click", function(e) {
    if (e.target.tagName === "BUTTON") {
        console.log("Button clicked");
    }
});

✔ Only ONE listener on parent
✔ Uses bubbling + e.target


IMPORTANT NOTE (CLARITY)
--------------------------------------------------------------------------------
- Listener is attached to parent (not document)
- Event actually happens on child
- Event bubbles up to parent
- Parent uses e.target to know which child was clicked

tagName comes from browser:
e.target.tagName → returns tag in UPPERCASE (e.g., "BUTTON")


================================================================================
HANDLING MULTIPLE CHILD ELEMENTS
================================================================================

EXAMPLE HTML
------------
<div id="container">
  <button>Save</button>
  <a href="#">Link</a>
  <p>Text</p>
</div>


JS (MULTIPLE CONDITIONS)
-----------------------
let parent = document.querySelector("#container");

parent.addEventListener("click", function(e) {
    if (e.target.tagName === "BUTTON") {
        console.log("Button clicked");
    } 
    else if (e.target.tagName === "A") {
        console.log("Link clicked");
    } 
    else if (e.target.tagName === "P") {
        console.log("Paragraph clicked");
    }
});

✔ One listener
✔ Handles multiple child elements


================================================================================
BETTER REAL-WORLD APPROACH (USING CLASSES)
================================================================================

HTML
----
<div id="container">
  <button class="btn">Save</button>
  <a class="link">Link</a>
  <p class="text">Text</p>
</div>


JS
--
parent.addEventListener("click", function(e) {
    if (e.target.classList.contains("btn")) {
        console.log("Button clicked");
    } 
    else if (e.target.classList.contains("link")) {
        console.log("Link clicked");
    } 
    else if (e.target.classList.contains("text")) {
        console.log("Text clicked");
    }
});

✔ More flexible than tagName
✔ Works even if HTML tag changes


================================================================================
BEST PRACTICE (MOST IMPORTANT)
================================================================================

Use closest() to handle nested elements

parent.addEventListener("click", function(e) {
    if (e.target.closest(".btn")) {
        console.log("Button clicked");
    } 
    else if (e.target.closest(".link")) {
        console.log("Link clicked");
    }
});


WHY closest() IS BETTER
--------------------------------------------------------------------------------
Example:
<button class="btn">
   <span>Click me</span>
</button>

If user clicks <span>:

e.target.tagName = "SPAN"      ❌ (wrong element)
e.target.closest(".btn")       ✔ (correct parent found)


================================================================================
WHEN TO USE EVENT DELEGATION
================================================================================
✔ Lists (UL > LI)
✔ Tables
✔ Multiple buttons
✔ Forms with many inputs
✔ Dynamically added elements


================================================================================
FINAL UNDERSTANDING
================================================================================
- Event does NOT stay on child element
- It bubbles up to parent
- Parent can handle events for all children
- Delegation = using this behavior efficiently


ONE-LINE (INTERVIEW READY)
--------------------------------------------------------------------------------
Event delegation allows a parent element to handle events for multiple child
elements using a single listener by leveraging event bubbling and e.target.

EVENT CAPTURING/ not covered in class
============================================================

WHAT HAPPENS WHEN YOU CLICK?
----------------------------
When you click an element, browser does NOT directly run
that element’s handler.

It first travels from top → down:

document → html → body → parent → child (clicked element)

This downward travel = CAPTURING phase


KEY IDEA
--------
Even if you click the child element,
browser reaches it step-by-step from the top.


EXAMPLE
-------
HTML:
<div id="parent">
  <button id="child">Click</button>
</div>


CAPTURING ENABLED
-----------------
parent.addEventListener("click", () => console.log("Parent"), true);

child.addEventListener("click", () => console.log("Child"), true);


OUTPUT
------
Parent
Child

WHY?
----
Browser travels:
top → parent → child

So parent runs first, then child.


EVENT FLOW (IMPORTANT)
----------------------
1. Capturing  (top → target)
2. Target     (actual element)
3. Bubbling   (target → top)

Capturing ALWAYS happens internally,
but you only see it when enabled.


DEFAULT BEHAVIOR
----------------
addEventListener("click", handler);

→ Listens in BUBBLING phase


ENABLE CAPTURING
----------------
addEventListener("click", handler, true);

→ Run handler during capturing phase


MEMORY TRICK
------------
Capturing = DOWN
Bubbling  = UP


FINAL UNDERSTANDING
-------------------
Browser does NOT jump to clicked element.

It travels:
top → reaches element → then goes back up
