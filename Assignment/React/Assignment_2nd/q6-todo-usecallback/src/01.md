Why does this work?

Suppose we have

Learn React
Learn Hooks

When you click Add Todo, the parent (Todo) re-renders because the todos state changes.

Without any optimization:

Todo Render

↓

TodoItem 1 Render

↓

TodoItem 2 Render

↓

TodoItem 3 Render

All items render again.

With React.memo:

React compares the props passed to each TodoItem.

For the first item:

Old props

todo = { id:1, text:"Learn React" }
onDelete = deleteTodo

New props

todo = { id:1, text:"Learn React" }
onDelete = deleteTodo

The todo object for existing items is the same object reference because you append a new item using:

setTodos((prevTodos) => [
  ...prevTodos,
  {
    id: Date.now(),
    text: input,
  },
]);

The spread operator copies the array, but it reuses the existing todo objects. Only the new todo object is created.

Also, because deleteTodo is wrapped in useCallback([]), its function reference stays the same.

Since both props are unchanged, React.memo skips re-rendering the existing items.

Only the newly added todo has no previous props to compare, so it renders.

What if we remove useCallback?

Every time the parent renders, a new deleteTodo function is created.

So React sees:

Old onDelete !== New onDelete

Even though the todo data hasn't changed, the function prop changed, so every TodoItem re-renders.

What if we don't use the functional form of setState?

For example:

const deleteTodo = useCallback((id) => {
  setTodos(todos.filter((todo) => todo.id !== id));
}, [todos]);

Now deleteTodo depends on todos.

Every time the todo list changes, a new deleteTodo function is created because the dependency (todos) changed.

That means the onDelete prop changes for every TodoItem, causing all memoized items to re-render.

Using the functional form:

setTodos((prevTodos) =>
  prevTodos.filter((todo) => todo.id !== id)
);

avoids reading todos from the outer scope, so deleteTodo has no dependencies and can safely use an empty dependency array ([]). This keeps the function reference stable and allows React.memo to prevent unnecessary re-renders, exactly as required by the assignment.
