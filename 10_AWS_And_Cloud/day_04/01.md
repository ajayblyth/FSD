Dockerfile is a text file containing instructions to build a Docker image.

A Dockerfile is a text file that contains a sequence of instructions (such as FROM, COPY, RUN, and CMD) used by Docker to automatically build a Docker image.

With a Dockerfile

You write the instructions once, then build the image anytime with:

=====================================================================
DOCKERFILE INSTRUCTIONS
=====================================================================

+------------+-----------------------------------------------+
| Instruction| Purpose                                       |
+------------+-----------------------------------------------+
| FROM       | Specifies the base image to build from.       |
|            | Example: FROM node:20                         |
+------------+-----------------------------------------------+
| WORKDIR    | Sets the working directory inside the image.  |
|            | Example: WORKDIR /app                         |
+------------+-----------------------------------------------+
| COPY       | Copies files/folders from host to image.      |
|            | Example: COPY . .                             |
+------------+-----------------------------------------------+
| RUN        | Executes commands during image build.         |
|            | Can be used multiple times.                   |
|            | Example: RUN npm install                      |
+------------+-----------------------------------------------+
| ENV        | Sets environment variables.                   |
|            | Example: ENV PORT=3000                        |
+------------+-----------------------------------------------+
| EXPOSE     | Documents the port used by the application.   |
|            | Example: EXPOSE 3000                          |
+------------+-----------------------------------------------+
| USER       | Sets the user for subsequent instructions.    |
|            | Example: USER node                            |
+------------+-----------------------------------------------+
| CMD        | Specifies the default command when the        |
|            | container starts. Only one CMD is allowed.    |
|            | Example: CMD ["npm", "start"]                 |
+------------+-----------------------------------------------+

=====================================================================
BUILD TIME vs CONTAINER START TIME
=====================================================================

RUN  → Executes while building the Docker image.
CMD  → Executes when the container starts.

Example:
RUN npm install      → Install dependencies during build.
CMD npm start        → Start the application when the container runs.

If you're writing a Dockerfile and want to use the Node.js 22 Alpine image:

FROM node:22-alpine
Why node:22-alpine?
node → Official Node.js image from Docker Hub.
22 → Uses Node.js version 22.
alpine → Based on Alpine Linux, a lightweight Linux distribution.
Benefits of Alpine
✅ Smaller image size (much smaller than standard Node images)
✅ Faster downloads
✅ Faster image builds
✅ Uses less disk space
✅ Good for production in many cases

DOCKERFILE EXPLANATION
=====================================================================

Dockerfile
---------------------------------------------------------------------
FROM node:22-alpine

WORKDIR /testapp

COPY package*.json ./

RUN npm install

COPY . .
=====================================================================


1. FROM
---------------------------------------------------------------------
FROM node:22-alpine

Purpose:
• Specifies the base image to build from.
• Downloads the official Node.js image from Docker Hub.
• Uses Node.js version 22.
• Uses Alpine Linux (small and lightweight).

Meaning:
"Start with a computer that already has Node.js 22 installed."


2. WORKDIR
---------------------------------------------------------------------
WORKDIR /testapp

Purpose:
• Creates the folder (if it doesn't exist).
• Sets it as the current working directory.
• All following commands execute inside this folder.

Equivalent to:

cd /testapp


3. COPY package*.json ./
---------------------------------------------------------------------
COPY package*.json ./

Purpose:
• Copies dependency files from your computer into the image.

Copies:
• package.json
• package-lock.json (if present)

Destination:
Current working directory (/testapp)

Why first?
• npm install only needs these files.
• Docker can reuse this layer if only application code changes.


4. RUN
---------------------------------------------------------------------
RUN npm install

Purpose:
• Installs all project dependencies.
• Executes while BUILDING the image.
• Creates the node_modules folder inside the image.

Runs only during:
docker build


5. COPY . .
---------------------------------------------------------------------
COPY . .

Purpose:
• Copies the entire project into the image.

First "."  → Current folder on your computer.
Second "." → Current working directory inside the image (/testapp).

Example:

Host Machine                 Docker Image
------------                 ----------------
app.js         ----------->  /testapp/app.js
routes/        ----------->  /testapp/routes/
public/        ----------->  /testapp/public/
views/         ----------->  /testapp/views/


=====================================================================
WHY COPY package*.json FIRST?
=====================================================================

COPY package*.json ./
RUN npm install
COPY . .

Reason:
• If only your source code changes (app.js, routes, etc.),
  Docker reuses the cached npm install layer.
• Dependencies are not installed again.
• Build becomes much faster.

=====================================================================
ENV
=====================================================================

ENV MONGO_DB_USERNAME=root

Purpose:
• Sets an environment variable inside the image/container.
• Used to store configuration values.

Example:
MONGO_DB_USERNAME = root


=====================================================================
EXPOSE
=====================================================================

EXPOSE 5050

Purpose:
• Documents that the application listens on port 5050.
• Does NOT publish the port to the host.
• Used for documentation and by Docker tools.

Example:
Application runs on port 5050 inside the container.


=====================================================================
CMD
=====================================================================

CMD ["node", "server.js"]

Purpose:
• Specifies the default command to run when the container starts.
• Only one CMD is allowed in a Dockerfile.

Meaning:
When the container starts, Docker executes:

node server.js

=====================================================================
BUILD THE DOCKER IMAGE
=====================================================================

Command:
---------------------------------------------------------------------
docker build -t testapp .

=====================================================================
BREAKDOWN
=====================================================================

1. docker build
---------------------------------------------------------------------
• Reads the Dockerfile.
• Executes each instruction (FROM, COPY, RUN, etc.).
• Builds a Docker image.

Flow:
Dockerfile  ───►  Docker Build  ───►  Docker Image


2. -t testapp
---------------------------------------------------------------------
• -t = tag (name the image).
• Assigns the image the name "testapp".

Example:
docker build -t testapp .

With version:
docker build -t testapp:1.0 .


3. . (Dot)
---------------------------------------------------------------------
• Represents the current folder.
• Called the Build Context.
• Docker looks in this folder for:
  - Dockerfile
  - Source code
  - Files to COPY into the image

IMPORTANT:
Run the command from the folder that contains the Dockerfile.

Example:

project/
│
├── Dockerfile
├── package.json
├── server.js
└── ...

Open Command Prompt in "project" and run:

docker build -t testapp .


=====================================================================
VERIFY THE IMAGE
=====================================================================

List all Docker images:

docker images

Example Output:

REPOSITORY   TAG      IMAGE ID       CREATED
testapp      latest   ab12cd34ef56   2 minutes ago

=====================================================================
SUMMARY
=====================================================================

docker build      → Builds an image from the Dockerfile.
-t testapp        → Names (tags) the image as "testapp".
-t testapp:1.0    → Names the image with version 1.0.
.                 → Current folder (build context).

Verify:
docker images

1. docker run
---------------------------------------------------------------------
• Creates and starts a new container from an image.


2. -p 5050:5050
---------------------------------------------------------------------
Syntax:
-p <HostPort>:<ContainerPort>

Meaning:
Host Port      : 5050
Container Port : 5050

Purpose:
• Maps port 5050 on your computer to port 5050
  inside the container.

Example:
http://localhost:5050


3. --network docker-testapp-main_default
---------------------------------------------------------------------
Purpose:
• Connects the container to the specified Docker network.

Reason:
• Allows this container to communicate with other
  containers on the same network.

Network Name:
docker-testapp-main_default


4. --name node-testapp
---------------------------------------------------------------------
Purpose:
• Assigns a name to the container.

Container Name:
node-testapp

Instead of using the container ID, you can use:

docker stop node-testapp
docker logs node-testapp


5. -e MONGO_DB_PWD=qwert
---------------------------------------------------------------------
-e = Environment Variable

Variable:
MONGO_DB_PWD

Value:
qwert

Purpose:
• Passes the MongoDB password to the application
  running inside the container.


6. -e MONGO_DB_HOST=mongo
---------------------------------------------------------------------
Variable:
MONGO_DB_HOST

Value:
mongo

Purpose:
• Tells the application where MongoDB is running.
• "mongo" is the name of the MongoDB container
  (or service in Docker Compose).


7. testapp
---------------------------------------------------------------------
Purpose:
• Name of the Docker image to run.

Docker:
"Create a container from the image named 'testapp'."
