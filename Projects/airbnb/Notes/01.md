EXPRESS MIDDLEWARE + ERROR HANDLING (COMPLETE NOTES)
=============================================================================


📌 USING next() IN MIDDLEWARE
-----------------------------------------------------------------------------
• next = function used to pass control to next middleware

Example:
-----------------------------------------------------------------------------
app.use((req, res, next) => {
  console.log('Time:', Date.now());
  next();
});

-----------------------------------------------------------------------------


📌 IMPORTANT RULE
-----------------------------------------------------------------------------
• If middleware does NOT send response → it MUST call next()
• Otherwise request will hang (no response sent)

Example:
-----------------------------------------------------------------------------
app.use((req, res, next) => {
  console.log("Hi, I am 1st middleware");
  next();
});

app.use((req, res, next) => {
  console.log("Hi, I am 2nd middleware");
  next();
});

-----------------------------------------------------------------------------


⚠️ COMMON MISTAKES
-----------------------------------------------------------------------------
1. Forgetting next() → request hangs ❌
2. Writing code after next() ❌

Wrong:
-----------------------------------------------------------------------------
next();
console.log("This may not run properly");

👉 Either use return next() OR ensure no important code after it


=============================================================================
📌 UTILITY MIDDLEWARE
-----------------------------------------------------------------------------
app.use((req, res, next) => {
  req.responseTime = new Date(Date.now()).toString();
  console.log(req.method, req.path, req.responseTime, req.hostname);
  next();
});

👉 Used for logging, adding custom fields, debugging


=============================================================================
📌 ORDER OF MIDDLEWARE (VERY IMPORTANT)
-----------------------------------------------------------------------------
• Express executes in TOP → DOWN order

✔ Correct:
-----------------------------------------------------------------------------
app.use((req, res, next) => {
  console.log("Middleware runs first!");
  next();
});

app.get('/home', (req, res) => {
  res.send("Home Page");
});

❌ Wrong:
-----------------------------------------------------------------------------
app.get('/home', (req, res) => {
  res.send("Home Page");
});

app.use((req, res, next) => {
  console.log("This will NOT run for /home");
  next();
});


=============================================================================
📌 PATH IN app.use()
-----------------------------------------------------------------------------
• Controls where middleware runs

-----------------------------------------------------------------------------


✔ GLOBAL (no path)
-----------------------------------------------------------------------------
app.use((req, res, next) => {
  console.log("Runs for ALL routes");
  next();
});


✔ WITH PATH
-----------------------------------------------------------------------------
app.use('/api', (req, res, next) => {
  console.log("Runs only for /api routes");
  next();
});

👉 Matches:
• /api
• /api/users
• /api/products

=============================================================================
📌 CUSTOM ERROR HANDLER (IMPORTANT)
-----------------------------------------------------------------------------
• Must be placed AFTER all routes

Example:
-----------------------------------------------------------------------------
app.use((err, req, res, next) => {
  console.log(err);
  console.log("I am error handler 1");
  next(err); // pass forward
});

app.use((err, req, res, next) => {
  console.log("Final error handler");
  console.log(err);
  res.status(500).send("Internal Server Error!");
});

👉 Either handle OR pass → not both after sending response


=============================================================================
📌 ERROR HANDLER PLACEMENT RULE
-----------------------------------------------------------------------------
• Always at the END

Why?
-----------------------------------------------------------------------------
• Express runs top → bottom
• Last handler acts as catch-all


Example:
-----------------------------------------------------------------------------
app.use('/users', userRoutes);
app.use('/products', productRoutes);
app.use('/orders', orderRoutes);

app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({
    message: "Something went wrong!",
    error: err.message
  });
});


=============================================================================
📌 REGULAR vs ERROR MIDDLEWARE
=============================================================================

REGULAR MIDDLEWARE
-----------------------------------------------------------------------------
Signature: (req, res, next)

• Runs on every request
• Used for logging, auth, parsing

Example:
-----------------------------------------------------------------------------
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next();
});


-----------------------------------------------------------------------------


ERROR MIDDLEWARE
-----------------------------------------------------------------------------
Signature: (err, req, res, next)

• Runs only when error occurs
• Must be at end

Example:
-----------------------------------------------------------------------------
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(err.status || 500).json({ error: err.message });
});

📌 CUSTOM ERROR CLASS
-----------------------------------------------------------------------------
class ExpressError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}

-----------------------------------------------------------------------------


📌 USING CUSTOM ERROR
-----------------------------------------------------------------------------
const checkToken = (req, res, next) => {
  let { token } = req.query;

  if (token === "giveaccess") {
    return next();
  }

  throw new ExpressError(401, "ACCESS DENIED!");
};


=============================================================================
🎯 FINAL KEY POINTS
-----------------------------------------------------------------------------
• next() → passes control
• No next() → request hangs
• Order matters (top → bottom)
• Middleware can be global or route-specific
• Error handler must be LAST
• Either send response OR call next()
• Custom errors improve structure

HANDLING ASYNC ERRORS IN EXPRESS (IMPORTANT)
=============================================================================


📌 PROBLEM (ASYNC ERRORS)
-----------------------------------------------------------------------------
• Errors inside async functions are NOT caught automatically (in Express 4)

Example (WRONG - will crash / skip custom handler):
-----------------------------------------------------------------------------
app.get('/user/:id', async (req, res) => {
  const user = await User.findById(req.params.id); // may throw error
  res.json(user);
});

👉 If error occurs → NOT caught → may crash or go to default handler


=============================================================================
📌 SOLUTION 1: TRY / CATCH (BASIC WAY)
-----------------------------------------------------------------------------
app.get('/user/:id', async (req, res, next) => {
  try {
    const user = await User.findById(req.params.id);

    if (!user) {
      return res.status(404).json({ error: "User not found" });
    }

    res.json(user);

  } catch (err) {
    next(err); // forward error to middleware
  }
});


📌 ERROR HANDLER (CATCHES IT)
-----------------------------------------------------------------------------
app.use((err, req, res, next) => {
  res.status(500).json({ error: err.message });
});


👉 FLOW:
async error → catch → next(err) → error middleware


=============================================================================
📌 EXPRESS VERSION DIFFERENCE (VERY IMPORTANT)
-----------------------------------------------------------------------------
Express 4:
• ❌ Does NOT auto-handle async errors
• Must use try/catch OR wrapper

Express 5:
• ✔ Automatically forwards rejected promises
• No need for try/catch in most cases


=============================================================================
📌 IMPORTANT CAVEATS
-----------------------------------------------------------------------------
1. Works only for async/await or promise-based code
2. setTimeout errors NOT caught automatically

Example:
-----------------------------------------------------------------------------
setTimeout(() => {
  throw new Error("Error"); // ❌ must handle manually
}, 1000);

3. Synchronous errors inside async function → auto handled


=============================================================================
📌 PROBLEM WITH TRY/CATCH
-----------------------------------------------------------------------------
• Repetitive
• Bulky
• Makes code messy


=============================================================================
📌 SOLUTION 2: wrapAsync (BEST PRACTICE)
-----------------------------------------------------------------------------
function asyncWrap(fn) {
  return function (req, res, next) {
    fn(req, res, next).catch(err => next(err));
  };
}


👉 Automatically catches async errors and forwards them


=============================================================================
📌 USING wrapAsync
-----------------------------------------------------------------------------
app.get("/chats/:id", asyncWrap(async (req, res, next) => {

  let { id } = req.params;

  let chat = await Chat.findById(id);

  if (!chat) {
    return next(new ExpressError(404, "Chat not found"));
  }

  res.json(chat);
}));

📌 CUSTOM ERROR CLASS (USED HERE)
-----------------------------------------------------------------------------
class ExpressError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}


=============================================================================
📌 FINAL FLOW (CLEAN ARCHITECTURE)
-----------------------------------------------------------------------------
Route (async) 
   ↓
asyncWrap catches error
   ↓
next(err)
   ↓
Custom error middleware
   ↓
Response sent


=============================================================================
🎯 FINAL KEY POINTS
-----------------------------------------------------------------------------
• Async errors NOT auto-caught in Express 4
• Use try/catch OR wrapAsync
• wrapAsync = cleaner + reusable
• Always call next(err) to forward error
• Error middleware must be last
• setTimeout errors must be handled manually
