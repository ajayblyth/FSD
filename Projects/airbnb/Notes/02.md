======================================== MONGOOSE ERRORS ========================================

Definition:
----------------------------------------
Mongoose errors occur when database operations fail
due to validation issues, wrong queries, missing data,
casting problems, etc.


======================================== WHY ERROR HANDLING IS IMPORTANT ========================================

- Prevents application crash
- Gives meaningful response
- Helps debugging
- Improves security
- Improves user experience


======================================== COMMON MONGOOSE ERRORS ========================================

Error Type                 | Meaning
---------------------------|--------------------------------------------------
ValidationError            | Schema validation failed
CastError                  | Invalid ObjectId or datatype
MongoServerError           | Database/server-related error
DocumentNotFoundError      | Document not found
VersionError               | Version conflict during update


======================================== VALIDATION ERROR ========================================

Definition:
----------------------------------------
Occurs when submitted data does not satisfy
schema validation rules.

Examples:
----------------------------------------
- Required field missing
- minlength failed
- Invalid datatype
- Custom validator failed


======================================== EXAMPLE SCHEMA ========================================

const userSchema = new mongoose.Schema({

  username: {
    type: String,
    required: true,
    minlength: 3
  },

  age: {
    type: Number,
    min: 18
  }

});


======================================== EXAMPLE VALIDATION ERROR ========================================

const User = mongoose.model("User", userSchema);

const user = new User({
  username: "ab",
  age: 10
});

await user.save();

WHY ERROR?
----------------------------------------
- username length < 3
- age < 18

👉 Mongoose throws ValidationError


======================================== ERROR HANDLER FUNCTION ========================================

const handleValidationErr = (err) => {

  console.log("Validation error occurred");

  return err;

};

Purpose:
----------------------------------------
- Handles validation-related errors
- Keeps code organized
- Reusable function


======================================== EXPRESS ERROR MIDDLEWARE ========================================

app.use((err, req, res, next) => {

  console.log(err.name);

  if (err.name === "ValidationError") {

    err = handleValidationErr(err);

  }

  next(err);

});



======================================== BREAKDOWN OF SYNTAX ========================================

app.use(...)
----------------------------------------
Registers middleware in Express


(err, req, res, next)
----------------------------------------
Express error-handling middleware syntax

IMPORTANT:
----------------------------------------
Normal middleware:
(req, res, next)

Error middleware:
(err, req, res, next)

👉 Presence of err makes it error middleware


======================================== FLOW OF EXECUTION ========================================

1) Request comes
        ↓
2) Mongoose operation runs
        ↓
3) Validation fails
        ↓
4) Mongoose throws ValidationError
        ↓
5) Express catches error
        ↓
6) app.use(error middleware) runs
        ↓
7) handleValidationErr executes
        ↓
8) next(err) forwards error


======================================== err.name ========================================

err.name contains error type name

Example:
----------------------------------------
ValidationError
CastError
MongoServerError

Used for:
----------------------------------------
- Identifying specific error type
- Custom handling logic


======================================== VALIDATION ERROR OBJECT ========================================

ValidationError contains detailed info

Example:
----------------------------------------
err.errors.username.message
err.errors.age.message

Useful for:
----------------------------------------
- Showing user-friendly messages
- Sending API error responses


======================================== BETTER VERSION (PRACTICAL) ========================================

app.use((err, req, res, next) => {

  if (err.name === "ValidationError") {

    console.log("Validation Error");

    return res.status(400).send(err.message);

  }

  next(err);

});


======================================== CAST ERROR (IMPORTANT)
========================================

Definition:
----------------------------------------
Occurs when invalid datatype is used.

Example:
----------------------------------------
/users/abc123invalidid

If Mongoose expects ObjectId:
----------------------------------------
CastError occurs ❗


======================================== HANDLING MULTIPLE ERRORS ========================================

app.use((err, req, res, next) => {

  if (err.name === "ValidationError") {

    return res.send("Validation Failed");

  }

  if (err.name === "CastError") {

    return res.send("Invalid ID");

  }

  next(err);

});


======================================== KEY CONCEPTS ========================================

✔ Mongoose throws errors automatically
✔ Express middleware can catch errors
✔ err.name identifies error type
✔ ValidationError is very common
✔ next(err) forwards error middleware chain


======================================== ONE-LINE (INTERVIEW) ========================================

Mongoose validation errors occur when data violates
schema rules, and Express error middleware is used
to catch and handle those errors properly.
===================================================== FORM VALIDATION ========================================

Definition:
----------------------------------------
Form Validation = checking whether user input is correct, complete,
and in proper format before processing.


======================================== WHY VALIDATION IS IMPORTANT ========================================

- Prevents invalid data        | - Improves security
- Improves user experience     | - Avoids wrong submissions
- Protects database consistency


======================================== VALIDATION LEVELS ========================================

1) Client-Side Validation      | 2) Server-Side Validation


======================================== 1) CLIENT-SIDE VALIDATION ========================================

Definition:                                  | Flow:
--------------------------------------------|-----------------------------------------
Validation performed in browser             | User → Browser → Server
before data is sent to server               |

Purpose:                                    | Examples:
--------------------------------------------|-----------------------------------------
- Fast feedback                             | - Required field
- Reduces server requests                   | - Email format
- Better user experience                    | - Password length
                                            | - Number range

Technologies Used:
--------------------------------------------
- HTML5 validation
- JavaScript
- Bootstrap validation


======================================== COMMON HTML VALIDATION ATTRIBUTES ========================================

required                    | minlength / maxlength     | type
----------------------------|----------------------------|-----------------------
<input required>            | <input minlength="3">     | <input type="email">


min / max                   | pattern
----------------------------|------------------------------------------
<input min="1" max="10">    | <input pattern="[A-Za-z]+">


======================================== CLIENT VALIDATION EXAMPLE ========================================

<form>
  <input type="email" required>
  <button>Submit</button>
</form>

Browser checks:
----------------------------------------
✔ field not empty
✔ valid email format


======================================== 2) SERVER-SIDE VALIDATION ========================================

Definition:                                  | Flow:
--------------------------------------------|-----------------------------------------
Validation performed on server              | User → Browser → Server → Validation
after form submission                       |

Purpose:
--------------------------------------------
- Security
- Final verification
- Prevent fake/malicious data

IMPORTANT:
--------------------------------------------
Client-side validation can be bypassed ❗
Server-side validation is mandatory ✅


======================================== SERVER VALIDATION EXAMPLE ========================================

app.post("/signup", (req, res) => {

  if(!req.body.email) {
    return res.send("Email required");
  }

});


======================================== CLIENT vs SERVER VALIDATION ========================================

Feature              | Client-Side           | Server-Side
----------------------------------------------------------------
Where                | Browser               | Server
Speed                | Fast                  | Slower
Security             | Less secure           | Secure
User Experience      | Better                | Final protection
Can be bypassed?     | Yes ❗                | No ✅


======================================== BROWSER VALIDATION ========================================

Browser checks:
----------------------------------------
- Correct data format
- Required fields filled
- Constraints satisfied

Examples:
----------------------------------------
✔ Valid email format
✔ Password length
✔ Required input
✔ Valid number range


======================================== BOOTSTRAP FORM VALIDATION ========================================

Bootstrap provides custom styles and feedback
for HTML5 form validation.

Docs:
----------------------------------------
https://getbootstrap.com/docs/5.3/forms/validation/


======================================== BOOTSTRAP VALIDATION CLASSES ========================================

was-validated              | is-valid                 | is-invalid
---------------------------|---------------------------|--------------------------
Triggers validation style  | Marks input valid        | Marks input invalid


======================================== BOOTSTRAP VALIDATION EXAMPLE ========================================

<form class="was-validated">

  <input
    type="email"
    class="form-control"
    required
  >

  <div class="invalid-feedback">
    Please enter valid email
  </div>

</form>


======================================== HOW IT WORKS ========================================

- Browser validates input
- Bootstrap adds styles
- JavaScript can add custom checks
- User gets instant feedback


======================================== ONE-LINE (INTERVIEW) ========================================

Form validation ensures that user input is correct, secure,
and within required constraints before processing.
