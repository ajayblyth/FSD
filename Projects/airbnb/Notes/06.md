=============================================================================
HTTP & SESSIONS
=============================================================================

HTTP is a communication protocol between client and server.

-----------------------------------------------------------------------------
HTTP DEFINES:
-----------------------------------------------------------------------------
• how request is sent
• how response is returned
• request/response structure
• communication rules

=============================================================================
STATEFUL vs STATELESS PROTOCOL
=============================================================================

📌 STATEFUL PROTOCOL
-----------------------------------------------------------------------------
Server remembers previous request/session information.

-----------------------------------------------------------------------------
EXAMPLE:
-----------------------------------------------------------------------------
FTP

-----------------------------------------------------------------------------
MEANING:
-----------------------------------------------------------------------------
• server stores client state
• connection/session maintained

=============================================================================
📌 STATELESS PROTOCOL
-----------------------------------------------------------------------------
Server does NOT remember previous requests automatically.

-----------------------------------------------------------------------------
EXAMPLE:
-----------------------------------------------------------------------------
HTTP

-----------------------------------------------------------------------------
MEANING:
-----------------------------------------------------------------------------
Every request is independent.

Server forgets previous request unless extra mechanism used.

=============================================================================
PROBLEM WITH HTTP
=============================================================================

Suppose user logs in:

Request 1:
-----------------------------------------------------------------------------
POST /login

-----------------------------------------------------------------------------
Request 2:
-----------------------------------------------------------------------------
GET /profile

-----------------------------------------------------------------------------
ISSUE:
-----------------------------------------------------------------------------
HTTP itself does NOT remember user login.

=============================================================================
EXPRESS SESSION
=============================================================================

Express-session is an attempt to make HTTP behave statefully.

-----------------------------------------------------------------------------
PURPOSE:
-----------------------------------------------------------------------------
• remember logged-in users
• store user session data
• maintain state across requests

=============================================================================
SESSION CONCEPT
=============================================================================

USER 1
-----------------------------------------------------------------------------
sessionId: 101

{
  item: "laptop",
  item: "charger"
}

USER 2
-----------------------------------------------------------------------------
sessionId: 102

{
  item: "shirt",
  item: "pants"
}

-----------------------------------------------------------------------------
MEANING:
-----------------------------------------------------------------------------
Each user gets unique session storage on server.

=============================================================================
HOW EXPRESS SESSION WORKS
=============================================================================

BROWSER
-----------------------------------------------------------------------------
GET /testsession

SERVER
-----------------------------------------------------------------------------
stores:
{
  abc123: { user_id: "1234567890" }
}

-----------------------------------------------------------------------------
Server generates session ID:
-----------------------------------------------------------------------------
abc123

-----------------------------------------------------------------------------
Server sends cookie:
-----------------------------------------------------------------------------
Set-Cookie:
connect.sid=s:abc123.signature

=============================================================================
NEXT REQUEST
=============================================================================

BROWSER SENDS:
-----------------------------------------------------------------------------
GET /getsession

Cookie:
connect.sid=s:abc123.signature

=============================================================================
SERVER DOES
=============================================================================

1. Reads cookie
2. Extracts session id
3. Finds session data using id
4. Attaches data to req.session

-----------------------------------------------------------------------------
RESULT:
-----------------------------------------------------------------------------
"got session"

=============================================================================
IMPORTANT UNDERSTANDING
=============================================================================

Cookie stores ONLY session ID.

Actual session data stays on SERVER.

=============================================================================
INSTALL express-session
=============================================================================

npm install express-session

=============================================================================
BASIC SETUP
=============================================================================

const session = require("express-session");

app.use(session({

  secret: "secretkey",

  resave: false,

  saveUninitialized: false
}));

=============================================================================
resave
=============================================================================

QUESTION:
-----------------------------------------------------------------------------
"Should session be saved again even if nothing changed?"

-----------------------------------------------------------------------------
resave: true
-----------------------------------------------------------------------------
• saves session every request
• unnecessary writes

-----------------------------------------------------------------------------
resave: false   ✔ recommended
-----------------------------------------------------------------------------
• saves only when session changes

=============================================================================
saveUninitialized
=============================================================================

QUESTION:
-----------------------------------------------------------------------------
"Should empty new sessions be stored?"

-----------------------------------------------------------------------------
UNINITIALIZED SESSION:
-----------------------------------------------------------------------------
• session created
• but no data added yet

=============================================================================
saveUninitialized: true
=============================================================================

• stores empty sessions
• every visitor gets session entry

=============================================================================
saveUninitialized: false   ✔ recommended
=============================================================================

• session stored only after adding data

EXAMPLE:
-----------------------------------------------------------------------------
req.session.userId = 42

=============================================================================
SESSION STORE
=============================================================================

By default:
-----------------------------------------------------------------------------
express-session uses MemoryStore

=============================================================================
WHY MemoryStore IS BAD FOR PRODUCTION
=============================================================================

• memory leaks possible
• not scalable
• not shared across servers/processes

=============================================================================
POPULAR SESSION STORES
=============================================================================

connect-redis
-----------------------------------------------------------------------------
Redis-based, fast, scalable

connect-mongo
-----------------------------------------------------------------------------
MongoDB-based

connect-pg-simple
-----------------------------------------------------------------------------
PostgreSQL-based

session-file-store
-----------------------------------------------------------------------------
File-system based

=============================================================================
MONGODB SESSION STORE EXAMPLE
=============================================================================

const session = require("express-session");

const MongoStore = require("connect-mongo");

app.use(session({

  secret: "your-secret-key",

  resave: false,

  saveUninitialized: false,

  store: MongoStore.create({
    mongoUrl: "mongodb://localhost:27017/sessions"
  }),

  cookie: {
    maxAge: 1000 * 60 * 60 * 24
  }
}));

=============================================================================
cookie.maxAge
=============================================================================

1000 * 60 * 60 * 24

-----------------------------------------------------------------------------
MEANING:
-----------------------------------------------------------------------------
1 day in milliseconds

=============================================================================
SIMPLE COMPLETE FLOW
=============================================================================

User logs in
      ↓
Server creates session
      ↓
Session stored on server
      ↓
Session ID sent in cookie
      ↓
Browser stores cookie
      ↓
Browser sends cookie next request
      ↓
Server finds session using session ID

=============================================================================
ONE-LINE
=============================================================================

Express-session makes stateless HTTP behave statefully by storing session
data on the server and tracking users using session IDs stored in cookies.
