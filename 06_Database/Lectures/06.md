======================================================================
MYSQL AGGREGATE FUNCTIONS
======================================================================

 Aggregate functions take multiple rows and produce one result (or one result per group).

MAIN FUNCTIONS:
COUNT()   |   SUM()   |   AVG()   |   MIN()   |   MAX()

======================================================================
1) COUNT()
======================================================================

DEFINITION:
Returns number of rows or number of non-NULL values

----------------------------------------------------------------------
TYPES
----------------------------------------------------------------------
COUNT(*)                     → all rows (NULL included)
COUNT(column)               → non-NULL values only
COUNT(DISTINCT column)      → unique non-NULL values

----------------------------------------------------------------------
EXAMPLES
----------------------------------------------------------------------
SELECT COUNT(*) FROM student;                 → total rows
SELECT COUNT(age) FROM student;              → non-NULL ages
SELECT COUNT(DISTINCT city) FROM student;    → unique cities

----------------------------------------------------------------------
WITH WHERE / GROUP BY
----------------------------------------------------------------------
SELECT COUNT(*) FROM student WHERE age > 20;

SELECT city, COUNT(*)
FROM student
GROUP BY city;

----------------------------------------------------------------------
MULTIPLE COLUMN DISTINCT
----------------------------------------------------------------------
SELECT COUNT(DISTINCT city, age) FROM student;

→ unique (city, age) combinations

----------------------------------------------------------------------
IMPORTANT BEHAVIOR
----------------------------------------------------------------------
• COUNT(*) counts rows
• COUNT(column) ignores NULL
• DISTINCT ignores NULL

----------------------------------------------------------------------
EDGE CASES
----------------------------------------------------------------------
• All NULL column      → COUNT(column) = 0
• Empty table          → COUNT(*) = 0
• WHERE no match       → 0
• COUNT(*) vs COUNT(1) → same in MySQL
• Expressions          → NULL ignored

----------------------------------------------------------------------
WITH JOIN ⚠
----------------------------------------------------------------------
SELECT COUNT(*)
FROM student s
JOIN orders o ON s.id = o.student_id;

→ counts joined rows (may increase count)

----------------------------------------------------------------------
NOTES
----------------------------------------------------------------------
1) Always returns integer
2) Most used in analytics
3) Do not confuse COUNT(*) vs COUNT(column)

----------------------------------------------------------------------
EDGE CASES

• Non-numeric → error / wrong conversion ❌
• Mixed data  → strings → 0 ❌
• Large values → rare overflow

----------------------------------------------------------------------
NOTES
----------------------------------------------------------------------
1) Numeric columns only
2) Returns single value
3) Used in totals / reports

EDGE CASES
----------------------------------------------------------------------

----------------------------------------------------------------------
NOTES
----------------------------------------------------------------------
1) Uses SUM + COUNT internally
2) Numeric only
3) Widely used in analytics

5) MAX()
======================================================================

DEFINITION:
Returns largest value

SYNTAX:
SELECT MAX(column) FROM table;

----------------------------------------------------------------------
EXAMPLES
----------------------------------------------------------------------
SELECT MAX(age) FROM student;

If you want the second highest salary, you need to skip the highest one and pick the next.

✅ Method 1 (Simple & Common)

SELECT MAX(salary) AS second_highest
FROM employee
WHERE salary < (SELECT MAX(salary) FROM employee);

## doubt: so for 10th highest salary ,we need 10 nested sub queries?

for a general “Nth highest salary” problem, manually nesting 10 subqueries would be a terrible approach.

The nested MAX() method is useful mainly for explaining the 2nd/3rd highest interview question.

For Nth highest salary, use a ranking approach.

Best modern approach: DENSE_RANK()

SELECT salary
FROM (
    SELECT
        salary,
        DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employee
) AS ranked
WHERE rnk = 10;

Note: DENSE_RANK()
By itself, it doesn't know how to rank. That's what OVER() tells it.
duplicates get the same rank, and the next rank doesn't get skipped.

How it works

Suppose:

salary
------
100000
90000
90000
80000
70000
60000

DENSE_RANK() produces:

salary    rank
100000     1
90000      2
90000      2
80000      3
70000      4
60000      5

So:

WHERE rnk = 3

→ 80000

WHERE rnk = 10

→ 10th highest distinct salary

Another simple approach: LIMIT + OFFSET

If you want the Nth distinct salary:

SELECT DISTINCT salary
FROM employee
ORDER BY salary DESC
LIMIT 1 OFFSET 9;

If you remove DISTINCT, duplicate salaries count as separate rows.

Because:

1st highest → OFFSET 0
2nd highest → OFFSET 1
3rd highest → OFFSET 2
...
10th highest → OFFSET 9

Interview takeaway
2nd/3rd highest → nested MAX() is okay for a simple interview question

Nth highest → DENSE_RANK() / LIMIT + OFFSET

Need to handle duplicate salaries properly → DENSE_RANK()

And yes, your instinct is correct: don't build a query with 10 nested MAX() calls just because someone asked for the 10th highest.

note: LIMIT + OFFSET → simple positional selection
DENSE_RANK()   → actual ranking, especially with duplicates

MYSQL GROUP BY + HAVING
======================================================================

DEFINITION:
GROUP BY → groups rows with same values → apply aggregate per group  
HAVING   → filters grouped results (after GROUP BY)

GROUP BY is used to divide data into groups so aggregate functions can be
 applied to each group separately.

======================================================================
BASIC SYNTAX
======================================================================
SELECT column, AGG_FUNCTION(column)
FROM table
GROUP BY column;

======================================================================
BASIC EXAMPLE
======================================================================
SELECT city, COUNT(*)
FROM student
GROUP BY city;

→ count students per city

======================================================================
WHY GROUP BY
======================================================================
• Aggregation per category (city, dept, etc.)
• Data summarization (COUNT, SUM, AVG...)

======================================================================
MULTIPLE COLUMNS
======================================================================
SELECT city, age, COUNT(*)
FROM student
GROUP BY city, age;

→ grouping by combination (city + age)

======================================================================
COMMON AGGREGATIONS
======================================================================
SELECT city, AVG(age) FROM student GROUP BY city;
SELECT city, SUM(age) FROM student GROUP BY city;
SELECT city, MIN(age) FROM student GROUP BY city;
SELECT city, MAX(age) FROM student GROUP BY city;

======================================================================
GROUP BY + WHERE (ROW FILTER)
======================================================================
SELECT city, COUNT(*)
FROM student
WHERE age > 20
GROUP BY city;

→ WHERE filters rows BEFORE grouping

======================================================================
HAVING (GROUP FILTER)
======================================================================
SELECT city, COUNT(*)
FROM student
GROUP BY city
HAVING COUNT(*) > 2;

→ filters groups AFTER grouping

----------------------------------------------------------------------
HAVING WITH MULTIPLE CONDITIONS
----------------------------------------------------------------------
SELECT city, AVG(age) AS avg_age
FROM student
GROUP BY city
HAVING AVG(age) > 20 AND COUNT(*) >= 2;

----------------------------------------------------------------------
HAVING WITHOUT GROUP BY
----------------------------------------------------------------------
SELECT COUNT(*) 
FROM student
HAVING COUNT(*) > 5;

→ entire table treated as one group

======================================================================
WHERE vs HAVING
======================================================================
WHERE  → row-level filter (before GROUP BY)
HAVING → group-level filter (after GROUP BY)

----------------------------------------------------------------------
COMBINED FLOW
----------------------------------------------------------------------
SELECT city, COUNT(*)
FROM student
WHERE age > 20
GROUP BY city
HAVING COUNT(*) > 2;

======================================================================
GROUP BY + ORDER BY
======================================================================
SELECT city, COUNT(*) AS total
FROM student
GROUP BY city
ORDER BY total DESC;

→ sort grouped result

======================================================================
IMPORTANT RULE
======================================================================
Selected columns must be:
✔ in GROUP BY
OR
✔ used with aggregate

❌ WRONG:
SELECT city, age FROM student GROUP BY city;

✔ CORRECT:
SELECT city, COUNT(*) FROM student GROUP BY city;

======================================================================
GROUP BY vs DISTINCT (DISTINCT returns only unique values by removing duplicates.)
======================================================================
SELECT DISTINCT city FROM student;

≈

SELECT city FROM student GROUP BY city;

======================================================================
EXAMPLES (EMPLOYEES)
======================================================================
TABLE: employees(id, name, department, salary)

----------------------------------------------------------------------
UNIQUE DEPARTMENTS
----------------------------------------------------------------------
SELECT department FROM employees GROUP BY department;

note:  GROUP BY itself already gives you one result row per unique group, so goving unique even without distinct.
----------------------------------------------------------------------
COUNT PER DEPARTMENT
----------------------------------------------------------------------
SELECT department, COUNT(*) AS total_emps
FROM employees
GROUP BY department;

----------------------------------------------------------------------
SUM PER DEPARTMENT
----------------------------------------------------------------------
SELECT department, SUM(salary) AS total_salary
FROM employees
GROUP BY department;

----------------------------------------------------------------------
FULL AGGREGATION
----------------------------------------------------------------------
SELECT 
  department,
  COUNT(*)    AS total_emps,
  SUM(salary) AS total_salary,
  AVG(salary) AS avg_salary,
  MIN(salary) AS min_salary,
  MAX(salary) AS max_salary
FROM employees
GROUP BY department;

======================================================================
ADVANCED CASES
======================================================================
----------------------------------------------------------------------
GROUP BY WITH EXPRESSIONS
----------------------------------------------------------------------
SELECT YEAR(order_date), COUNT(*)
FROM orders
GROUP BY YEAR(order_date);

----------------------------------------------------------------------
GROUP BY WITH JOIN
----------------------------------------------------------------------
SELECT s.city, COUNT(o.id)
FROM student s
JOIN orders o ON s.id = o.student_id
GROUP BY s.city;

----------------------------------------------------------------------
NULL BEHAVIOR
----------------------------------------------------------------------
• NULL forms its own group
• Aggregates ignore NULL (except COUNT(*))

----------------------------------------------------------------------
NO ROWS
----------------------------------------------------------------------
→ returns EMPTY result

======================================================================
EXECUTION ORDER
======================================================================
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

======================================================================
COMMON MISTAKES
======================================================================
❌ Missing GROUP BY column
❌ Using WHERE instead of HAVING for aggregates
❌ Expecting row-level data after grouping
❌ Confusing DISTINCT with GROUP BY

======================================================================
PERFORMANCE
======================================================================
• Can be slow on large data
• Use indexes on grouped columns

======================================================================
FINAL NOTES
======================================================================
1) GROUP BY → core for analytics/reporting
2) HAVING → always used for aggregate filtering
3) WHERE + GROUP BY + HAVING often used together
4) Produces one row per group

MYSQL DATE, DATETIME & TIMESTAMP
======================================================================

======================================================================
1) DATE DATA TYPE
======================================================================

DEFINITION:
DATE → stores only date (no time)

FORMAT:
'YYYY-MM-DD'   ✔ correct  
'10-01-2024'   ❌ wrong  
'2024/01/10'   ❌ unreliable  

----------------------------------------------------------------------
CREATE / INSERT
----------------------------------------------------------------------
CREATE TABLE orders (
  id INT AUTO_INCREMENT PRIMARY KEY,
  order_date DATE
);

INSERT INTO orders (order_date)
VALUES ('2024-01-10'), 
      ('2024-02-15');
 
----------------------------------------------------------------------
COMPARISON
----------------------------------------------------------------------
SELECT * FROM orders
WHERE order_date > '2024-02-01';

→ compared chronologically

----------------------------------------------------------------------
RANGE
----------------------------------------------------------------------
'1000-01-01' → '9999-12-31'

----------------------------------------------------------------------
COMMON FUNCTIONS
----------------------------------------------------------------------

CURDATE()  
SELECT CURDATE();                      → current date

NOW()  
SELECT NOW();                          → date + time

DATE()  
SELECT DATE('2024-03-20 10:30:00');    → extract date

YEAR / MONTH / DAY  
SELECT YEAR(order_date) FROM orders;

----------------------------------------------------------------------
DATEDIFF / TIMEDIFF
----------------------------------------------------------------------

DATEDIFF (days only)
SELECT DATEDIFF('2024-03-20','2024-03-10'); → 10
If first date is earlier → result is negative

TIMEDIFF (time only)
SELECT TIMEDIFF('10:30:00','08:15:00');     → 02:15:00

• DATEDIFF → returns number  
• TIMEDIFF → returns HH:MM:SS  
• TIME range → -838:59:59 to 838:59:59

----------------------------------------------------------------------
DATE MANIPULATION ...ADDDATE/SUBDATE..> ADDDATE('DATE', INTERVAL _ DAY);
----------------------------------------------------------------------

ADDDATE  
SELECT ADDDATE('2024-03-20', INTERVAL 5 DAY); → 2024-03-25

SUBDATE  
SELECT SUBDATE('2024-03-20', INTERVAL 5 DAY); → 2024-03-15

----------------------------------------------------------------------
FORMAT / CONVERSION
----------------------------------------------------------------------

STR_TO_DATE  → Converts a STRING into a DATE/DATETIME value using the specified format.

SELECT STR_TO_DATE('20-03-2024','%d-%m-%Y');
→ 2024-03-20


DATE_FORMAT  → Converts/formats a DATE/DATETIME value into a STRING in the specified format.
SELECT DATE_FORMAT('2024-03-20','%d-%m-%Y');   SELECT DATE_FORMAT('2024-03-20','%d-%m-%Y');
→ '20-03-2024'


SELECT DATE_FORMAT('2024-03-20 10:30:45','%d-%m-%Y %H:%i:%s');
→ '20-03-2024 10:30:45'

%d → day (01–31)
%m → month (01–12)
%Y → 4-digit year
%H → hour (00–23)
%i → minutes
%s → seconds
----------------------------------------------------------------------
IMPORTANT RULES
----------------------------------------------------------------------
1) Always use quotes 'YYYY-MM-DD'
2) Stored & compared as DATE (not string)
3) Use functions for extraction/manipulation

----------------------------------------------------------------------
EDGE CASES
----------------------------------------------------------------------
• Invalid date      → '2024-02-30' ❌  
• No quotes         → treated as math ❌  
• NULL allowed      → ignored in comparisons  
• DATE vs DATETIME  → time affects comparison  
• No timezone effect (DATE only)
======================================================================
1) DATE
======================================================================

DEFINITION:

Stores date only.

FORMAT:

'YYYY-MM-DD'

EXAMPLE:

'2024-03-20'

KEY POINTS:

• Stores only date — no time.
• No timezone conversion.

Example:

CREATE TABLE events (
    event_date DATE
);


======================================================================
2) DATETIME
======================================================================

DEFINITION:

Stores date + time.

FORMAT:

'YYYY-MM-DD HH:MM:SS'

EXAMPLE:

'2024-03-20 10:30:45'

KEY POINTS:

• Stored as given — no timezone conversion.
• Larger range than TIMESTAMP.
• No auto-update by default.
• Can use DEFAULT CURRENT_TIMESTAMP.
• Can use ON UPDATE CURRENT_TIMESTAMP.

----------------------------------------------------------------------

CREATE TABLE

----------------------------------------------------------------------

CREATE TABLE events (
    id INT AUTO_INCREMENT PRIMARY KEY,
    event_time DATETIME
);

----------------------------------------------------------------------

DEFAULT CURRENT_TIMESTAMP

----------------------------------------------------------------------

CREATE TABLE events (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

→ Automatically sets current date + time when row is INSERTED.

----------------------------------------------------------------------

AUTO UPDATE

----------------------------------------------------------------------

CREATE TABLE events (
    id INT AUTO_INCREMENT PRIMARY KEY,
    updated_at DATETIME
        DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP
);

→ Sets current date + time when inserted.
→ Automatically changes when the row is updated.

----------------------------------------------------------------------

IMPORTANT

----------------------------------------------------------------------

DEFAULT CURRENT_TIMESTAMP
→ Runs when the row is INSERTED.

ON UPDATE CURRENT_TIMESTAMP
→ Runs when the row is UPDATED.

----------------------------------------------------------------------

COMMON USE

----------------------------------------------------------------------

DATETIME is useful when you want to store a date/time value
without MySQL timezone conversion.

Example:

event_start = '2026-10-15 18:30:00'


======================================================================
3) TIMESTAMP
======================================================================

DEFINITION:

Stores date + time and converts between the stored UTC value
and the current MySQL session time zone when retrieved/displayed.

FORMAT:

'YYYY-MM-DD HH:MM:SS'

----------------------------------------------------------------------

CREATE TABLE

----------------------------------------------------------------------

CREATE TABLE orders (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP
);

----------------------------------------------------------------------

DEFAULT CURRENT_TIMESTAMP
----------------------------------------------------------------------

CREATE TABLE orders (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

→ Automatically stores the current date + time when inserted.

----------------------------------------------------------------------

AUTO UPDATE
----------------------------------------------------------------------

CREATE TABLE orders (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP
);

→ updated_at automatically changes when the row is updated.

----------------------------------------------------------------------

REAL-WORLD EXAMPLE
----------------------------------------------------------------------

CREATE TABLE user_logins (
    login_id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT,
    login_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    logout_time TIMESTAMP
);

→ Useful for tracking events such as:
   created_at, updated_at, login_time, etc.

----------------------------------------------------------------------

COMMON FUNCTIONS
----------------------------------------------------------------------

SELECT NOW();

SELECT CURRENT_TIMESTAMP;

→ Both return the current date + time.

NOTE:

NOW() / CURRENT_TIMESTAMP
→ Get the current date + time.

DATETIME / TIMESTAMP
→ Data types used to store date + time.

----------------------------------------------------------------------

EXTRACT
----------------------------------------------------------------------

SELECT YEAR(created_at) FROM orders;

SELECT MONTH(created_at) FROM orders;

SELECT DAY(created_at) FROM orders;

SELECT HOUR(created_at) FROM orders;

→ Extracts individual parts from a date/time value.

----------------------------------------------------------------------

COMPARISON
----------------------------------------------------------------------

SELECT *
FROM orders
WHERE created_at > '2024-03-01 00:00:00';

→ Finds records after the specified date/time.

----------------------------------------------------------------------

RANGE
----------------------------------------------------------------------

TIMESTAMP:

'1970-01-01 00:00:01'
→
'2038-01-19 03:14:07'

DATETIME:

'1000-01-01 00:00:00'
→
'9999-12-31 23:59:59'

----------------------------------------------------------------------

UTC
----------------------------------------------------------------------

UTC (Coordinated Universal Time)
→ Standard time reference used worldwide.

Simple meaning:
→ Base/reference time from which time zones are calculated.


======================================================================
TIMESTAMP vs DATETIME
======================================================================

TIMESTAMP:

• Date + time
• Timezone conversion by MySQL
• Smaller range
• Supports DEFAULT CURRENT_TIMESTAMP
• Supports ON UPDATE CURRENT_TIMESTAMP
• Common for created_at / updated_at

DATETIME:

• Date + time
• No timezone conversion
• Much larger range
• Supports DEFAULT CURRENT_TIMESTAMP
• Supports ON UPDATE CURRENT_TIMESTAMP
• Useful when the stored date/time should remain exactly as specified


======================================================================
EDGE CASES
======================================================================

• TIMESTAMP display depends on MySQL session time zone.
• TIMESTAMP has a smaller supported range.
• DATETIME does not automatically convert between time zones.
• DEFAULT CURRENT_TIMESTAMP must be explicitly defined if desired.
• ON UPDATE CURRENT_TIMESTAMP must be explicitly defined if desired.
• Invalid date/time values can cause errors depending on MySQL
  SQL mode.


======================================================================
FINAL NOTES
======================================================================

1) DATE
   → Date only.

2) DATETIME
   → Date + time, no timezone conversion.

3) TIMESTAMP
   → Date + time with MySQL timezone conversion.

4) TIMESTAMP
   → Common for created_at / updated_at and tracking events.

5) DATETIME
   → Useful when you need a larger date range or want the value
     stored/retrieved without MySQL timezone conversion.

6) NOW()
   → Function that returns current date + time.

7) DEFAULT CURRENT_TIMESTAMP
   → Automatically sets current date + time on INSERT.

8) ON UPDATE CURRENT_TIMESTAMP
   → Automatically updates date + time when the row is UPDATEd.
