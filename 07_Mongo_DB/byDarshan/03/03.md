23. AGGREGATION PIPELINE
======================================================================

WHAT IS AGGREGATION?
An aggregation pipeline in MongoDB is a sequence of stages where documents pass through multiple processing steps to filter, transform, group, sort, and analyze data. Each stage takes the output of the previous stage as its input and passes its result to the next stage.
The pipeline is provided as an array of stages to the aggregate() method.

- Process documents in stages
- Similar to SQL GROUP BY
- Computes results, not just fetches data

WHY USE IT?

✔ Reports
✔ Analytics
✔ Grouping
✔ Totals
✔ Averages
✔ Data Transformation

Syntax

db.collection.aggregate([
  { stage1 },
  { stage2 }
])

Pipeline Flow

Documents
   ↓
$match
   ↓
$group
   ↓
$project
   ↓
Result


real cases:
How much money did we make from completed orders?
Aggregation:

db.orders.aggregate([
  { $match: { status: "completed" } },
  { $group: { _id: null, totalRevenue: { $sum: "$amount" } } }
])
-----
db.employees.aggregate([
  {
    $group: {
      _id: null,
      averageSalary: { $avg: "$salary" }
    }
  }
])

----
Question:

Which products sold the most?

You can:

orders
 ↓
$unwind
 ↓
$group
 ↓
$sum
 ↓
$sort
 ↓
$limit

This is a very common real-world aggregation use case.

26. AGGREGATION ACCUMULATORS
======================================================================

Used mainly inside $group.

----------------------------------------------------------------------

$sum

Interview:
Adds numeric values from documents in each group.

{
  $sum: "$marks"
}

Count documents:

Interview:
$sum: 1 counts how many documents are present in each group.

{
  $sum: 1
}

----------------------------------------------------------------------

$avg

Interview:
Calculates the average of numeric values in each group.

{
  $avg: "$marks"
}

----------------------------------------------------------------------

$min

Interview:
Returns the smallest value found in  group.

{
  $min: "$marks"
}

----------------------------------------------------------------------

$max

Interview:
Returns the largest value found in each group.

{
  $max: "$marks"
}

----------------------------------------------------------------------

$first

Interview:
Returns the value from the first document encountered in each group.

{
  $first: "$name"
}

Important:
"First" depends on the document order reaching $group.
If you need a meaningful first value, usually use $sort before $group.

----------------------------------------------------------------------

$last

Interview:
Returns the value from the last document encountered in each group.

{
  $last: "$name"
}

Important:
"Last" depends on the document order reaching $group.
If you need a meaningful last value, usually use $sort before $group.

----------------------------------------------------------------------

$push

Interview:
Collects values from all documents in each group and stores them in an array.

{
  $push: "$name"
}

Example result:

{
  _id: "Bangalore",
  names: ["Ajay", "Rahul", "Priya"]
}

----------------------------------------------------------------------

EASY MEMORY

$sum   → total
$avg   → average
$min   → smallest
$max   → largest
$first → first
$last  → last
$push  → collect into array

      }
    }
  }

----------------------------------------------------------------------

Total students by course

db.students.aggregate([
  {
    $group:{
      _id:"$course",
      totalStudents:{
        $sum:1
      }
    }
  }
])

why not $count?

Because $count answers:

"How many documents reached this stage?"

But $group needs to answer:

"How many documents are in EACH group?"

Suppose:

Ajay   → Java
Rahul  → Java
Priya  → MongoDB
Neha   → MongoDB
Raj    → MongoDB

$group first creates:

Java
 ├── Ajay
 └── Rahul

MongoDB
 ├── Priya
 ├── Neha
 └── Raj

Then:

$sum: 1

counts the documents inside each group:

Java    → 2
MongoDB → 3
could $count be used after $group?

Not for this purpose.

If you do:

db.students.aggregate([
  {
    $group: {
      _id: "$course"
    }
  },
  {
    $count: "totalCourses"
  }
])

you get:

{ totalCourses: 2 }

That's counting the number of groups/courses, not the number of students in each course.

⭐ interview answer

We use $sum: 1 here because we need a count for each $group. $count is a pipeline stage that produces one overall count of the documents reaching that stage, whereas $sum: 1 can count documents within each group.

# $sum vs $count is a very common MongoDB interview area, especially because $sum: 1 can look like counting.

1. $sum — what is it?

$sum is an accumulator used to calculate the total of numeric values, or to count documents when used as $sum: 1.

Case 1: add a numeric field

Suppose:

{ name: "A", amount: 100 }
{ name: "B", amount: 200 }
{ name: "C", amount: 300 }
{
  $group: {
    _id: null,
    totalAmount: { $sum: "$amount" }
  }
}

Result:

{ _id: null, totalAmount: 600 }

Because:

100 + 200 + 300 = 600
Case 2: count documents using $sum: 1
{
  $group: {
    _id: null,
    totalOrders: { $sum: 1 }
  }
}

Result:

{ _id: null, totalOrders: 3 }

Why?

Each document contributes 1:

document 1 → 1
document 2 → 1
document 3 → 1
               ─
               3

So:

$sum: 1 means count each document that reaches the $group stage.

2. $count — what is it?

$count is an aggregation pipeline stage used specifically to count the number of documents which reach that point in the pipeline.

db.orders.aggregate([
  { $count: "totalOrders" }
])

Result:

{ totalOrders: 3 }

Think:

$count → "how many documents are there?"
⭐ Biggest interview difference

This is the question interviewers love:

$sum: 1 vs $count

They can both count documents, but they are used differently.

$sum: 1

Usually used inside $group:

{
  $group: {
    _id: "$city",
    count: { $sum: 1 }
  }
}

This gives:

Bangalore → 5
Mumbai    → 3
Delhi     → 7

You're saying:

Group by city and count documents in each group.

$count

Used as its own pipeline stage:

{
  $count: "totalStudents"
}

It gives one overall count of documents reaching that stage.

3. Very important: $count can also count after $match

Example:

db.orders.aggregate([
  { $match: { status: "completed" } },
  { $count: "completedOrders" }
])

Pipeline:

all orders
    ↓
$match
    ↓
completed orders
    ↓
$count
    ↓
number of completed orders

If there are 25 completed orders:

{ completedOrders: 25 }
4. $sum: "$amount" vs $sum: 1

This is another very common interview question.

$sum: "$amount"
total: { $sum: "$amount" }

means:

Add the values stored in the amount field.

Example:

100
200
300

Result:

600
$sum: 1
count: { $sum: 1 }

means:

Add 1 for every document.

Example:

document → 1
document → 1
document → 1

Result:

3

So:

$sum: "$amount" → calculate total amount

$sum: 1         → count documents
5. What if we group?

This is where $sum: 1 becomes extremely useful.

Suppose:

{ name: "A", city: "Bangalore" }
{ name: "B", city: "Bangalore" }
{ name: "C", city: "Mumbai" }
{ name: "D", city: "Mumbai" }
{ name: "E", city: "Mumbai" }

Query:

db.students.aggregate([
  {
    $group: {
      _id: "$city",
      studentCount: { $sum: 1 }
    }
  }
])

Result:

{ _id: "Bangalore", studentCount: 2 }
{ _id: "Mumbai", studentCount: 3 }

Why?

$group first creates groups:

Bangalore
  ├── A
  └── B

Mumbai
  ├── C
  ├── D
  └── E

Then:

Bangalore → 1 + 1 = 2

Mumbai → 1 + 1 + 1 = 3
6. $count cannot do what $sum does

Suppose you want:

total revenue per city.

You need:

db.orders.aggregate([
  {
    $group: {
      _id: "$city",
      totalRevenue: { $sum: "$amount" }
    }
  }
])

You cannot use:

$count: "$amount"

because $count is not saying "add the values of this field."

It's saying:

count how many documents reached this stage.

So:

$count → count documents

$sum   → add values / calculate totals
7. Another important interview question
"Can $sum count?"

Yes.

Using:

$sum: 1
"Can $count calculate a total?"

No.

For example, if:

amount = 100
amount = 200
amount = 300

$count gives:

3

while:

$sum: "$amount"

gives:

600
8. $count stage vs $sum accumulator

This wording is important for interviews.

$count

Stage

{ $count: "total" }

It appears directly in the pipeline:

db.orders.aggregate([
  { $match: {...} },
  { $count: "total" }
])
$sum

Accumulator/operator used within stages such as $group

{
  $group: {
    _id: "$city",
    total: { $sum: "$amount" }
  }
}

So don't confuse:

$count → pipeline stage

$sum   → accumulator/expression used for calculation
9. Interview scenarios — what would you choose?
Requirement	Use
Count all documents	$count
Count documents after $match	$count
Count documents within each group	$sum: 1
Total of a numeric field	$sum: "$field"
Revenue per customer	$sum: "$amount"
Number of orders per customer	$sum: 1
Number of students per city	$sum: 1
Total sales	$sum: "$amount"
Count completed orders	$match + $count
Count completed orders per customer	$match + $group + $sum: 1
⭐ Interview questions to practice
Q1. What is the difference between $sum: 1 and $count?

$sum: 1 is normally used inside $group to count documents within each group, while $count is a pipeline stage that counts all documents reaching that stage.

Q2. What does $sum: "$amount" do?

It adds the numeric values from the amount field across the documents being processed.

Q3. Why does $sum: 1 count documents?

Because each document contributes a value of 1 to the sum, so the final sum represents the number of documents.

Q4. Can $count calculate total revenue?

No. $count only counts documents. For total revenue, we use $sum: "$amount".

Q5. How do you count documents by category?
db.products.aggregate([
  {
    $group: {
      _id: "$category",
      count: { $sum: 1 }
    }
  }
])
Q6. How do you get the total number of documents?
db.products.aggregate([
  { $count: "totalProducts" }
])
Q7. How do you count only completed orders?
db.orders.aggregate([
  { $match: { status: "completed" } },
  { $count: "completedOrders" }
])
Q8. How do you calculate completed-order revenue?
db.orders.aggregate([
  { $match: { status: "completed" } },
  {
    $group: {
      _id: null,
      totalRevenue: { $sum: "$amount" }
    }
  }
])
