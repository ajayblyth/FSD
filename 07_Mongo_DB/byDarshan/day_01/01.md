3A. OBJECTID
----------------------------------------------------------------------

ObjectId = Default type used for _id field.

Characteristics

- Automatically generated if _id is omitted
- 12-byte unique identifier
- Globally unique
- Indexed by default

Example

{
  _id: ObjectId("686f4a...")
}

Benefits

- Unique identification
- Fast lookups
- Suitable for distributed systems

IMPORTANT

Every document must have an _id field.
MongoDB creates ObjectId automatically if not provided.

10. UPSERT
----------------------------------------------------------------------

UPSERT = UPDATE + INSERT

+-------------------+----------------------+
| Condition         | Action               |
+-------------------+----------------------+
| Match Found       | Update Document      |
| No Match Found    | Insert Document      |
+-------------------+----------------------+

Syntax

db.collection.updateOne(
  filter,
  update,
  { upsert: true }
)

Example

db.employees.updateOne(
  { name: "Rohit" },
  { $set: { age: 30 } },
  { upsert: true }
)

CASE 1 : Rohit Exists

Before                    After
------------------------  ------------------------
{name:"Rohit",age:25}  -> {name:"Rohit",age:30}

Result

+----------------+-------+
| Field          | Value |
+----------------+-------+
| modifiedCount  | 1     |
| upsertedCount  | 0     |
+----------------+-------+

CASE 2 : Rohit Doesn't Exist

Created Document

{
  _id: ObjectId(...),
  name: "Rohit",
  age: 30
}

Result

+----------------+----------------+
| Field          | Value          |
+----------------+----------------+
| modifiedCount  | 0              |
| upsertedCount  | 1              |
| upsertedId     | ObjectId(...)  |
+----------------+----------------+

Document Creation Logic

Filter : {name:"Rohit"}
Update : {$set:{age:30}}

Generated Document

{
  name: "Rohit",
  age: 30
}

DOUBT: Why Sometimes We Use a Filter First and Sometimes {} ?
======================================================================

UPDATE SYNTAX

db.collection.updateMany(
  filter,
  update
)

----------------------------------------------------------------------

CASE 1 : Use a Filter

Example

db.employees.updateMany(
  { role: "Dev" },
  { $set: { dept: "Tech" } }
)

Meaning

Step 1:
Find employees where role = "Dev"

Step 2:
Update only those employees

Result

Dev      → dept = Tech
Manager  → unchanged
HR       → unchanged

----------------------------------------------------------------------

WHEN TO USE A FILTER?

Use a filter when only specific documents should be updated.

Examples

{ role: "Dev" }

{ city: "Delhi" }

{ salary: { $gt: 50000 } }

======================================================================

CASE 2 : Use {}

Example

db.employees.updateMany(
  {},
  [
    {
      $set: {
        mature: {
          $cond: {
            if: { $gt: ["$age", 30] },
            then: 1,
            else: 0
          }
        }
      }
    }
  ]
)

Meaning

Step 1:
Process EVERY employee

Step 2:
For each employee check

age > 30 ?

YES → mature = 1

NO  → mature = 0

----------------------------------------------------------------------

Why Not Use Filter Here?

If we use:

db.employees.updateMany(
  { age: { $gt: 30 } },
  { $set: { mature: 1 } }
)

Result

Age 35 → mature = 1
Age 40 → mature = 1
Age 25 → unchanged
Age 28 → unchanged

Problem

Employees with age <= 30 never get mature = 0

----------------------------------------------------------------------

Using {}

db.employees.updateMany(
  {},
  [ ... ]
)

Result

Age 35 → mature = 1
Age 40 → mature = 1
Age 25 → mature = 0
Age 28 → mature = 0

Every document is processed.

======================================================================

QUICK RULE
======================================================================

Use Filter
-----------
When only SOME documents need updating.

Examples

{ role: "Dev" }

{ city: "Delhi" }

{ age: { $gt: 30 } }

----------------------------------------------------------------------

Use {}
------
When EVERY document should be processed and the value
depends on a condition.

Examples

mature = age > 30 ? 1 : 0

grade = marks >= 80 ? "PASS" : "FAIL"

status = salary > 50000 ? "HIGH" : "LOW"

======================================================================

INTERVIEW ONE-LINER
======================================================================

Filter
→ Decides WHICH documents are updated.

$cond
→ Decides WHAT value each document gets.
