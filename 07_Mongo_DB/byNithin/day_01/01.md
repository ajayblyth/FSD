==================== MONGODB (QUICK NOTES) ====================

1. WHAT IS MONGODB

MongoDB is a NoSQL, document-oriented database  
stores data in the form of JSON-like BSON documents instead of rows and tables. 
Documents are stored inside collections.

MongoDB provides features like flexible schema, embedded documents, indexing, aggregation, replication, sharding, and transaction support.

Q: What are the main features of MongoDB?

Answer:

Document-oriented – stores data as BSON documents.
Flexible schema – documents in the same collection can have different structures.
Embedded documents – supports nested objects and arrays.
Indexing – improves query performance.
Aggregation – allows complex data processing and reporting.
Replication – provides high availability using replica sets.
Sharding – supports horizontal scaling by distributing data across servers.
Transactions – supports ACID transactions for operations involving multiple documents.
Atomic operations – useful for operations like updating ticket inventory safely.
Powerful queries – supports filtering, sorting, updating, and complex queries.

Q: Why did you choose MongoDB for EventHub?

Both MongoDB and MySQL support indexing, transactions, atomic operations, and scalability. The main reason we chose MongoDB for EventHub is its document-oriented and flexible data model. Our application has nested structures such as ticket tiers, location, preferences, and booking ticket snapshots, which can be represented naturally as embedded documents and arrays in MongoDB. In MySQL, these structures would typically require additional tables and relationships, or JSON columns.

MONGODB INSERT OPERATIONS
-------------------------

1. insertOne()
---------------
db.<collection>.insertOne({
  key1: value1,
  key2: value2
});

Example:
db.users.insertOne({
  name: "Ajay",
  age: 25,
  active: true
});


2. insertMany()
----------------
db.<collection>.insertMany([
  { key1: value1 },
  { key1: value2 },
  { key1: value3 }
]);

Example:
db.users.insertMany([
  { name: "Ajay", age: 25 },
  { name: "Ravi", age: 28 },
  { name: "Neha", age: 23 }
]);

db .< collection>.find()
Query all documents

db .< collection>.updateOne()
Update a document

db .< collection>.deleteOne()
Delete a document

exit
Exit the shell

- mongod  → server
- mongosh → shell (client)
- Compass → GUI (easy to use)

==================== COLLECTION vs DOCUMENT ====================

1. COLLECTION
---------------------------------------------------------------
- A collection = group of documents
- Similar to "table" in SQL
- No fixed schema (documents can differ)

Example:
users (collection)
  → many user documents inside

---------------------------------------------------------------

2. DOCUMENT
---------------------------------------------------------------
- A document = single record (data)
- Stored in JSON/BSON format
- Similar to "row" in SQL

Example:
{
  name: "Ajay",
  age: 22,
  skills: ["Java", "Node"]
}

---------------------------------------------------------------

3. RELATION (VERY IMPORTANT)
---------------------------------------------------------------
Database
  → Collection
      → Document
          → Fields (key-value pairs)

---------------------------------------------------------------

4. EXAMPLE
---------------------------------------------------------------
Collection: users

Document 1:
{
  name: "Ajay",
  age: 22
}

Document 2:
{
  name: "Rahul",
  age: 25,
  city: "Bangalore"
}

👉 Notice:
- Different structure allowed (flexible schema)

==================== SQL vs MONGODB (MAPPING + NOTES) ====================

1. CORE MAPPING
---------------------------------------------------------------------------
SQL (RDBMS)        | MongoDB (NoSQL)        | DESCRIPTION
-------------------|------------------------|------------------------------
Database           | Database               | Top-level container
Table              | Collection             | Group of related data
Row / Record       | Document               | Single entry of data
Column             | Field                  | Property / attribute
Primary Key        | _id                    | Unique identifier
JOIN               | Embedded Doc / $lookup | Linking related data

---------------------------------------------------------------------------

2. DATA REPRESENTATION
---------------------------------------------------------------------------

SQL TABLE (FIXED STRUCTURE)
---------------------------------------------------------------------------
+----+--------+-----+-----------+
| id | name   | age | city      |
+----+--------+-----+-----------+
| 1  | Ajay   | 22  | Bangalore |
| 2  | Rahul  | 25  | Delhi     |
+----+--------+-----+-----------+

👉 Same columns for every row (strict schema)

---------------------------------------------------------------------------

MONGODB COLLECTION (FLEXIBLE DOCUMENTS)
---------------------------------------------------------------------------
{
  _id: 1, //generated by mongodb automatically for entries
  name: "Ajay",
  age: 22,
  city: "Bangalore"
}

{
  _id: 2,
  name: "Rahul",
  age: 25
}

👉 Fields can vary (flexible schema)

---------------------------------------------------------------------------

3. RELATION HANDLING
---------------------------------------------------------------------------

SQL (USING JOIN)
---------------------------------------------------------------------------
users table + orders table → JOIN needed

MongoDB (EMBEDDED DOCUMENT)
---------------------------------------------------------------------------
{
  name: "Ajay",
  orders: [
    { product: "Laptop", price: 70000 },
    { product: "Mouse", price: 500 }
  ]
}

👉 No JOIN needed (data stored together)

---------------------------------------------------------------------------

4. QUICK DIFFERENCE
---------------------------------------------------------------------------
SQL                        | MongoDB
---------------------------|-------------------------
Table (rows/columns)       | Collection (documents)
Strict schema              | Flexible schema
Joins for relations        | Embedded documents
Structured data            | Semi-structured data
