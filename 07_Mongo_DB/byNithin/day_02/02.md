JSON vs JAVASCRIPT OBJECT
------------------------

They look similar but have key differences

JavaScript Object              JSON
------------------             ------------------
name: "Alice",                 "name": "Alice",
age: 30,                       "age": 30,
active: true                   "active": true
}                              }

JS Object:
- Keys don’t need quotes
- Values can be functions
- Only exists in memory (runtime)

JSON:
- Keys MUST be in double quotes
- No functions allowed
- Used for storing & transferring data (text format)

Conversion:
-----------
JSON.stringify(obj)
→ JS Object → JSON string (for sending/storing)

JSON.parse(str)
→ JSON string → JS Object (for using in code)

👉 JSON = "shipping format"


--------------------------------------------------

JSON RULES
----------

1. Data is key-value pairs
   "name": "Ajay"

2. Keys must be in double quotes
   ❌ name: "Ajay"
   ✅ "name": "Ajay"

3. Strings must be in double quotes
   ❌ 'Ajay'
   ✅ "Ajay"

4. No trailing commas
   ❌ {"a":1,}
   ✅ {"a":1}

5. Supported data types:
   - string  → "text"
   - number  → 10, 3.5
   - boolean → true / false
   - null    → null
   - object  → {}
   - array   → []

6. Objects use {}
   {"id":1, "name":"Ajay"}

7. Arrays use []
   [1,2,3] or ["a","b"]

8. JSON is text format (not code)

9. Not allowed:
   ❌ functions
   ❌ undefined
   ❌ comments

10. Must be valid structure
    (no missing brackets)


--------------------------------------------------

BSON DATA TYPES
---------------

MongoDB stores data as BSON (Binary JSON)

String
"hello" → UTF-8 text

Integer
42 → 32-bit or 64-bit number

Double
3.14 → Floating point number

Boolean
true / false → Boolean value

Date
new Date() → Date & time (stored as ms since epoch)

ObjectId
new ObjectId() → Unique 12-byte document identifier

Array
[1, 2, 3] → List of values

Object
{ key: value } → Embedded / nested document

Null
null → Null value

Binary
BinData(0, "...") → Binary data (images, files)

👉 Every document automatically gets an _id field 
   of type ObjectId if not provided


--------------------------------------------------

BSON vs JSON (WHY BSON WINS)
----------------------------

BSON is MongoDB’s storage format

1. More Data Types
   JSON → string, number, boolean, array, object, null
   BSON → Date, ObjectId, Binary, Int32, Int64, Decimal128, etc.

2. Dates as Real Values
   JSON → "2024-01-01" (just string)
   BSON → new Date() (real timestamp, sortable)

3. Efficient Binary Storage
   BSON → binary (fast for DB engine)
   JSON → text (slower parsing)

4. Precise Numbers
   JSON → single number type
   BSON → Int32, Int64, Double, Decimal128 (no precision loss)

5. Unique IDs Built-in
   BSON → ObjectId (auto-generated unique ID)
   JSON → no native ID type

6. Supports Binary Data
   BSON → stores images/files directly
   JSON → needs Base64 encoding

👉 BSON = designed for machines  
👉 JSON = designed for humans  

MongoDB uses BSON internally but lets you work with JSON-like syntax

MONGODB QUERIES (FILTERING)
---------------------------

1. Find by Field
----------------
college> db.student.find({ city: "Delhi" })

→ Returns documents where city = Delhi

Example Output:
{
  _id: ObjectId("..."),
  name: "John",
  age: 21,
  city: "Delhi"
}


2. Greater Than ($gt)
---------------------
college> db.student.find({ marks: { $gt: 75 } })

→ Returns students with marks > 75

Example:
adam → marks: 88


3. Insert More Data
-------------------
college> db.student.insertMany([
  { name: "Akash", age: 18, marks: 65, city: "Bengaluru" },
  { name: "Madura", age: 21, city: "Mumbai" }
])

👉 Schema is flexible (fields can differ, but not recommended)


4. View All Data
----------------
college> db.student.find()

→ Shows all documents:
- adam
- bob
- John
- Akash
- Madura


5. $in Operator
---------------
college> db.student.find({
  city: { $in: ["Delhi", "Mumbai"] }
})

→ Matches any value in list

Output:
- John (Delhi)
- Madura (Mumbai)

---

college> db.student.find({
  city: { $in: ["Delhi", "Mumbai", "Hyderabad"] }
})

→ Hyderabad not present → ignored


6. $or Operator
---------------
college> db.student.find({
  $or: [
    { marks: { $gt: 50 } },
    { city: "Delhi" }
  ]
})

→ Condition:
marks > 50 OR city = Delhi

Returns:
- adam
- bob
- John
- Akash


7. $and Operator
----------------
college> db.student.find({
  $and: [
    { marks: { $gt: 50 } },
    { city: "Delhi" }
  ]
})

→ Condition:
marks > 50 AND city = Delhi

Returns:
- John only


❌ Wrong Syntax Example
----------------------
college> db.student.find({ : [ ... ] })
→ Invalid (missing operator like $and / $or)


KEY POINTS
----------
- find({}) → filter documents
- $gt → greater than
- $in → match multiple values
- $or → any condition true
- $and → all conditions must be true
------------------------------------------------------
MONGODB QUERY OPERATORS
-----------------------

COMPARISON
----------
$eq   → equal
$ne   → not equal
$gt   → greater than
$gte  → greater than or equal
$lt   → less than
$lte  → less than or equal
$in   → match values in array

Example:
db.student.find({ marks: { $gt: 75 } })
db.student.find({ city: { $in: ["Delhi","Mumbai"] } })


LOGICAL
-------
$and → both conditions true
$or  → any condition true
$nor → none should match
$not → condition should NOT match

Example:
db.student.find({ $or: [ {marks: {$gt: 50}}, {city: "Delhi"} ] })
db.student.find({ $and: [ {marks: {$gt: 50}}, {city: "Delhi"} ] })


EVALUATION
----------
$regex → pattern match
$text  → text search
$where → JS expression

Example:
db.student.find({ name: { $regex: "^A" } })


--------------------------------------------------

UPDATE OPERATIONS
-----------------

updateOne()
-----------
db.collection.updateOne(
  { filter },
  { $set: { ... } }
)

Example:
db.student.updateOne(
  { name: "John" },
  { $set: { age: 28, marks: 75 } }
)

Result:
acknowledged: true
matchedCount: 1
modifiedCount: 1


updateMany()
------------
db.collection.updateMany(
  { filter },
  { $set: { ... } }
)

→ updates ALL matching documents


replaceOne()
------------
db.collection.replaceOne(
  { filter },
  { newDocument }
)

→ replaces entire document


UPDATE OPERATORS
----------------
$set   → update/set field
$unset → remove field
$inc   → increment number
$push  → add to array
$pull  → remove from array


--------------------------------------------------

DATA AFTER UPDATE (example)
---------------------------
db.student.find()

John → age: 28, marks: 75 (updated)


--------------------------------------------------

NESTING (EMBEDDED DOCUMENT)
---------------------------
Example Document:
{
  name: "farah",
  performance: { marks: 88, grade: "A" }
}

Query:
db.student.findOne({ "performance.marks": 88 })


--------------------------------------------------

DELETE OPERATIONS
-----------------

deleteOne()
-----------
db.collection.deleteOne({ filter })

Example:
db.student.deleteOne({ state: "Haryana" })

Result:
{ acknowledged: true, deletedCount: 1 }


deleteMany()
------------
db.collection.deleteMany({ filter })


DROP DATABASE
-------------
db.dropDatabase()

→ deletes entire database


--------------------------------------------------

KEY POINTS
----------
- updateOne → first match only
- updateMany → all matches
- $set → most used update operator
- dot notation → access nested fields
- deleteOne / deleteMany → remove data

MONGOOSE (NODE + MONGODB)
-------------------------

WHAT IS MONGOOSE?
-----------------
- ODM (Object Data Modeling) library for MongoDB
- Works with Node.js
- Provides schema, validation, easy queries


INSTALLATION
------------
npm install mongoose


IMPORT
------
const mongoose = require("mongoose");


CONNECT TO DATABASE
-------------------
mongoose.connect("mongodb://127.0.0.1:27017/testDB")
  .then(() => console.log("Connected"))
  .catch(err => console.log(err));


SCHEMA
------
- Defines structure of documents

const userSchema = new mongoose.Schema({
  name: String,
  age: Number,
  email: String
});


MODEL
-----
- Represents collection

const User = mongoose.model("User", userSchema);


CREATE (INSERT)
---------------
const user = new User({
  name: "Ajay",
  age: 25,
  email: "ajay@gmail.com"
});

user.save();


READ (FIND)
-----------
User.find().then(data => console.log(data));

User.findOne({ name: "Ajay" });


UPDATE
------
User.updateOne(
  { name: "Ajay" },
  { $set: { age: 26 } }
);


DELETE
------
User.deleteOne({ name: "Ajay" });


KEY FEATURES
------------
- Schema-based structure
- Validation support
- Middleware (hooks)
- Easy CRUD operations
- Converts JS objects ↔ MongoDB documents


ONE LINE
--------
Mongoose = MongoDB + Schema + Easy JS API
