MONGOOSE + SCALING + MONGODB NOTES (ORGANISED)
----------------------------------------------


🔹 MONGOOSE (ODM FOR MONGODB)
----------------------------
Definition:
Mongoose is an elegant MongoDB object modeling library for Node.js that helps:
- Structure data with schemas
- Enforce validation
- Add middleware/hooks
- Build expressive queries

Official Note:
"Writing MongoDB validation, casting and business logic boilerplate is a drag.
That's why we wrote Mongoose."


BASIC EXAMPLE
-------------
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  name: String,
  email: String,
  password: String
});

const User = mongoose.model('User', userSchema);



---------------------------------
VERTICAL SCALING vs HORIZONTAL SCALING
-------------------------------------

VERTICAL SCALING (SCALE UP)
---------------------------
Definition:
Increase power of a single machine

How:
- Add more CPU
- Add more RAM
- Upgrade storage

Example:
- 8 GB RAM → 32 GB RAM

Pros:
- Simple
- No major code/architecture change

Cons:
- Limited scaling
- Single point of failure
- Expensive at high level


HORIZONTAL SCALING (SCALE OUT)
------------------------------
Definition:
Increase number of machines

How:
- Add more servers
- Distribute load using load balancer

Example:
- 1 server → 5 servers

Pros:
- Highly scalable
- Fault tolerant
- Handles high traffic

Cons:
- Complex system design
- Requires load balancing
- Needs distributed handling


KEY DIFFERENCE
--------------
Feature          Vertical Scaling     Horizontal Scaling
-------------------------------------------------------
Approach         One strong machine   Multiple machines
Limit            Limited              Almost unlimited
Complexity       Low                  High
Failure Risk     High                 Low
Cost (long run)  Expensive            More efficient


ANALOGY
-------
Vertical   → Upgrade bike to superbike
Horizontal → Add more bikes



----------------------------------------
MONGODB FLEXIBILITY vs NEED FOR STRUCTURE
----------------------------------------

🔹 MONGODB (SCHEMA-LESS DATABASE)
--------------------------------
Definition:
- Stores data as documents (JSON-like)
- No fixed schema required

Freedom:
- Different documents in same collection can have different fields
- Easy to evolve structure over time

Example:
{ name: "Ajay", age: 25 }
{ username: "Ravi", email: "ravi@mail.com", isAdmin: true }

✔ No restriction → very flexible


⚠ PROBLEM: TOO MUCH FREEDOM
---------------------------
Issues:
- Field naming mismatch
  { name: "Ajay" }
  { fullName: "Ajay" }

- Data type inconsistency
  { age: 25 }
  { age: "twenty five" }

- Missing required fields
  { name: "Ravi" }   // no email

- Extra unwanted fields
  { name: "A", randomField: "xyz" }

👉 Result:
- Hard to query
- Bugs in backend
- Data becomes messy/unreliable


🔹 WHY STRUCTURE IS STILL NEEDED
-------------------------------
- Applications expect consistent data
- Queries need predictable fields
- Validation ensures correctness

👉 Required:
✔ Defined structure
✔ Validation rules
✔ Controlled data format


🔹 MONGOOSE ROLE (SOLUTION)
--------------------------
Acts as a middle layer between app and MongoDB

Provides structured way to handle flexible data


🔹 WHAT MONGOOSE PROVIDES
------------------------

1. SCHEMA (STRUCTURE)
---------------------
Define document shape

Example:
{
  name: String,
  age: Number,
  email: String
}

✔ Ensures consistency


2. VALIDATION
-------------
Rules:
- required: true
- min / max
- enum
- match (regex)

✔ Prevents invalid data


3. DEFAULT VALUES
-----------------
Example:
createdAt: { type: Date, default: Date.now }

✔ Avoids missing fields


4. TYPE SAFETY
--------------
✔ Enforces correct data types
✔ Example: age must be number


5. MIDDLEWARE / HOOKS
---------------------
Run logic before/after operations

Examples:
- Hash password before save
- Logging

✔ Controls data flow


6. MODEL-BASED ACCESS
---------------------
✔ Use models instead of raw queries
✔ Cleaner, maintainable code


🔹 FINAL IDEA
------------
MongoDB → Flexibility (powerful but risky)  
Mongoose → Structure (safe and maintainable)  

👉 Balance:
Freedom + Rules = Scalable, clean backend

MONGOOSE + CREATE COLLECTION + SETUP (ORGANISED)
-----------------------------------------------


🔹 MONGOOSE OVERVIEW
-------------------
Mongoose = elegant MongoDB object modeling for Node.js

- Provides schema-based solution
- Adds structure on top of MongoDB
- Handles validation, casting, queries, hooks

Official idea:
"Writing MongoDB validation, casting and business logic boilerplate is a drag.
That's why we wrote Mongoose."

Version:
- 9.5.0


🔹 INSTALLATION
---------------
Requirement:
- MongoDB installed
- Node.js installed

Install:
npm install mongoose



🔹 BASIC CONNECTION
------------------
const mongoose = require('mongoose');

mongoose.connect('mongodb://127.0.0.1:27017/test');

👉 With auth:
await mongoose.connect('mongodb://user:password@127.0.0.1:27017/test');



🔹 COMPLETE STARTER EXAMPLE
--------------------------
const mongoose = require('mongoose');

main().catch(err => console.log(err));

async function main() {

  await mongoose.connect('mongodb://127.0.0.1:27017/test');

  const Cat = mongoose.model('Cat', { name: String });

  const kitty = new Cat({ name: 'Zildjian' });

  await kitty.save();

  console.log("meow");
}



🔹 SCHEMA
---------
Definition:
Schema defines the structure (shape) of documents in a collection

Example:
const userSchema = new mongoose.Schema({
  name: String,
  email: String,
  age: Number
});



🔹 MODEL
--------
Definition:
Model = compiled version of schema

Example:
const User = mongoose.model('User', userSchema);

👉 'User' → model  
👉 'users' → collection (auto-created, plural + lowercase)



🔹 COLLECTION CREATION (IMPORTANT)
---------------------------------
❗ In Mongoose:
- No need to manually create collection

✔ Collection is created automatically when:
- First document is inserted

Example:
const user = new User({
  name: "Ajay",
  email: "ajay@mail.com",
  age: 25
});

await user.save();

👉 This creates:
- Collection: users
- Document inserted



🔹 ALTERNATE INSERT (SHORTCUT)
-----------------------------
await User.create({
  name: "Ravi",
  email: "ravi@mail.com",
  age: 30
});

MONGODB MANUAL COLLECTION CREATION (RAW)
----------------------------------------

Syntax:
db.createCollection(name, options)

Example:
db.createCollection("users");


🔹 ADVANCED OPTIONS (OVERVIEW)
-----------------------------
db.createCollection("collectionName", {

  capped: <boolean>,

  timeseries: {
    timeField: <string>,
    metaField: <string>,
    granularity: <string>,
    bucketMaxSpanSeconds: <number>,
    bucketRoundingSeconds: <number>
  },

  expireAfterSeconds: <number>,
  clusteredIndex: <document>,
  changeStreamPreAndPostImages: <document>,

  size: <number>,
  max: <number>,

  storageEngine: <document>,
  validator: <document>,
  validationLevel: <string>,
  validationAction: <string>,

  indexOptionDefaults: <document>,

  viewOn: <string>,
  pipeline: <pipeline>,

  collation: <document>,
  writeConcern: <document>,

  encryptedFields: <document>
});


🔹 TIME SERIES COLLECTION EXAMPLE
--------------------------------
Create collection for weather data (24 hours):

db.createCollection("weather24h", {
  timeseries: {
    timeField: "timestamp",
    metaField: "data",
    granularity: "hours"
  },
  expireAfterSeconds: 86400
});


👉 Meaning:
- Stores time-based data
- Auto deletes after 24 hours (86400 sec)



🔹 KEY TAKEAWAY
--------------
Mongoose:
- You DON'T manually create collections
- Schema → Model → Insert → Collection auto-created

MongoDB (raw):
- You CAN manually create collections with options
- Useful for advanced control (time-series, capped, etc.)
MONGOOSE MODELS (ORGANISED NOTES)
--------------------------------


🔹 WHAT IS A MODEL
-----------------
- Model = class built from Schema
- Instance of model = Document

Responsibilities:
✔ Create, Read, Update, Delete (CRUD)
✔ Acts as interface between app and MongoDB


🔹 MODEL CREATION
----------------
const User = mongoose.model("User", userSchema);

👉 'User' = model name (singular)


🔹 COLLECTION NAMING (AUTO)
---------------------------
- Lowercase + pluralize

User     → users
Person   → people
Category → categories

👉 Can override:
mongoose.model("User", schema, "customName")


🔹 IMPORTANT NOTE
----------------
✔ .model() makes a COPY of schema
✔ Define fields/validations BEFORE creating model


--------------------------------------------------

🔹 DOCUMENT CREATION
--------------------

1) Using new + save()
const user = new User({ name: "Ajay" });
await user.save();

2) Using create()
await User.create({ name: "Ajay" });

3) Insert many
await User.insertMany([
  { name: "Ajay" },
  { name: "Rahul" }
]);


--------------------------------------------------

🔹 QUERYING (READ)
-----------------
- find()        → multiple docs
- findOne()     → first match
- findById()    → by _id

Example:
User.find({ age: { $gte: 18 } })
.then(data => console.log(data));

👉 Returns Query object (thenable, not real Promise)


--------------------------------------------------

🔹 UPDATE
---------
- updateOne()        → first match
- updateMany()       → all matches
- findOneAndUpdate() → update + return doc

Examples:
User.updateOne({ name: "Bruce" }, { age: 49 });

User.updateMany({ age: { $gt: 45 } }, { age: 45 });

User.findOneAndUpdate(
  { name: "Tony" },
  { age: 60 },
  { new: true }   // returns updated doc
);


--------------------------------------------------

🔹 DELETE
---------
- deleteOne()        → deletes one
- deleteMany()       → deletes many
- findByIdAndDelete()
- findOneAndDelete()

Example:
User.deleteOne({ name: "Adam" });
User.deleteMany({ age: { $gt: 40 } });

-------------------------
✔ Required before any DB operation

await mongoose.connect("mongodb://127.0.0.1/db");

Custom:
const conn = mongoose.createConnection("mongodb://127.0.0.1/test");

🔹 SCHEMA VALIDATIONS (RULES)
----------------------------

const bookSchema = new mongoose.Schema({
  title: {
    type: String,
    required: true           // must be present
  },
  author: {
    type: String
  },
  price: {
    type: Number,
    min: [1, "Price too low"] // minimum value
  },
  discount: {
    type: Number,
    default: 0               // default value
  },
  category: {
    type: String,
    enum: ["fiction", "non-fiction"] // allowed values
  },
  genre: [String]            // array of strings
});

const Book = mongoose.model("Book", bookSchema);


--------------------------------------------------

🔹 COMMON VALIDATIONS (ONE-LINER)
--------------------------------
required → field must exist  
min/max → number range  
enum → restrict values  
default → auto value if missing  
unique → no duplicate values  
match → regex validation  
minLength/maxLength → string length control  


--------------------------------------------------

🔹 RUN VALIDATORS ON UPDATE
---------------------------
Book.findByIdAndUpdate(id, { price: -500 }, {
  runValidators: true
});
