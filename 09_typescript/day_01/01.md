any vs unknown (TypeScript)

1. any

- Disables type checking.
- You can do anything with the value.
- TypeScript trusts you completely.
- Similar to turning off TypeScript for that variable.

Example:

let value: any = "Hello";

value.toUpperCase();   // OK
value = 123;
value.toFixed(2);      // OK


2. unknown

- Type-safe version of any.
- Can store any value.
- Must check/narrow the type before using it.

Example:

let value: unknown = "Hello";

value.toUpperCase();   // ERROR

if (typeof value === "string") {
    value.toUpperCase();   // OK
}


Key Difference

any:
    Store anything ✔
    Use immediately ✔
    No type checking ✔

unknown:
    Store anything ✔
    Use immediately ✖
    Type checking required ✔


Example

let a: any = 10;
let b: unknown = 10;

a.toUpperCase();   // Compiles (may fail at runtime)

b.toUpperCase();   // Compile-time error


Type Narrowing with unknown

let data: unknown = "Ajay";

if (typeof data === "string") {
    console.log(data.length);
}

if (typeof data === "number") {
    console.log(data.toFixed(2));
}


Type Assertion

let value: unknown = "Hello";

let str = value as string;

console.log(str.toUpperCase());


Interview Answer

any:
- Turns off TypeScript type checking.
- Allows any operation.
- Less safe.

unknown:
- Accepts any value.
- Requires type checking before use.
- Safer than any.

Rule of Thumb:
Use unknown when you don't know the type yet.
Use any only when absolutely necessary.

---------------------------
INTERFACE vs TYPE (TypeScript)

What are they?
--------------
Both are used to define the shape of data.

Interface:
- Defines the structure of an object.
- Primarily designed for object contracts.

Type:
- Defines object shapes, primitives, unions, tuples, functions, etc.
- More flexible than interface.


-----------------------------------------
1. Basic Syntax
-----------------------------------------

Interface

interface User {
    id: number;
    name: string;
}

Type

type User = {
    id: number;
    name: string;
};


-----------------------------------------
2. Object Creation
-----------------------------------------

interface User {
    id: number;
    name: string;
}

const user: User = {
    id: 1,
    name: "Ajay"
};


type User = {
    id: number;
    name: string;
};

const user: User = {
    id: 1,
    name: "Ajay"
};


-----------------------------------------
3. Extending / Inheritance
-----------------------------------------

Interface

interface Person {
    name: string;
}

interface Employee extends Person {
    salary: number;
}

const emp: Employee = {
    name: "Ajay",
    salary: 50000
};


Type

type Person = {
    name: string;
};

type Employee = Person & {
    salary: number;
};

const emp: Employee = {
    name: "Ajay",
    salary: 50000
};


-----------------------------------------
4. Declaration Merging
-----------------------------------------

Interface supports it.

interface User {
    id: number;
}

interface User {
    name: string;
}

Result:

interface User {
    id: number;
    name: string;
}


Type does NOT support it.

type User = {
    id: number;
};

type User = {
    name: string;
};

ERROR


-----------------------------------------
5. Primitive Types
-----------------------------------------

Interface cannot represent primitives.

interface Age = number;    // ERROR


Type can.

type Age = number;

let age: Age = 25;


-----------------------------------------
6. Union Types
-----------------------------------------

Interface cannot create unions.

interface Status = "success" | "error";   // ERROR


Type can.

type Status = "success" | "error";


-----------------------------------------
7. Tuple Types
-----------------------------------------

Interface cannot easily define tuples.

Type can.

type Coordinates = [number, number];

const point: Coordinates = [10, 20];


-----------------------------------------
8. Function Types
-----------------------------------------

Type

type Add = (a: number, b: number) => number;

const sum: Add = (a, b) => a + b;


Interface

interface Add {
    (a: number, b: number): number;
}

const sum: Add = (a, b) => a + b;


-----------------------------------------
9. Class Implementation
-----------------------------------------

Interface

interface Animal {
    name: string;
    makeSound(): void;
}

class Dog implements Animal {
    name = "Tommy";

    makeSound() {
        console.log("Bark");
    }
}


Type

type Animal = {
    name: string;
    makeSound(): void;
};

class Dog implements Animal {
    name = "Tommy";

    makeSound() {
        console.log("Bark");
    }
}


-----------------------------------------
10. When to Use What?
-----------------------------------------

Use Interface:
- Object shapes
- Class contracts
- Public APIs
- When declaration merging is useful

Use Type:
- Unions
- Intersections
- Tuples
- Primitive aliases
- Function types
- Advanced type manipulation


-----------------------------------------
Quick Comparison
-----------------------------------------

Feature                     Interface    Type
------------------------------------------------
Object Shape                Yes          Yes
Extend / Inherit            Yes          Yes (&)
Declaration Merging         Yes          No
Primitive Alias             No           Yes
Union Types                 No           Yes
Tuple Types                 No           Yes
Function Types              Yes          Yes
Class Implements            Yes          Yes
Advanced Type Operations    Limited      Yes


-----------------------------------------
Interview Answer
-----------------------------------------

Interface and Type are both used to define types in TypeScript.

Interface is mainly used for object contracts and supports
declaration merging.

Type is more flexible and can represent objects, primitives,
unions, tuples, intersections, and function types.

For object-oriented designs, interfaces are commonly preferred.
For advanced type composition, type aliases are preferred.
