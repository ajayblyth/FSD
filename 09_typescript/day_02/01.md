TUPLES (TYPESCRIPT) - NOTEPAD STYLE
------------------------------------------------------------

DEFINITION
- Tuple = fixed-length array with specific types at each position
- Each element has a defined type
- IMPORTANT: ORDER MATTERS while passing values

------------------------------------------------------------

BASIC SYNTAX
let user: [number, string] = [1, "Ajay"];

------------------------------------------------------------

ORDER MATTERS (VERY IMPORTANT)
let user: [number, string] = [1, "Ajay"];   // ✅ correct

let user2: [number, string] = ["Ajay", 1];  // ❌ wrong
// type mismatch because order is fixed

------------------------------------------------------------

EXAMPLE
let student: [number, string, number] = [101, "Ravi", 85];

------------------------------------------------------------

ACCESSING VALUES
let id = student[0];       // number
let name = student[1];     // string
let marks = student[2];    // number

------------------------------------------------------------

TUPLE WITH DIFFERENT TYPES
let data: [number, string, boolean] = [10, "OK", true];

------------------------------------------------------------

OPTIONAL ELEMENTS
let user: [number, string?] = [1];
let user2: [number, string?] = [1, "Ajay"];

------------------------------------------------------------

READONLY TUPLE
let user: readonly [number, string] = [1, "Ajay"];

// user[0] = 2 ❌ ERROR (cannot modify)

------------------------------------------------------------

REST IN TUPLES (SPREAD STYLE)
let numbers: [number, ...number[]] = [1, 2, 3, 4, 5];

let mixed: [string, ...number[]] = ["start", 1, 2, 3];

------------------------------------------------------------

NAMED TUPLE
let employee: [id: number, name: string, salary: number]
    = [1, "Ajay", 50000];

------------------------------------------------------------

USE CASES
- API response with fixed structure
- Returning multiple values from function
- Coordinates (x, y)
- Small grouped data

------------------------------------------------------------

LIMITATIONS
- Not flexible like arrays
- Hard to maintain for large structures
- Prefer objects/interfaces for complex data

------------------------------------------------------------

BEST PRACTICE
- Use tuples only for small fixed data
- Prefer objects/interfaces for scalable design

TYPE ASSERTION (TYPESCRIPT) - NOTEPAD STYLE
------------------------------------------------------------

DEFINITION
- Type Assertion = telling TypeScript to treat a value as a specific type
- You are overriding TypeScript's inferred type

------------------------------------------------------------

WHY USE IT
- When TypeScript cannot correctly infer the type
- When you know more about the value than TS compiler

------------------------------------------------------------

SYNTAX (2 WAYS)

1. "as" syntax (RECOMMENDED)
------------------------------------------------------------
let value: any = "Hello";

let length: number = (value as string).length;

------------------------------------------------------------

2. Angle-bracket syntax (NOT USED IN JSX)
------------------------------------------------------------
let value: any = "Hello";

let length: number = (<string>value).length;

------------------------------------------------------------
NOTE:
- Use "as" in React/JSX projects
- Angle-bracket syntax may conflict with JSX

------------------------------------------------------------

EXAMPLES

------------------------------------------------------------
let data: any = "TypeScript";

let size = (data as string).length;

------------------------------------------------------------

DOM EXAMPLE
------------------------------------------------------------
const input = document.getElementById("myInput") as HTMLInputElement;

input.value = "Hello";

------------------------------------------------------------

IMPORTANT POINTS
- Type assertion does NOT change runtime value
- It only tells TypeScript compiler about the type
- No type conversion happens

------------------------------------------------------------

WRONG USAGE (DANGEROUS)

let num = "123" as number;  ❌ (no real conversion)
------------------------------------------------------------

USE CASES
- DOM element handling
- API responses (unknown type)
- Narrowing 'any' or 'unknown' types

------------------------------------------------------------

BEST PRACTICE
- Use only when you are 100% sure about the type
- Prefer type narrowing (typeof, instanceof) when possible
