============================== BASICS ==============================

1. WHAT IS HTTP
-------------------------------------------------------------------
HTTP (HyperText Transfer Protocol) is a stateless communication protocol
used between client (browser) and server to exchange data over the web.

It follows a request-response model:
Client sends HTTP request → Server processes → sends HTTP response.

Each request is independent (stateless), meaning server does not remember
previous requests unless sessions/cookies are used.

HTTP methods:
GET (fetch), POST (create), PUT/PATCH (update), DELETE (remove)

Response contains:
- Status code (200, 404, 500)
- Headers (metadata)
- Body (HTML, JSON, etc.)

Example: Opening a website → browser sends GET request → server returns HTML


2. JSON vs HTTP
-------------------------------------------------------------------
HTTP → protocol (defines how data is transferred over network)
JSON → data format (defines how data is structured)

Example:
HTTP carries data, JSON is the data inside.


3. WHAT IS A WEBSITE
-------------------------------------------------------------------
A website is a collection of interconnected web pages hosted on a server
and accessed via a domain name using a browser.

It typically has two parts:
Frontend → UI (HTML, CSS, JavaScript)
Backend  → server logic + database (optional for dynamic sites)

Types:
- Static (fixed content)
- Dynamic (content changes based on user/data)

Example:
Google search page → static UI + dynamic results from backend.

4. WEBPAGES
-------------------------------------------------------------------
A webpage is a single document/page of a website (HTML page).
Examples: Home, About, Contact pages.


=========================== WEBSITE TYPES ===========================

5. STATIC WEBSITE
-------------------------------------------------------------------
Content is fixed and same for all users. No backend processing.
Example: portfolio, simple landing page.


6. DYNAMIC WEBSITE
-------------------------------------------------------------------
Content changes based on user input, database, or time.
Uses backend + database.
Example: Instagram, Amazon.


=========================== WEB FLOW ================================

7. END-TO-END FLOW
-------------------------------------------------------------------
User → Browser → HTTP Request → Server → Backend Logic
     → Database → Response (JSON/HTML) → Browser → UI Render


8. WHAT IS API
-------------------------------------------------------------------
API (Application Programming Interface) is a set of rules that allows
different software systems to communicate with each other.

It acts as a middle layer:
Client sends request → API processes → returns response (usually JSON)

APIs hide internal implementation and expose only required data.

Types:
- REST API (most common)
- SOAP API
- GraphQL

Example:
Frontend calls /api/users → backend returns user data.


9. REST API
-------------------------------------------------------------------
REST (Representational State Transfer) is an architectural style
for designing scalable and simple APIs using HTTP.

Key principles:
- Stateless (no memory of previous requests)
- Uses standard HTTP methods (GET, POST, PUT, PATCH, DELETE)
- Resource-based URLs (/users, /products)
- Uses JSON for data exchange

Example:
GET /users       → fetch users
POST /users      → create user
DELETE /users/1  → delete user

REST improves scalability and simplicity.


10. STATEFUL vs STATELESS + SESSION
-------------------------------------------------------------------
Stateful:
Server remembers client data across multiple requests using sessions.
Used in traditional web apps.

Example:
User logs in → session created → server remembers user → no need to login again.

Stateless:
Each request is independent, server does not store client state.
Used in REST APIs (often with tokens like JWT).

Session:
A session is server-side storage that keeps user-specific data
(like login status, user ID).

Session Flow:
Login → server creates session ID → sends to client (cookie)
→ client sends session ID in every request → server पहचान user

Stateless alternative:
Instead of session, token (JWT) is sent with each request.

12. NODE_MODULES
-------------------------------------------------------------------
node_modules is a folder that stores all installed packages and
their dependencies. It is auto-created by npm and should NOT be pushed to GitHub.


========================== IMPORTANT ================================


13. PORT
===================================================================

📌 DEFINITION
-------------------------------------------------------------------
A port is a logical number used to identify a specific application
or service running on a machine.

It helps the operating system route incoming network requests to
the correct application.


📌 BASIC IDEA
-------------------------------------------------------------------
IP address → identifies the machine
Port       → identifies the application inside that machine

Example:
localhost:3000 → Node app
localhost:8080 → another app


📌 RANGE
-------------------------------------------------------------------
Ports range from 0 to 65535

Common ports:
80   → HTTP
443  → HTTPS
27017 → MongoDB


📌 LISTENING (NODE.JS)
-------------------------------------------------------------------
app.listen(3000);

Meaning:
- Start server on port 3000
- OS assigns that port to your app
- App waits for incoming requests on that port


📌 WHY PORTS ARE NEEDED
-------------------------------------------------------------------
A single system can run multiple services:

- Node server     → port 3000
- Database        → port 27017
- Another service → port 5000

Ports ensure each request goes to the correct application.

Without ports:
❌ System cannot differentiate between multiple services


📌 IMPORTANT POINTS
-------------------------------------------------------------------
- Only one application can use a port at a time
- If port is already in use → error (EADDRINUSE)
- Ports 0–1023 are reserved (system ports)


📌 ONE-LINE ANSWER
-------------------------------------------------------------------
A port is a logical endpoint that allows multiple applications on
the same machine to communicate by uniquely identifying each service.

14. LOCAL vs GLOBAL PACKAGE PRIORITY
-------------------------------------------------------------------
If a package is installed locally and globally with different versions,
Node.js will ALWAYS use the local (project) version first.


15. API RESPONSE vs TEMPLATE RESPONSE
-------------------------------------------------------------------
API Response      → Sends JSON data (used for frontend/backend communication)
Template Response → Sends HTML page (used for rendering UI)

Example:
res.json({}) → JSON response
res.render() → HTML response
