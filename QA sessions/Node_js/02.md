========================================================
1) SHALLOW COPY vs DEEP COPY (JavaScript)
========================================================

A) Spread operator {...obj} → SHALLOW COPY
--------------------------------------------------------
const original = { a: 1, b: { c: 2 } };
const copy = { ...original };

copy.a = 10;
copy.b.c = 20;

console.log(original.a);      // 1
console.log(original.b.c);    // 20 ❗

WHY?
--------------------------------------------------------
a → primitive → copied (independent)
b → object → reference copied (same memory)

👉 Nested objects are shared → SHALLOW COPY


========================================================
B) Arrays → REFERENCE COPY
========================================================

const a = [1,2,3];
const b = a;

b.push(4);

console.log(a); // [1,2,3,4]

👉 b and a point to same memory


========================================================
C) Spread with array inside object → still SHALLOW
========================================================

const a = { arr: [1,2] };
const b = { ...a };

b.arr.push(3);

console.log(a.arr); // [1,2,3]

👉 inner array reference is shared


========================================================
D) Nested object spread → still SHALLOW
========================================================

const a = {
  name: "Darshan",
  address: { city: "Bangalore" }
};

const b = { ...a };

b.address.city = "Mysore";

console.log(a.address.city); // Mysore ❗


========================================================
E) Object.assign → SHALLOW COPY
========================================================

const a = { x: 1 };
const b = Object.assign({}, a);

b.x = 100;

console.log(a.x); // 1

👉 Same behavior as spread (shallow copy)


========================================================
F) JSON Deep Copy → DEEP COPY (LIMITED)
========================================================

const a = {
  x: 1,
  y: { z: 2 }
};

const b = JSON.parse(JSON.stringify(a));

b.y.z = 100;

console.log(a.y.z); // 2


LIMITATIONS:
--------------------------------------------------------
- removes functions
- removes undefined
- breaks Date, Map, Set

2) PROTOTYPE vs __proto__ (IMPORTANT)
========================================================


========================================================
A) prototype (Function property)
========================================================

DEFINITION:
👉 prototype exists only on functions (constructor functions)

function Person(name) {
  this.name = name;
}

Person.prototype.sayHello = function () {
  console.log("Hello " + this.name);
};


MEANING:
--------------------------------------------------------
- used to define shared methods
- all objects created from constructor inherit from it


========================================================
B) __proto__ (Object internal link)
========================================================

DEFINITION:
👉 __proto__ exists on objects

const obj = new Person("Darshan");

console.log(obj.__proto__ === Person.prototype); // true


MEANING:
--------------------------------------------------------
- points to parent prototype
- forms prototype chain


========================================================
C) KEY DIFFERENCE TABLE
========================================================

Feature        | prototype              | __proto__
--------------------------------------------------------
Exists on      | Functions             | Objects
Purpose        | Define shared methods | Link to prototype
Usage          | Constructor setup     | Inheritance lookup
Direct use     | Yes                   | Not recommended


========================================================
D) PROTOTYPE CHAIN FLOW
========================================================

obj → __proto__ → Person.prototype → Object.prototype → null


========================================================
E) SIMPLE INTUITION
========================================================

prototype  → blueprint (design time)
__proto__  → actual link (runtime)


========================================================
F) MODERN BEST PRACTICE
========================================================

Object.getPrototypeOf(obj)   // preferred over __proto__

1) JAVASCRIPT RUNTIME (BROWSER / NODE)
========================================================

DEFINITION:
JavaScript Runtime = Environment where JS code executes.

It is NOT just JS engine.
It includes:
- JS Engine (V8, SpiderMonkey, etc.)
- Web APIs (browser) / Node APIs
- Callback Queue
- Microtask Queue
- Event Loop


FLOW:
--------------------------------------------------------
JS Code → JS Engine → Web APIs → Queues → Event Loop → Execution


========================================================
2) V8 ENGINE (Google Chrome / Node.js)
========================================================

DEFINITION:
V8 is a JavaScript engine developed by Google.
It converts JS code into machine code (fast execution).

USED IN:
- Google Chrome
- Node.js


========================================================
V8 COMPONENTS
========================================================

A) CALL STACK
--------------------------------------------------------
- Executes JS functions
- Works in LIFO (Last In First Out)

Example:
function A() → function B()
B executes first, then A


========================================================

B) HEAP MEMORY
--------------------------------------------------------
- Used for storing objects, arrays, functions
- Unstructured memory area


Example:
const obj = { name: "Darshan" }
→ stored in heap


========================================================

C) HEAP + STACK TOGETHER
--------------------------------------------------------
Stack → execution
Heap → storage


========================================================

D) GARBAGE COLLECTOR
--------------------------------------------------------
- Removes unused memory from heap
- Uses "Mark and Sweep" algorithm

👉 Frees memory automatically


========================================================

E) JUST-IN-TIME (JIT) COMPILATION
--------------------------------------------------------
V8 = Interpreter + Compiler

Steps:
1. Parse JS code
2. Convert to Bytecode
3. Optimize frequently used code
4. Convert to Machine Code

👉 Makes JS very fast


========================================================
3) EVENT LOOP (IMPORTANT PART OF RUNTIME)
========================================================

Handles async operations.

FLOW:
--------------------------------------------------------
Call Stack → Web APIs → Callback Queue → Event Loop → Stack


TWO QUEUES:
--------------------------------------------------------
1. Callback Queue (macrotasks)
   - setTimeout
   - setInterval

2. Microtask Queue (higher priority)
   - Promises
   - process.nextTick (Node)


RULE:
--------------------------------------------------------
Microtask queue runs BEFORE callback queue


========================================================
4) WHAT IS HTTP?
========================================================

DEFINITION:
HTTP (HyperText Transfer Protocol)
→ protocol used for communication between client and server


HOW IT WORKS:
--------------------------------------------------------
Client (browser) → sends request → Server → sends response


FEATURES:
--------------------------------------------------------
- Stateless (no memory of previous request)
- Works on request/response model
- Runs over TCP


HTTP METHODS:
--------------------------------------------------------
GET     → fetch data
POST    → create data
PUT     → update full data
PATCH   → update partial data
DELETE  → remove data


STATUS CODES:
--------------------------------------------------------
200 → OK
201 → Created
400 → Bad Request
401 → Unauthorized
404 → Not Found
500 → Server Error

5) WHAT IS REST API?
========================================================

DEFINITION:
REST API = way of designing APIs using HTTP rules.

REST = Representational State Transfer


========================================================
PRINCIPLES OF REST
========================================================

1. Client-Server separation
2. Stateless communication
3. Cacheable responses
4. Uniform interface
5. Layered system


========================================================
REST API EXAMPLE
========================================================

GET    /users        → get all users
GET    /users/1      → get user by id
POST   /users        → create user
PUT    /users/1      → update user
DELETE /users/1      → delete user


========================================================
KEY IDEA
========================================================

HTTP = communication protocol  
REST API = rules/design pattern using HTTP

🔥 new KEYWORD vs CONSTRUCTOR (JavaScript)
========================================================


========================================================
1) CONSTRUCTOR FUNCTION
========================================================

DEFINITION:
--------------------------------------------------------
A constructor is a normal function used to create objects.

Example:
--------------------------------------------------------
function Person(name, age) {
  this.name = name;
  this.age = age;
}

✔ Acts as a blueprint for objects


========================================================
2) new KEYWORD
========================================================

DEFINITION:
--------------------------------------------------------
new is used to create object from constructor function


WHAT new DOES INTERNALLY (VERY IMPORTANT)
--------------------------------------------------------

const p1 = new Person("Ajay", 22);

INTERNAL STEPS:
--------------------------------------------------------
1) Create empty object
   {}

2) Link object to prototype
   obj.__proto__ = Person.prototype

3) Call constructor with this
   Person.call(obj, "Ajay", 22)

4) Return object
   return obj


========================================================
🔥 INTERNAL SIMULATION OF new
========================================================

function myNew(Constructor, ...args) {

  const obj = {};                         // step 1

  obj.__proto__ = Constructor.prototype;  // step 2

  Constructor.apply(obj, args);           // step 3

  return obj;                             // step 4
}


========================================================
3) USING CONSTRUCTOR + new
========================================================

function Person(name) {
  this.name = name;
}

const p1 = new Person("Ajay");

console.log(p1.name); // Ajay


========================================================
4) WHAT IF WE DON'T USE new?
========================================================

function Person(name) {
  this.name = name;
}

const p1 = Person("Ajay"); // ❌ no new


RESULT:
--------------------------------------------------------
- this refers to global object (or undefined in strict mode)
- Object is NOT created properly


========================================================
5) CONSTRUCTOR vs NORMAL FUNCTION
========================================================

Feature          | Constructor           | Normal Function
------------------------------------------------------------
Called with new  | Yes                   | No
Purpose          | Create objects        | General logic
Uses this        | Yes                   | Optional
Returns object   | Yes (auto)            | Manual


========================================================
6) ADDING METHODS USING PROTOTYPE
========================================================

function Person(name) {
  this.name = name;
}

Person.prototype.greet = function() {
  console.log("Hello " + this.name);
};

const p1 = new Person("Ajay");

p1.greet(); // Hello Ajay

✔ Method is shared (memory efficient)


========================================================
7) CLASS (MODERN SYNTAX)
========================================================

class Person {

  constructor(name) {
    this.name = name;
  }

  greet() {
    console.log("Hello " + this.name);
  }
}

const p1 = new Person("Ajay");

✔ Internally same as constructor + prototype


========================================================
🔥 FINAL SUMMARY
========================================================

✔ Constructor → function used to create objects  
✔ new → creates object + sets prototype + binds this  


🧠 ONE LINE (INTERVIEW)
--------------------------------------------------------
new executes a constructor by:
- creating an object
- binding this
- linking prototype
- returning the object
