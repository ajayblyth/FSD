# 1. What is JavaScript?

JavaScript (JS) is a high-level, dynamically typed programming language mainly used to add behavior, interactivity, and dynamic functionality to web applications.

Basically, HTML gives us the structure, CSS handles the styling, and JavaScript handles the behavior. Using JavaScript, we can manipulate the DOM, respond to user actions, validate forms, communicate with APIs, and update the UI dynamically without necessarily reloading the page.

For example, on an e-commerce website, when a user clicks "Add to Cart", JavaScript can handle the click, update the cart count immediately, and communicate with the backend API to save the cart information.

JavaScript is also single-threaded, meaning it executes JavaScript code one task at a time using a single Call Stack. However, it can handle asynchronous operations such as API calls, timers, and other background operations with the help of Browser/Node.js APIs and the Event Loop. We use callbacks, Promises, and async/await to work with these operations.

JavaScript is not limited to browsers. With Node.js, we can also use JavaScript on the server side to build backend applications and APIs.

Why was JavaScript created?

Originally, websites mainly consisted of HTML and CSS. HTML provided the structure and CSS provided the styling, but there was very little client-side behavior.

JavaScript was introduced to add behavior and interactivity to web pages, so actions could happen in the browser without requiring a complete page reload for every interaction.

For example:
- Showing or hiding content
- Validating a form before submission
- Updating a cart count
- Handling button clicks
- Performing live search


What is the DOM?

DOM stands for Document Object Model.

It is a programming interface provided by the browser that represents an HTML document as a tree of objects.

JavaScript uses the DOM to read and modify the page, such as changing content, changing styles, adding or removing elements, and handling events.

In simple words:

The DOM acts as a bridge between JavaScript and the HTML page.


Important Nature of JavaScript

1. High-level
JavaScript provides abstractions, so developers don't have to directly manage low-level memory operations.

2. Dynamically typed
We don't need to specify a variable's data type when declaring it. The type is determined at runtime.

Example:
let value = 10;
value = "Hello";

3. Single-threaded
JavaScript executes JavaScript code using a single Call Stack, so one piece of JavaScript code is executed at a time.

However, asynchronous operations can be handled using Browser/Node.js APIs and the Event Loop.

4. Event-driven
JavaScript can execute code in response to events such as clicks, keyboard input, form submission, timers, or API responses.

5. Asynchronous
JavaScript supports asynchronous programming using callbacks, Promises, and async/await.

6. Prototype-based
JavaScript uses prototypes for inheritance and code reuse. Objects can access properties and methods through the prototype chain.

7. First-class functions
Functions can be stored in variables, passed as arguments, and returned from other functions.

8. Automatic Garbage Collection
JavaScript automatically manages memory and removes objects that are no longer reachable.


Is JavaScript interpreted or compiled?

Historically, JavaScript was commonly described as an interpreted language because it was executed at runtime.

Modern JavaScript engines use Just-In-Time (JIT) compilation.

Examples:
- V8 → Chrome and Node.js
- SpiderMonkey → Firefox
- JavaScriptCore → Safari

In a simplified view, the engine parses the code, executes it, and optimizes frequently executed code into efficient machine code.

So modern JavaScript is not purely interpreted; modern engines use JIT compilation.


Common Uses of JavaScript

JavaScript is commonly used for:
- Dynamic web pages
- Form validation
- Interactive UI components
- API communication
- Live search
- Dashboards
- Chat and notifications
- Games
- Single Page Applications (SPAs)
- Backend applications using Node.js

# 2. What are the data types in JavaScript?

Data types define what kind of value a variable holds. As we know that JavaScript is dynamically typed, which means we don't need to specify the data type when declaring a variable. The type is determined at runtime based on the value.

JavaScript data types are broadly divided into:

1. Primitive Data Types
2. Non-Primitive (Reference) Data Type


1. Primitive Data Types

Primitive values are single, simple values. They are immutable, meaning the original primitive value cannot be changed.
let age = 25;

age = 30;

Here, we are not changing the value 25 into 30. We are reassigning the variable age so that it now refers to a different primitive value.

JavaScript has 7 primitive data types:

1. String
   Used to store text.

   let name = "Ajay";

2. Number
   Used for both integer and decimal numbers.

   let age = 25;
   let price = 99.99;

3. BigInt
   Used for integers larger than the safe limit of Number.

   let bigNumber = 12345678901234567890n;

   The "n" at the end indicates a BigInt.

4. Boolean
   Represents true or false.

   let isLoggedIn = true;

5. Undefined
   A variable is declared but has not been assigned a value.

   let value;
   console.log(value);   // undefined

6. Null
   Represents an intentional absence of a value.

   let user = null;

7. Symbol
   Used to create unique values, mainly when unique object properties are required.

   let id = Symbol("id");


2. Non-Primitive / Reference Data Type

Object is the main non-primitive data type. Objects are used to store collections of related data.

Example:

let user = {
    name: "Ajay",
    age: 25
};

Arrays and functions are also technically objects in JavaScript.
Because in JavaScript, arrays and functions are special kinds of objects. They have object-like properties and methods, and they are reference values.

let numbers = [10, 20, 30];

function greet() {
    console.log("Hello");
}


Important Interview Point:
Primitive values are stored and copied by value, whereas objects are handled by reference.

Example:

let a = 10;
let b = a;

b = 20;

console.log(a);   // 10
console.log(b);   // 20


With an object:

let obj1 = { name: "Ajay" };
let obj2 = obj1;

obj2.name = "Rahul";

console.log(obj1.name);   // Rahul

Both variables refer to the same object.


typeof Operator:

We can use typeof to check the type of a value.

typeof "Hello"       // "string"
typeof 10            // "number"
typeof true          // "boolean"
typeof undefined     // "undefined"
typeof 10n           // "bigint"
typeof Symbol()      // "symbol"
typeof {}            // "object"

One important exception:

typeof null           // "object"

This is a historical JavaScript behavior/bug. Even though null represents an intentional absence of value, typeof null returns "object".


Interview-ready answer:

"JavaScript has seven primitive data types: String, Number, BigInt, Boolean, Undefined, Null, and Symbol. Apart from these, we have objects as the main non-primitive type, which includes objects, arrays, and functions. JavaScript is dynamically typed, so the type is determined at runtime rather than being explicitly declared."

Both represent the absence of a value, but they have different meanings.

Example:

null means we intentionally assign "no value" to a variable.

# 5. What is the difference between == and ===?

The main difference is that == performs type coercion before comparison, while === compares both value and data type without type coercion.

Coercion means JavaScript automatically converts a value from one data type to another when needed.
coercion (/koʊˈɜːr.ʒən/)
5 + "5"   // "55"

Example:

5 == "5"       // true
5 === "5"      // false

With ==, JavaScript converts the values according to its type coercion rules before comparing them.

With ===, both the value and data type must be the same.

Example:

0 == false     // true
0 === false    // false

Another example:

null == undefined     // true
null === undefined    // false

In practice, === is generally preferred because it avoids unexpected results caused by automatic type coercion.

Interview point:
== checks equality after type coercion.
=== checks strict equality without type coercion.

2. 1. Why is var hoisting considered a problem?

Consider this code:

console.log(age);

var age = 25;

JavaScript internally treats it like this:

var age;              // Hoisted

console.log(age);     // undefined

age = 25;

So the output is:

undefined
Why is this bad?

Suppose you accidentally use a variable before assigning it.

if (age > 18) {
    console.log("Adult");
}

var age = 25;

You might think it should print "Adult".

But internally:

var age = undefined;

if (age > 18) {
    console.log("Adult");
}

age = 25;

Now,

undefined > 18

is

false

So nothing prints.

No error.
No warning.
Your program silently behaves incorrectly.

These silent bugs are difficult to find.

Why is let better?
console.log(age);

let age = 25;

Output:

ReferenceError

Immediately you know:

"I used the variable before declaring it."

This is because of the Temporal Dead Zone (TDZ).

# 7. What is Hoisting?

"Hoisting means JavaScript process declarations in memory before execution starts. That's why `var` can be accessed before its declaration, while `let` and `const` give a ReferenceError because they are in the Temporal Dead Zone. Function declarations are fully hoisted and can be called before they are written."

JavaScript Execution Phases

When JavaScript runs a program, we can broadly think of it as going through two phases:

1. Memory Creation Phase

Before executing the code, JavaScript creates the required memory for variables and functions.

- var → memory is allocated and initialized with undefined.
- let → memory is allocated but remains uninitialized.
- const → memory is allocated but remains uninitialized.
- Function declarations → the complete function is stored in memory.

No actual code is executed during this phase.


2. Execution Phase

JavaScript then executes the code in order.

- Assignments are performed.
- Functions are called.
- Expressions are evaluated.


Example 1: var

console.log(a);

var a = 10;

console.log(a);


What happens:

During the memory creation phase:

a → undefined

During execution:

console.log(a);   // undefined

a = 10;

console.log(a);   // 10


Output:

undefined
10

So, var is hoisted and initialized with undefined.


Example 2: let

console.log(a);

let a = 10;


Here, a is also created during the memory creation phase, but it is not initialized.

a → <uninitialized>

When JavaScript reaches console.log(a), the variable is still in its Temporal Dead Zone.

Output:

ReferenceError: Cannot access 'a' before initialization


Example 3: const

console.log(a);

const a = 10;


const behaves similarly to let during hoisting.

The variable is created but remains uninitialized until the declaration is reached.

So accessing it before initialization gives:

ReferenceError: Cannot access 'a' before initialization


Temporal Dead Zone (TDZ)

The Temporal Dead Zone is the period between the start of the scope, where a let or const variable has already been created but is still uninitialized, and the point where its declaration is executed.

Example:

{
    console.log(a);  // ReferenceError
    let a = 10;
    console.log(a);  // 10
}

The first console.log() is inside the TDZ.

Once execution reaches:

let a = 10;

the variable is initialized and can be accessed normally.


Function Hoisting

Function declarations are fully hoisted.

Example:

greet();

function greet() {
    console.log("Hello");
}

Output:

Hello

This works because the complete function declaration is available during the memory creation phase.

Memory:

greet → function


Function Expression

A function expression follows the hoisting behavior of the variable used to store it.

Example:

greet();

var greet = function () {
    console.log("Hello");
};

Here, var greet is hoisted and initialized with undefined.

Memory:

greet → undefined

When JavaScript reaches:

greet();

it is effectively trying to call undefined as a function.

Output:

TypeError: greet is not a function


Arrow Function

Arrow functions are also function expressions, so they follow the hoisting behavior of the variable they are assigned to.

Example:

sayHi();

const sayHi = () => {
    console.log("Hi");
};

Because sayHi is declared using const, it is in the TDZ until its declaration is executed.

Output:

ReferenceError: Cannot access 'sayHi' before initialization


Important Memory Example

Code:

var a = 5;
let b = 10;
const c = 20;

function add() {}


Memory Creation Phase:

a   → undefined
b   → <uninitialized>
c   → <uninitialized>
add → function


After execution:

a   → 5
b   → 10
c   → 20
add → function

# 8. What is scope?

Scope defines where a variable can be accessed in a JavaScript program.

In simple terms, scope determines the "visibility" or accessibility of a variable.

JavaScript mainly has three types of scope:
- Global scope
- Function scope
- Block scope


1. Global Scope

A variable declared outside any function or block has global scope.

It can be accessed from anywhere in the program, as long as it is accessible in that environment.

Example:

let name = "Ajay";

function greet() {
    console.log(name);
}

greet();              // Ajay
console.log(name);    // Ajay

Here, name is globally scoped, so it can be accessed inside the function as well.


2. Function Scope

A variable declared inside a function is function-scoped.

It can be accessed only inside that function and cannot be accessed from outside.

Example:

function greet() {
    let message = "Hello";
    console.log(message);
}

greet();              // Hello

console.log(message); // ReferenceError

Here, message exists only inside greet().


3. Block Scope

A block is code inside curly braces {}, such as an if statement, for loop, or while loop.

Variables declared using let and const are block-scoped, meaning they can only be accessed inside that block.

Example:

if (true) {
    let age = 25;
    const name = "Ajay";

    console.log(age);      // 25
    console.log(name);     // Ajay
}

console.log(age);         // ReferenceError
console.log(name);        // ReferenceError

Here, age and name are accessible only inside the if block.


Important: var vs let/const in scope

var is function-scoped, while let and const are block-scoped.

Example:

if (true) {
    var a = 10;
    let b = 20;
    const c = 30;
}

console.log(a);    // 10
console.log(b);    // ReferenceError
console.log(c);    // ReferenceError

So, var ignores block scope, but let and const respect block scope.

4. Lexical Scope
=====================================================================

Lexical scope means a variable's accessibility is determined by where the
variable and function are written in the code, not by where the function is called.

An inner function can access variables from its outer scope. This is the
foundation of closures in JavaScript.


Example:

let x = 10;

function outer() {
    let y = 20;

    function inner() {
        console.log(x); // 10
        console.log(y); // 20
    }

    inner();
}

outer();


Scope chain:

Global Scope
    ↓
outer() Scope
    ↓
inner() Scope

When JavaScript looks for a variable inside `inner()`, it first checks its
own scope. If it doesn't find it, it looks in the outer scope, and continues
up the scope chain until it finds the variable or reaches the global scope.


Important:

Lexical scope is not usually considered a separate "type" like global,
function, and block scope. It describes how these scopes are connected based
on where the code is written.

Interview wording:

"Lexical scope means JavaScript determines variable accessibility based on
where the code is physically written. An inner function can access variables
from its outer scopes, which creates the scope chain and is also the basis
for closures."

Scope Chain

If JavaScript cannot find a variable in the current scope, it looks in the outer scope. This continues until it reaches the global scope.

Example:

let name = "Ajay";

function outer() {
    let age = 25;

    function inner() {
        console.log(name);  // Ajay
        console.log(age);   // 25
    }

    inner();
}

outer();

Here, inner() can access its own variables, then variables from outer(), and finally variables from the global scope.

This lookup process is called the scope chain.


Interview-ready answer:

"Scope defines where a variable can be accessed in JavaScript. The main types are global scope, function scope, and block scope. A globally declared variable can generally be accessed throughout its accessible environment, a variable declared inside a function is available only within that function, and variables declared with let and const inside a block are available only within that block. One important difference is that var is function-scoped, while let and const are block-scoped. JavaScript also uses a scope chain, so if a variable isn't found in the current scope, it looks in the outer scopes."

# 9. What is a function in JavaScript?

A function is a reusable block of code designed to perform a specific task. Instead of writing the same logic repeatedly, we define it once and call it whenever we need it.

Functions can accept input through parameters, perform some logic, and optionally return a result.

Why do we need functions?

The main purpose is code reusability. If the same logic is needed multiple times, we can write it once and reuse it with different inputs.

This reduces code duplication and makes the code easier to read, maintain, test, and modify.

Example:

Without a function:

console.log(10 + 20);
console.log(50 + 60);
console.log(100 + 200);


With a function:

function add(a, b) {
    return a + b;
}

console.log(add(10, 20));    // 30
console.log(add(50, 60));    // 110
console.log(add(100, 200));  // 300


Function Syntax:

function functionName(parameters) {
    // code
    return value;
}


Example:

function add(a, b) {
    return a + b;
}

Here:

function → keyword
add → function name
a, b → parameters
a + b → function logic
return → sends the result back to the caller

Calling the function:

add(10, 20);

Here, 10 and 20 are arguments.


Parameters vs Arguments

Parameters are the variables defined in the function declaration.

Arguments are the actual values passed when calling the function.

Example:

function greet(name) {
    console.log("Hello " + name);
}

greet("Ajay");

Here:
name → parameter
"Ajay" → argument


Return Keyword

The return statement sends a value back to where the function was called.

Example:

function add(a, b) {
    return a + b;
}

let result = add(2, 3);

console.log(result);    // 5


If a function does not explicitly return a value, it returns undefined.

Example:

function add(a, b) {
    a + b;
}

console.log(add(2, 3));    // undefined


Ways to Define Functions


1. Function Declaration

A function declaration is defined using the function keyword.

function greet() {
    console.log("Hello");
}

greet();

Function declarations are fully hoisted, so they can be called before their declaration.

greet();    // Hello

function greet() {
    console.log("Hello");
}


2. Function Expression

A function expression is a function assigned to a variable.

const greet = function () {
    console.log("Hello");
};

greet();

The function itself is not fully hoisted. It follows the hoisting behavior of the variable.

For example, with const or let, calling it before the assignment results in a ReferenceError because the variable is in the Temporal Dead Zone.


3. Anonymous Function

An anonymous function is a function without a name.

const greet = function () {
    console.log("Hello");
};

It is commonly used when the function doesn't need to be referenced by its own name, especially as a callback.

Example:

setTimeout(function () {
    console.log("Hello");
}, 1000);


4. Named Function Expression

A named function expression is a function expression that has its own name.

const greet = function sayHello() {
    console.log("Hello");
};

The variable is greet, while the function itself is named sayHello.

Named function expressions can be useful for debugging and recursion, although they are less common in everyday code.


5. Arrow Function

Arrow functions were introduced in ES6 and provide a shorter way to write functions.

const greet = () => {
    console.log("Hello");
};

They are especially common in callbacks and array methods.

Example:

const numbers = [1, 2, 3];

const doubled = numbers.map(num => num * 2);

Arrow functions also have important behavioral differences from normal functions, particularly with this, arguments, constructors, and prototypes.


6. Immediately Invoked Function Expression (IIFE)

An IIFE is a function that is defined and executed immediately.

(function () {
    console.log("Executed");
})();

Output:

Executed

IIFEs are mainly used to create an isolated/private scope and avoid unnecessary variables in the surrounding scope.


# Default Parameters

JavaScript allows us to provide default values for parameters.

Example:

function greet(name = "Guest") {
    console.log("Hello " + name);
}

greet();          // Hello Guest
greet("Ajay");    // Hello Ajay

The default value is used when no value, or undefined, is passed for that parameter.


Rest Parameter

The rest parameter allows a function to accept multiple arguments and collect them into an array.

Example:

function sum(...numbers) {
    console.log(numbers);
}

sum(1, 2, 3, 4);

Output:

[1, 2, 3, 4]

The ...numbers here is a rest parameter.


Callback Function

A callback is a function passed as an argument to another function so that the receiving function can execute it.

Example:

function process(callback) {
    callback();
}

process(function () {
    console.log("Done");
});

Here, the anonymous function is passed to process() and executed inside it.


Higher-Order Function

A higher-order function is a function that either:

- accepts another function as an argument, or
- returns another function.

Example:

function process(callback) {
    callback();
}

process(() => {
    console.log("Done");
});

Here, process() is a higher-order function because it accepts a function as an argument.


First-Class Functions

JavaScript treats functions as first-class values.

This means functions can be:

- assigned to variables
- passed as arguments
- returned from other functions
- stored in objects or arrays

Example:

const greet = function () {
    console.log("Hello");
};


// Passed as an argument

function execute(fn) {
    fn();
}

execute(greet);


// Returned from another function

function getFunction() {
    return greet;
}

getFunction()();


// Stored in an object

const obj = {
    sayHello: greet
};

obj.sayHello();


This ability to treat functions like values is what makes callbacks, higher-order functions, and many JavaScript patterns possible.


Important Function Concepts

Functions can have:

- Parameters → inputs defined by the function
- Arguments → actual values passed to the function
- Return values → output returned by the function
- Default parameters → fallback values for missing arguments
- Rest parameters → collect multiple arguments into an array
- Callbacks → functions passed to other functions
- Higher-order behavior → functions accepting or returning other functions
- First-class behavior → functions can be treated like values


Interview-ready answer:

"A function in JavaScript is a reusable block of code designed to perform a specific task. We can pass data into a function through parameters, and it can return a result using the return statement. Functions help us avoid code duplication and make our code easier to maintain and reuse.

JavaScript supports different ways of defining functions, such as function declarations, function expressions, anonymous and named function expressions, arrow functions, and IIFEs. Functions can also accept default and rest parameters, and because JavaScript treats functions as first-class values, we can pass them as arguments, return them from other functions, and use them as callbacks or higher-order functions."

# 10. What is the difference between a normal function and an arrow function?

A normal function and an arrow function both allow us to define reusable functions, but arrow functions provide a shorter syntax and have some important behavioral differences, especially with this, arguments, and constructors.


1. Arrow Function Syntax

Normal function:

function add(a, b) {
    return a + b;
}

Arrow function:

const add = (a, b) => {
    return a + b;
};


The arrow function can be shortened when the function contains only one expression.

const add = (a, b) => a + b;

Here, curly braces {} and the return keyword are not required.

This is called an implicit return because the expression is automatically returned.


If we use curly braces, we need to explicitly use return:

const add = (a, b) => {
    return a + b;
};


Single Parameter

If an arrow function has exactly one parameter, parentheses are optional.

const greet = name => {
    console.log("Hello " + name);
};

But with multiple parameters, parentheses are required:

const add = (a, b) => a + b;


No Parameters

For zero parameters, empty parentheses are required:

const greet = () => {
    console.log("Hello");
};


Returning an Object

There is one important syntax issue when returning an object implicitly.

This is NOT correct:

const getUser = () => {
    name: "Ajay"
};

JavaScript treats {} as a function body.

To implicitly return an object, wrap the object in parentheses:

const getUser = () => ({
    name: "Ajay"
});


2. this

This is the most important behavioral difference.

A normal function has its own this, and its value depends on how the function is called.

An arrow function does not have its own this. It inherits this from its surrounding lexical scope.

Example:

const person = {
    name: "Ajay",

    greet() {
        const sayHello = () => {
            console.log(this.name);
        };

        sayHello();
    }
};

person.greet();    // Ajay

Here, the arrow function gets this from greet(), where this refers to person.


3. arguments

A normal function has its own arguments object.

function show() {
    console.log(arguments);
}

show(10, 20, 30);

An arrow function does not have its own arguments object.

If we need to collect multiple arguments in an arrow function, we can use the rest parameter:

const show = (...args) => {
    console.log(args);
};

show(10, 20, 30);


4. Constructor

Normal functions can be used as constructors with new.

function Person(name) {
    this.name = name;
}

const person = new Person("Ajay");

Arrow functions cannot be used as constructors.

const Person = name => {
    this.name = name;
};

// new Person("Ajay");    // TypeError


5. Prototype

Normal functions have a prototype property and can be used as constructor functions.

Arrow functions do not have their own prototype property.


6. Hoisting

Function declarations are fully hoisted:

greet();    // Hello

function greet() {
    console.log("Hello");
}

Arrow functions are normally assigned to variables, so they follow the hoisting behavior of that variable.

const greet = () => {
    console.log("Hello");
};

Calling greet() before the declaration gives a ReferenceError because const is in the Temporal Dead Zone.


7. Common Usage

Arrow functions are commonly used for short functions and callbacks.

For example:

const numbers = [1, 2, 3];

const doubled = numbers.map(num => num * 2);

console.log(doubled);    // [2, 4, 6]

The arrow function makes callback code shorter and easier to read.


Normal Function vs Arrow Function

| Feature              | Normal Function                         | Arrow Function                         |
|----------------------|------------------------------------------|-----------------------------------------|
| Syntax               | Uses function keyword                    | Uses => syntax                          |
| Short syntax         | No                                       | Yes                                     |
| One parameter        | Parentheses normally used                | Parentheses can be omitted              |
| One-expression return| Uses return                              | Implicit return possible                |
| this                  | Has its own this                         | Inherits lexical this                   |
| arguments             | Has its own arguments object             | No own arguments object                 |
| Constructor           | Can be used with new                     | Cannot be used with new                 |
| prototype             | Has prototype                            | No own prototype                        |
| Hoisting              | Function declaration is fully hoisted    | Follows variable's hoisting rules       |
| Common usage          | Methods, constructors, general functions | Callbacks and short functions           |

"Arrow functions were introduced in ES6 mainly to provide a shorter way of writing functions, but they also behave differently from normal functions. For example, if an arrow function has a single expression, we can omit the curly braces and return keyword because it has an implicit return. Parentheses can also be omitted when there is only one parameter.

The most important difference is this: a normal function has its own this, while an arrow function doesn't have its own this and inherits it from the surrounding lexical scope.
