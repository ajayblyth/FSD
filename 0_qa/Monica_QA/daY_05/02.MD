#  What is map()?

map() is an array method used to transform every element of an array and create a new array with the results.

The important point is that map() returns a new array and the original array is not changed.
Example:

const numbers = [1, 2, 3, 4];

const doubled = numbers.map(num => num * 2);

console.log(doubled);
// [2, 4, 6, 8]

Here, map() takes each number, multiplies it by 2, and puts the result into a new array.

The original array is not changed:

console.log(numbers);
// [1, 2, 3, 4]


Syntax:

array.map((element, index, array) => {
    // return new value
});


Important:

map() expects us to return a value for each element. That returned value becomes an element in the new array.

Example:

const names = ["Ajay", "Rahul", "Amit"];

const greetings = names.map(name => "Hello " + name);

console.log(greetings);
// ["Hello Ajay", "Hello Rahul", "Hello Amit"]


Interview-ready answer:

"map() is used when we want to transform every element of an array and create a new array containing the transformed values. It returns a new array and normally keeps the same number of elements as the original array."

# What is filter()?

filter() is an array method used when we want to select only the elements that satisfy a particular condition.

It returns a new array containing only the elements for which the callback returns true.

Example:

const numbers = [1, 2, 3, 4, 5, 6];

const evenNumbers = numbers.filter(num => num % 2 === 0);

console.log(evenNumbers);
// [2, 4, 6]

Here, filter() checks every number. If the condition is true, that element is included in the new array.

The original array is not changed.

Example:

const users = [
    { name: "Ajay", age: 25 },
    { name: "Rahul", age: 17 },
    { name: "Amit", age: 30 }
];

const adults = users.filter(user => user.age >= 18);

console.log(adults);
// Ajay and Amit

Important:

Unlike map(), filter() does not necessarily return the same number of elements. It can return fewer elements, all elements, or even an empty array.

Syntax:

array.filter((element, index, array) => {
    return condition;
});


Interview-ready answer:

"filter() is used when we want to select specific elements from an array based on a condition. It creates and returns a new array containing only the elements for which the condition is true."

#  What is reduce()?

reduce() is used when we want to process all elements of an array and combine them into a single result.

That result can be a number, string, object, array, or another type.

The key idea is that reduce() maintains an accumulator, which stores the result as the array is processed.

Syntax:

array.reduce((accumulator, currentValue) => {
    return updatedAccumulator;
}, initialValue);

Example:

const numbers = [1, 2, 3, 4];

const sum = numbers.reduce((total, num) => {
    return total + num;
}, 0);

console.log(sum);
// 10


How it works:

Initial total = 0

1 → 0 + 1 = 1
2 → 1 + 2 = 3
3 → 3 + 3 = 6
4 → 6 + 4 = 10

Final result = 10


Here:

total → accumulator
num → current element
0 → initial value



Another example:

const numbers = [1, 2, 3, 4];

const product = numbers.reduce((result, num) => {
    return result * num;
}, 1);

console.log(product);
// 24


Interview-ready answer:

"reduce() is used when we want to process an entire array and produce one final result. It uses an accumulator that keeps track of the result as each element is processed. For example, I can use reduce() to calculate a sum, product, count values, group data, or build an object."

# What is the difference between map(), filter(), and reduce()?

The easiest way to remember them is:

map()    → Transform
filter() → Select
reduce() → Combine

Example:

const numbers = [1, 2, 3, 4, 5];

map():

const doubled = numbers.map(num => num * 2);

// [2, 4, 6, 8, 10]

We transformed every element.


filter():

const even = numbers.filter(num => num % 2 === 0);

// [2, 4]

We selected only elements that satisfy the condition.


reduce():

const sum = numbers.reduce((total, num) => total + num, 0);

// 15

We combined all elements into one result.


Comparison:

| Method   | Main Purpose | Returns              | Number of Elements |
|----------|--------------|----------------------|--------------------|
| map()    | Transform    | New array            | Usually same       |
| filter() | Select       | New array            | Same or fewer      |
| reduce() | Combine      | Single final result* | Usually one result |

*reduce() can technically return any type, not necessarily a primitive value.


Interview-ready answer:

"map(), filter(), and reduce() are all array methods, but they solve different problems. I use map() when I want to transform every element and get a new array, filter() when I want to select elements based on a condition, and reduce() when I want to combine the array into a final result. So, in simple terms: map transforms, filter selects, and reduce combines."

# What is the difference between map() and forEach()?


Both map() and forEach() execute a callback for every element of an array, but their main purpose is different.

map() is used when I want to transform the elements and get a new array.

forEach() is mainly used when I simply want to perform some action for each element.

Example:

const numbers = [1, 2, 3];


Using map():

const doubled = numbers.map(num => num * 2);

console.log(doubled);
// [2, 4, 6]

map() returns a new array.


Using forEach():

numbers.forEach(num => {
    console.log(num * 2);
});

Here, forEach() performs the operation for each element but does not create and return a new array.


Important difference:

const result = numbers.forEach(num => num * 2);

console.log(result);
// undefined


Whereas:

const result = numbers.map(num => num * 2);

console.log(result);
// [2, 4, 6]


Comparison:

| Feature       | map()                         | forEach()                     |
|---------------|-------------------------------|-------------------------------|
| Purpose       | Transform elements            | Perform an action             |
| Returns       | New array                     | undefined                     |
| Creates array | Yes                           | No                            |
| Callback runs | For every element             | For every element             |
| Can chain     | Yes, because it returns array | Cannot directly chain result  |
| Best used for | Creating transformed data     | Side effects / actions        |


Example of forEach() being useful:

const users = ["Ajay", "Rahul", "Amit"];

users.forEach(user => {
    console.log("Welcome " + user);
});

Here, we aren't trying to create a new array. We simply want to perform an action for each user.


Interview-ready answer:

"The main difference is that map() is used when I want to transform an array and get a new array as the result, whereas forEach() is used when I simply want to perform an operation for each element. map() returns a new array, while forEach() returns undefined. So if I need transformed data, I use map(); if I just need to perform an action for every element, I generally use forEach()."

# What is the this keyword in JavaScript?

In JavaScript, this is a special keyword that refers to a particular object. or context associated with the current function execution.

 for a normal function, the value of this is mainly determined by how the function is called, not where the function was written.

So, instead of thinking "this always means the current object", think:

"this refers to the object determined by the way the function is invoked."


Example:

const person = {
    name: "Ajay",

    greet: function () {
        console.log(this.name);
    }
};

person.greet();

Output:
Ajay

Here, greet() is called as person.greet(), so this refers to person.

Therefore:

this.name
→ person.name
→ "Ajay"


Another example:

const person1 = {
    name: "Ajay",

    greet: function () {
        console.log(this.name);
    }
};

const person2 = {
    name: "Rahul",
    greet: person1.greet
};

person1.greet();    // Ajay
person2.greet();    // Rahul

The same function is being used, but this changes depending on the object that calls it.

That is why we say:

For a normal function, this depends on how the function is called.

Common this cases

1. Method call

const person = {
    name: "Ajay",

    greet() {
        console.log(this.name);
    }
};

person.greet();    // Ajay

this → person


2. Regular function call

function show() {
    console.log(this);
}

show();

In strict mode, this is undefined.

In a browser's non-strict global context, this can refer to the global window object.

For modern JavaScript, especially modules and strict-mode code, you should not assume that a regular function call gives you window.


3. Constructor call

When a normal function is called using new, this refers to the newly created object.

function Person(name) {
    this.name = name;
}

const person = new Person("Ajay");

console.log(person.name);    // Ajay

Here, this refers to the newly created person object.


4. Explicitly setting this

JavaScript provides call(), apply(), and bind() to explicitly control this.

function greet(city) {
    console.log(this.name + " from " + city);
}

const person = {
    name: "Ajay"
};

greet.call(person, "Bangalore");

Output:
Ajay from Bangalore

Here, call() explicitly makes this refer to person.


Important: Arrow Functions and this

Arrow functions are different.

An arrow function does not have its own this. It takes this from the surrounding lexical scope.

Example:

const person = {
    name: "Ajay",

    greet() {
        const sayHello = () => {
            console.log(this.name);
        };

        sayHello();
    }
};

person.greet();    // Ajay

The arrow function gets this from greet().

Because of this, call(), apply(), and bind() cannot change the this of an arrow function.

This is an important interview point.


Interview-ready answer:

"this is a special keyword in JavaScript whose value depends on the execution context. For a normal function, the value of this is determined mainly by how the function is called. For example, when a function is called as an object method, this refers to that object JavaScript also provides call(), apply(), and bind() to explicitly control this. Arrow functions are different because they don't have their own this; they inherit it from the surrounding scope."

#  What are call(), apply(), and bind()?

call(), apply(), and bind() are methods available on functions that allow us to explicitly control the value of this.

They are particularly useful when we want to reuse a function with a specific object as its "this" value.
Basically, call() lets us tell a function which object should be this.

We use call() when a function needs to work with the properties of a particular object by making that object the function's this
Example:

function greet(city, country) {
    console.log(this.name + " from " + city + ", " + country);
}

const person = {
    name: "Ajay"
};


1. call()

call() immediately invokes the function and allows us to specify this.

Arguments are passed individually.

Example:

greet.call(person, "Bangalore", "India");

Output:

Ajay from Bangalore, India


So:

call(thisValue, arg1, arg2, arg3)


2. apply()

apply() works almost the same way as call().

It immediately invokes the function and allows us to specify this.

The main difference is how arguments are passed.

apply() accepts the arguments as an array (more precisely, an array-like value).

Example:

greet.apply(person, ["Bangalore", "India"]);

Output:

Ajay from Bangalore, India


So:

apply(thisValue, [arg1, arg2, arg3])


3. bind()

bind() also allows us to specify this, but it does NOT immediately execute the function.

Instead, it returns a new function with this bound to the provided object.

Example:

const newGreet = greet.bind(person, "Bangalore", "India");

newGreet();

Output:

Ajay from Bangalore, India


So:

bind(thisValue, arg1, arg2, ...)

returns a new function.


Main Difference:

| Method | Sets this | Executes immediately? | Arguments |
|--------|-----------|------------------------|-----------|
| call() | Yes            | Yes            | Individually |
| apply() | Yes              | Yes             | Array/array-like |
| bind()    | Yes            | No             | Individually, and can be preset |


Simple way to remember:

call()
→ Call the function now.

apply()
→ Call the function now, but pass arguments as an array.

bind()
→ Bind this now, execute the returned function later.


Example showing all three:

function introduce(city) {
    console.log(this.name + " lives in " + city);
}

const person = {
    name: "Ajay"
};

introduce.call(person, "Bangalore");
// Ajay lives in Bangalore

introduce.apply(person, ["Bangalore"]);
// Ajay lives in Bangalore

const fn = introduce.bind(person, "Bangalore");

fn();
// Ajay lives in Bangalore


Partial Application with bind()

One useful feature of bind() is that we can preset arguments.

Example:

function multiply(a, b) {
    return a * b;
}

const double = multiply.bind(null, 2);

console.log(double(5));
// 10

Here, bind() has fixed the first argument as 2.

So:

double(5)

is effectively:

multiply(2, 5)


Interview-ready answer:

"call(), apply(), and bind() are function methods used to explicitly set the value of this. call() and apply() both execute the function immediately; the difference is that call() takes arguments individually, while apply() takes them as an array. bind() doesn't execute the function immediately. It returns a new function with this bound to the specified object, and it can also be used to preset arguments."

#  How are call(), apply(), and bind() related to this?

The connection is very simple:

Normally, the value of this is determined by how a regular function is called.

call(), apply(), and bind() give us a way to explicitly control that value.

Example:

const person = {
    name: "Ajay"
};

function greet() {
    console.log(this.name);
}


Without explicitly setting this:

greet();

The value of this depends on the way the function is called and the execution mode.


Using call():

greet.call(person);

Output:
Ajay

call() says:

"Execute greet() now, and use person as this."


Using apply():

greet.apply(person);

Output:
Ajay

apply() does the same thing regarding this; its main difference from call() is argument handling.


Using bind():

const newGreet = greet.bind(person);

newGreet();

Output:
Ajay

bind() says:

"Create a new function where this is permanently bound to person, and I'll execute that function later."


So the relationship is:

Normal function call
→ JavaScript determines this based on invocation.

call()
→ explicitly sets this and immediately calls the function.

apply()
→ explicitly sets this and immediately calls the function.

bind()
→ explicitly sets this and returns a new function for later execution.


Important Arrow Function Point

call(), apply(), and bind() cannot change the this of an arrow function because arrow functions don't have their own this.

Example:

const person = {
    name: "Ajay"
};

const greet = () => {
    console.log(this.name);
};

greet.call(person);

call() cannot make the arrow function's this refer to person.

The arrow function keeps the this value inherited from its surrounding lexical scope.


Interview-ready answer:

"call(), apply(), and bind() are directly related to this because they allow us to explicitly control the this value of a normal function. call() and apply() set this and immediately execute the function, while bind() sets this and returns a new function that can be executed later. The main difference between call() and apply() is how arguments are passed. One important exception is arrow functions: since arrow functions inherit this from their surrounding scope, call(), apply(), and bind() cannot change their this."
