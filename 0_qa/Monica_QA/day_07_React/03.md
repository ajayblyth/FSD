# 39. How do you handle API loading, success, and error states?

When a React component calls an API, there are normally three important states:

Loading
   ↓
API request is happening


Success
   ↓
Data received


Error
   ↓
Something went wrong
Interview answer

"I usually maintain separate loading, data, and error states. I set loading to true before the request, store the response data on success, and store an error message if the request fails. 

Finally, I set loading back to false in both success and failure cases."

Complete example

Let's create:

src/
├── components/
│   └── UserList.jsx
└── App.jsx

import { useEffect, useState } from "react";


function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");


  useEffect(() => {
    async function fetchUsers() {
      try {
        setLoading(true);
        setError("");


        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users"
        );


        if (!response.ok) {
          throw new Error("Failed to fetch users");
        }


        const data = await response.json();


        setUsers(data);


      } catch (error) {
        setError(error.message);
      } 
      finally {
        setLoading(false);
      }
    }


    fetchUsers();
  }, []);


  if (loading) {
    return <p>Loading users...</p>;

# 40. How do you cancel an API request in React?

Suppose the component starts an API request:

User opens /users
      ↓
Users component mounts
      ↓
useEffect runs
      ↓
API request starts
      ↓
User goes to /products
      ↓
Users component is removed
      ↓
Users component unmounts

Note:
Mount = component is added/appears in the UI.
Unmount = component is removed/disappears from the UI.


The request might still be running.

We can cancel a fetch() request using AbortController.

"I use AbortController with the Fetch API. I create an AbortController before starting the request and pass its signal to fetch. In the effect cleanup function, I call controller.abort() so the request is cancelled when the component unmounts or before a new request starts."

Complete example
src/components/UserList.jsx
import { useEffect, useState } from "react";


function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");


  useEffect(() => {
    const controller = new AbortController();


    async function fetchUsers() {
      try {
        setLoading(true);
        setError("");


        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users",
          {
            signal: controller.signal,
          }
        );


        if (!response.ok) {
          throw new Error("Failed to fetch users");
        }


        const data = await response.json();


        setUsers(data);
      } catch (error) {
        if (error.name === "AbortError") {
          console.log("Request was cancelled");
          return;
        }


        setError(error.message);
      } finally {
        setLoading(false);
      }
    }

    fetchUsers();


    return () => {
      controller.abort();
    };
  }, []);


  if (loading) {
    return <p>Loading...</p>;
  }


  if (error) {
    return <p>Error: {error}</p>;
  }


  return (
    <div>
      {users.map((user) => (
        <p key={user.id}>{user.name}</p>
      ))}
    </div>
  );
}


export default UserList;

Understand AbortController
We create:

const controller = new AbortController();

Then:

fetch(url, {
  signal: controller.signal,
});

This connects the request to the controller.

Then cleanup:

return () => {
  controller.abort();
};

means:

"Cancel this request when this effect is cleaned up."

Why do we check AbortError?

When we intentionally cancel the request:

controller.abort();

the fetch promise rejects.

But cancellation isn't really an application error.

So:

if (error.name === "AbortError") {
  return;
}

prevents us from displaying:

Error: The user cancelled the request

as though something went wrong.

Very important connection with useEffect

Remember:

useEffect(() => {


  // start request


  return () => {
    // cleanup
  };


}, []);

The cleanup runs when the component unmounts.

So:

Component mounts
    ↓
Effect runs
    ↓
Request starts
    ↓
Component unmounts
    ↓
Cleanup runs
    ↓
abort()

# 41. How do you handle API errors globally?

API errors can be handled globally at both the backend and frontend levels.

BACKEND:
I use Express error-handling middleware. If an error occurs in a controller, I pass it using next(error). The global error middleware catches it, logs it, and sends a consistent response with the appropriate HTTP status code and message.

FRONTEND:
I usually create one common Axios instance and use a response interceptor to handle common API errors in one place, like 401 Unauthorized, 403 Forbidden, token expiration, or 500 Server Error. If an error is specific to a particular screen, I handle that separately in the component.

The overall flow is:

Frontend
    ↓
Axios Request
    ↓
Backend API
    ↓
Controller
    ↓
Error occurs
    ↓
next(error)
    ↓
Global Error Middleware
    ↓
HTTP Error Response
    ↓
Axios Interceptor
    ↓
Component-specific handling if required

# 42. How do you implement pagination in React?

Pagination means:

Instead of loading all records at once, load a limited number of records for a particular page.

Example:

Page 1 → users 1–10
Page 2 → users 11–20
Page 3 → users 21–30

This reduces the amount of data loaded and rendered at once.

Typical API

A backend might support:

GET /users?page=1&limit=10

Meaning:

page = 1
limit = 10 users

Complete React example
Folder structure
src/
├── components/
│   └── UserPagination.jsx
└── App.jsx
src/components/UserPagination.jsx
import { useEffect, useState } from "react";


function UserPagination() {
  const [users, setUsers] = useState([]);
  const [page, setPage] = useState(1);
  const [loading, setLoading] = useState(false);


  const limit = 10;


  useEffect(() => {
    async function fetchUsers() {
      try {
        setLoading(true);


        const response = await fetch(
          `https://api.example.com/users?page=${page}&limit=${limit}`
        );


        if (!response.ok) {
          throw new Error("Failed to fetch users");
        }


        const data = await response.json();


        setUsers(data);
      } catch (error) {
        console.error(error);
      } finally {
        setLoading(false);
      }
    }


    fetchUsers();
  }, [page]);


  return (
    <div>
      <h2>Users - Page {page}</h2>


      {loading ? (
        <p>Loading...</p>
      ) : (
        users.map((user) => (
          <p key={user.id}>{user.name}</p>
        ))
      )}


      <button
        disabled={page === 1 || loading}
        onClick={() => setPage(page - 1)}
      >
        Previous
      </button>


      <span> Page {page} </span>


      <button
        disabled={loading}
        onClick={() => setPage(page + 1)}
      >
        Next
      </button>
    </div>
  );
}


export default UserPagination;

# 43. How do you implement infinite scrolling in React?


Infinite scrolling means:

Instead of showing page buttons, we automatically load the next set of data when the user reaches near the bottom of the page.

Example:

Load page 1
     ↓
User scrolls
     ↓
Near bottom
     ↓
Load page 2
     ↓
Append page 2
     ↓
User continues
     ↓
Load page 3

Important difference from pagination

Pagination:

Page 1
[Next]
   ↓
Page 2 replaces Page 1


Infinite scrolling:

Page 1
   ↓
Page 2 appended
   ↓
Page 3 appended

So we normally do:

setUsers((previousUsers) => [
  ...previousUsers,
  ...newUsers
]);

rather than:

setUsers(newUsers);
Better way: Intersection Observer

Instead of manually listening to every scroll event, we can use the browser's Intersection Observer API.

The idea:

sentinel element
      ↓
comes into viewport
      ↓
load next page

//A sentinel element is simply a small, usually invisible element that we place at the end of a list to detect when the user has reached the bottom.

# 44. How do you handle form validation in React?

1. First understand the problem

Suppose we have a registration form:

Name:     __________
Email:    __________
Password: __________


           [Register]

Before sending this data to the backend, we may want to check:

Name is not empty
Email has a valid format
Password has minimum length
Password and confirm password match

This is form validation.

There are two main places where validation can happen:

React/frontend
      ↓
Basic validation
      ↓
Backend
      ↓
Final/secure validation
Important

Frontend validation improves the user experience, but it is not enough for security.

A user can bypass React completely and send a request directly to your API.

So:

Frontend validation = user experience

Backend validation = actual protection

2. How do we validate in React?

The simplest approach is to keep the form values in state.

For example:

const [email, setEmail] = useState("");

When the user types:

<input
  value={email}
  onChange={(e) => setEmail(e.target.value)}
/>

React always knows the current value.

Then when the user submits:

const handleSubmit = (e) => {
  e.preventDefault();


  if (!email) {
    // show error
  }
};

We can store validation errors in another state:

const [errors, setErrors] = useState({});

For example:

{
  email: "Email is required",
  password: "Password must be at least 6 characters"
}
3. Complete example

A simple React form:

Folder structure
src/
├── App.jsx
└── main.jsx

No additional package is required.

src/App.jsx
import { useState } from "react";


function App() {
  const [formData, setFormData] = useState({
    name: "",
    email: "",
    password: "",
  });


  const [errors, setErrors] = useState({});


  const handleChange = (e) => {
    const { name, value } = e.target;


    setFormData({
      ...formData,
      [name]: value,
    });
  };


  const validate = () => {
    const newErrors = {};


    if (!formData.name.trim()) {
      newErrors.name = "Name is required";
    }


    if (!formData.email.trim()) {
      newErrors.email = "Email is required";
    } else if (!formData.email.includes("@")) {
      newErrors.email = "Enter a valid email";
    }


    if (!formData.password) {
      newErrors.password = "Password is required";
    } else if (formData.password.length < 6) {
      newErrors.password = "Password must be at least 6 characters";
    }


    return newErrors;
  };


  const handleSubmit = (e) => {
    e.preventDefault();


    const validationErrors = validate();


    if (Object.keys(validationErrors).length > 0) {
      setErrors(validationErrors);
      return;
    }


    setErrors({});


    console.log("Form submitted:", formData);
  };


  return (
    <div>
      <h2>Registration Form</h2>


      <form onSubmit={handleSubmit}>
        <div>
          <label>Name:</label>


          <input
            type="text"
            name="name"
            value={formData.name}
            onChange={handleChange}
          />


          {errors.name && <p>{errors.name}</p>}
        </div>


        <div>
          <label>Email:</label>


          <input
            type="email"
            name="email"
            value={formData.email}
            onChange={handleChange}
          />


          {errors.email && <p>{errors.email}</p>}
        </div>


        <div>
          <label>Password:</label>


          <input
            type="password"
            name="password"
            value={formData.password}
            onChange={handleChange}
          />


          {errors.password && <p>{errors.password}</p>}
        </div>


        <button type="submit">Register</button>
      </form>
    </div>
  );
}


export default App;

# 45. How do you upload a file from React to a backend?

This is another practical question.

The basic flow is:

User selects file
       ↓
<input type="file">
       ↓
React gets File object
       ↓
FormData
       ↓
POST request
       ↓
Backend receives file
       ↓
Store file / cloud storage

1. Getting the selected file

We use:

<input type="file" />

When the user selects a file:

const file = e.target.files[0];

files[0] gives us the selected File object.

2. Why FormData?

We normally don't send a file as normal JSON.

Instead, we use:

const formData = new FormData();

Then:

formData.append("file", file);

Now the file can be sent using fetch.

3. Complete React example
Folder structure
src/
├── App.jsx
└── main.jsx

No additional package is required for the basic implementation.

src/App.jsx
import { useState } from "react";


function App() {
  const [file, setFile] = useState(null);
  const [message, setMessage] = useState("");


  const handleFileChange = (e) => {
    setFile(e.target.files[0]);
  };


  const handleUpload = async () => {
    if (!file) {
      setMessage("Please select a file");
      return;
    }


    const formData = new FormData();


    formData.append("file", file);


    try {
      const response = await fetch("http://localhost:8080/api/upload", {
        method: "POST",
        body: formData,
      });


      if (!response.ok) {
        throw new Error("Upload failed");
      }


      setMessage("File uploaded successfully");
    } catch (error) {
      setMessage("Something went wrong");
    }
  };


  return (
    <div>
      <h2>File Upload</h2>


      <input
        type="file"
        onChange={handleFileChange}
      />


      <button onClick={handleUpload}>
        Upload
      </button>


      <p>{message}</p>
    </div>
  );
}


export default App;

4. Important lines
Getting the file
const file = e.target.files[0];

The browser gives us a FileList.

We take the first selected file.

Creating FormData
const formData = new FormData();

FormData is a browser-provided JavaScript API for constructing data that can be sent as multipart/form-data.

Adding the file
formData.append("file", file);

Here:

"file" → field name expected by backend
file   → actual File object

The backend must use the same field name.

Sending it
fetch("http://localhost:8080/api/upload", {
  method: "POST",
  body: formData,
});

Notice something important:

We don't manually set Content-Type.

Don't do:

headers: {
  "Content-Type": "multipart/form-data"
}

The browser automatically sets the correct multipart boundary when sending FormData.

5. What does the backend do?

For example, with a Spring Boot backend, the endpoint could receive:

@PostMapping("/upload")
public String upload(@RequestParam("file") MultipartFile file) {
    // save file
    return "Uploaded";
}

The complete flow becomes:

React
  │
  │ FormData
  ▼
POST /api/upload
  │
  ▼
Spring Boot
  │
  │ MultipartFile
  ▼
Save file
  │
  ├── Local storage
  └── AWS S3 / cloud storage

This is especially common in applications where users upload profile pictures, documents, hotel images, etc.

6. Multiple files

If multiple files are allowed:

<input
  type="file"
  multiple
  onChange={handleFileChange}
/>

Then:

const files = e.target.files;

We can append them:

for (const file of files) {
  formData.append("files", file);
}
Interview answer

"For file uploads in React, I use an input of type file to get the selected File object. Then I create a FormData object, append the file to it, and send it to the backend using a POST request, usually with multipart/form-data. The backend receives the file and can store it locally or upload it to cloud storage such as S3. I also validate things like file type and size before uploading."

Cross-questions
Q: Why use FormData instead of JSON?

Because files are binary data and are normally uploaded using multipart/form-data, whereas JSON is mainly used for structured text data.

Q: Can we send JSON and a file together?

Yes, commonly through multipart/form-data.

For example:

file → image.jpg
data → {"username":"Ajay"}

The backend can receive both parts.

Q: Where should file validation happen?

Both places:

Frontend → better user experience
Backend  → security and actual enforcement

For example:

maximum file size
allowed extensions/MIME types
malicious files

The backend must not blindly trust the frontend.

Q: Where would you store uploaded files?

For production applications, commonly:

React
  ↓
Backend
  ↓
AWS S3 / Cloud storage

Rather than storing large files directly inside the database.
