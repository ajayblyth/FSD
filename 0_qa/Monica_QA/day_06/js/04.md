# 16. Regular Expressions (Regex)

A regular expression is a pattern used to search, match, extract, or validate text.

JavaScript provides the RegExp object and also supports regex literal syntax.

### Basic syntax

const pattern = /hello/;

This checks whether "hello" appears in a string.

const text = "Hello, hello";

console.log(/hello/.test(text));

Output:

true


## Common Regex Methods

## 1. test()

test() checks whether a pattern matches a string and returns true or false.

Example:

const pattern = /javascript/i;

console.log(pattern.test("I love JavaScript"));

Output:

true

Here, i means case-insensitive, so JavaScript and javascript are treated as a match.

### Interview point

test() is commonly useful when we only need to know whether a string matches a particular pattern.


## 2. match()

match() returns information about the matching text.

Example:

const text = "I have 123 apples";

console.log(text.match(/\d+/));

Here:

\d → digit
+  → one or more

So \d+ means one or more digits.

The matching value is:

123

### Interview point

match() is useful when we want to retrieve the matching text rather than just get true or false.


## 3. replace()

replace() is used to replace matching text.

Example:

const text = "Hello World";

const result = text.replace(/World/, "Ajay");

console.log(result);

Output:

Hello Ajay


## Important Regex Characters

You don't need to memorize hundreds of regex patterns for normal interviews. These are the important ones:

\d      → digit
\w      → word character
\s      → whitespace
.       → any character except line terminators in normal mode
+       → one or more
*       → zero or more
?       → zero or one
^       → start of string/line depending on flags
$       → end of string/line depending on flags
[abc]   → a, b, or c
[^abc]  → anything except a, b, or c
{3}     → exactly 3
{3,5}   → between 3 and 5


## Example: 10-Digit Validation

const pattern = /^\d{10}$/;

Meaning:

^       → start of string
\d      → digit
{10}    → exactly 10 digits
$       → end of string

So the entire string must contain exactly 10 digits.

console.log(/^\d{10}$/.test("9876543210")); // true
console.log(/^\d{10}$/.test("12345"));      // false

The ^ and $ are important here because they make sure the entire string matches the pattern.


## Common Regex Flags

i → case-insensitive
g → global, find all matches
m → multiline

Example:

const text = "cat Cat CAT";

console.log(text.match(/cat/gi));

Output:

["cat", "Cat", "CAT"]

Here:

i → ignores case
g → finds all matches instead of stopping at the first match.


## Interview Answer

If asked "What is Regular Expression?", you can say:

Regular expressions are patterns used to search, match, extract, or validate text. JavaScript supports regex literals and the RegExp object. Methods like test(), match(), and replace() are commonly used for checking, extracting, and replacing text. Common flags include i for case-insensitive matching and g for finding all matches.

For normal interviews, you don't need to memorize complex regex patterns unless the project involves heavy text processing.



# Date



JavaScript provides the built-in Date object for working with dates and times.

It allows us to create dates, retrieve date/time components, compare dates, get timestamps, and format dates.


## Creating a Date

## 1. Current date and time

const now = new Date();

console.log(now);

This creates a Date object containing the current date and time.


## 2. Specific date

const date = new Date("2026-08-14");

console.log(date);

Here we create a Date object from a date string.


## 3. Using date components

const date = new Date(2026, 7, 14);

Important:

Months are zero-based in the multi-argument Date constructor.

0  → January
1  → February
2  → March
...
7  → August

Therefore:

new Date(2026, 7, 14)

represents August 14, 2026.


## Common Date Methods

const date = new Date();

date.getFullYear();
date.getMonth();
date.getDate();
date.getDay();
date.getHours();
date.getMinutes();
date.getSeconds();

These methods retrieve different parts of the date.


## Important Difference: getDate() vs getDay()

This is a common interview question.

getDate()
→ Returns the day of the month.

Example:

date.getDate(); // 14

This means the date is the 14th day of the month.


getDay()
→ Returns the day of the week.

0 → Sunday
1 → Monday
2 → Tuesday
3 → Wednesday
4 → Thursday
5 → Friday
6 → Saturday

So:

getDate() → 14th day of the month
getDay()  → Friday, for example


## UTC Methods

JavaScript also provides UTC versions of many Date methods.

date.getUTCFullYear();
date.getUTCMonth();
date.getUTCDate();

These return the corresponding components using UTC instead of the local timezone.

This is important when working with APIs, servers, and users in different time zones.


## Date.now()

Date.now() returns the current timestamp in milliseconds.

Example:

console.log(Date.now());

The exact number changes continuously because it represents the current point in time.

A timestamp is useful when we need to compare or calculate time.

For example:

const start = Date.now();

// some operation

const end = Date.now();

console.log(end - start);

The difference gives the approximate elapsed time in milliseconds.


## getTime()

We can also get the timestamp from a Date object:

const date = new Date();

console.log(date.getTime());

getTime() returns the number of milliseconds since the Unix epoch.

The Unix epoch is:

January 1, 1970, 00:00:00 UTC


## Formatting a Date

A commonly used method is toISOString():

const date = new Date();

console.log(date.toISOString());

Example output:

2026-08-14T10:30:00.000Z

toISOString() returns a standardized ISO 8601 string in UTC.

The Z at the end indicates UTC.

This format is commonly used when sending date/time information through APIs.


## Date Parsing

Be careful when parsing date strings.

Example:

const date = new Date("2026-08-14");

JavaScript date parsing and timezone behavior can sometimes cause surprises depending on the input format and how the date is interpreted.

For APIs and distributed applications, it is better to use a clear standardized format such as ISO 8601 and be explicit about timezone expectations.


## Date Comparison

Dates can be compared because Date objects can be converted to their numeric timestamps.

Example:

const date1 = new Date("2026-08-10");
const date2 = new Date("2026-08-14");

console.log(date2 > date1);

Output:

true

We can also explicitly compare timestamps:

console.log(date2.getTime() > date1.getTime());

Output:

true


## Interview Answer

If asked "How do you work with dates in JavaScript?", you can say:

JavaScript provides the built-in Date object for creating and manipulating dates and times. We can create dates using the current time, date strings, or individual components. Methods like getFullYear(), getMonth(), and getDate() retrieve local date components, while UTC methods retrieve UTC components. Date.now() and getTime() provide timestamps in milliseconds, and toISOString() is commonly used to represent dates in a standardized UTC format for APIs.


## Important Things to Remember

# Currying

Currying is a functional programming concept that tests your understanding of functions, closures, and returning functions.

What is Currying?

Basically, currying converts a function that takes multiple arguments into a sequence of functions, where each function takes one argument.

Normal function:

function add(a, b, c) {
    return a + b + c;
}

add(10, 20, 30);

Here, we pass all three arguments at once.

With currying:

function add(a) {
    return function (b) {
        return function (c) {
            return a + b + c;
        };
    };
}

console.log(add(10)(20)(30));

Output:

60

The flow is:

add(10)
   ↓
returns function(b)

(20)
   ↓
returns function(c)

(30)
   ↓
returns 60


Why does this work?

Because of closures.

When:

add(10)

runs, the returned function remembers a = 10.

Then:

(20)

returns another function that remembers both:

a = 10
b = 20

Finally:

(30)

can access all three values.

So:

Currying commonly relies on closures to preserve previously supplied arguments.


Practical Example

Suppose you have:

function multiply(a, b) {
    return a * b;
}

You can create a curried version:

function multiply(a) {
    return function (b) {
        return a * b;
    };
}

Now:

const double = multiply(2);

console.log(double(5));   // 10
console.log(double(10));  // 20

This is useful because we've created a specialized function.

multiply(2)
     ↓
returns function(b)
     ↓
double(5)
     ↓
2 × 5
     ↓
10


Currying with Arrow Functions

The same thing can be written more compactly:

const add = a => b => c => a + b + c;

console.log(add(10)(20)(30));

Output:

60

Don't just memorize this syntax.

Understand that each arrow function returns another function.

The above code is basically equivalent to:

function add(a) {
    return function (b) {
        return function (c) {
            return a + b + c;
        };
    };
}


Currying vs Partial Application

These are sometimes confused.

Currying

Converts:

f(a, b, c)

into:

f(a)(b)(c)

The function structure itself is changed into a sequence of functions.

Partial Application

Pre-fills some arguments and returns a function for the remaining ones.

Example:

function multiply(a, b) {
    return a * b;
}

const double = (b) => multiply(2, b);

console.log(double(5)); // 10

Here we've fixed:

a = 2

and created a new function that only needs b.

So:

Currying transforms the function structure, while partial application fixes some arguments to create a specialized function.


Interview Answer

If asked "What is currying?", say:

"Currying is a technique where a function that normally accepts multiple arguments is transformed into a sequence of functions, with each function accepting one argument. It is commonly implemented using closures, because each returned function needs to remember the arguments provided earlier."


# Memoization

Memoization is mainly about performance optimization.

What is Memoization?

Basically, memoization is a technique where we cache the result of an expensive function call so that if the same input occurs again, we can return the cached result instead of calculating it again.

Example:

function square(n) {
    console.log("Calculating...");
    return n * n;
}

If we call:

square(5);
square(5);

the calculation happens twice.

With memoization:

function memoize(fn) {
    const cache = new Map();

    return function (value) {
        if (cache.has(value)) {
            return cache.get(value);
        }

        const result = fn(value);

        cache.set(value, result);

        return result;
    };
}

Now:

function square(n) {
    console.log("Calculating...");
    return n * n;
}

const memoizedSquare = memoize(square);

console.log(memoizedSquare(5));
console.log(memoizedSquare(5));

Output:

Calculating...
25
25

"Calculating..." is printed only once.


How does it work?

First call:

memoizedSquare(5)
       ↓
Check cache
       ↓
5 is not present
       ↓
Calculate 5 × 5
       ↓
25
       ↓
Store 5 → 25 in cache
       ↓
Return 25

Second call:

memoizedSquare(5)
       ↓
Check cache
       ↓
5 is already present
       ↓
Return 25 directly

The calculation is skipped.


Why use Memoization?

It's useful when:

- A function is expensive to calculate.
- The same inputs occur repeatedly.
- The function is pure, meaning the same input should produce the same output.

For example:

fibonacci(40)

can involve a lot of repeated calculations.

Caching previous results can significantly improve performance because already calculated values can be reused.


Memoization and Closures

Notice this:

function memoize(fn) {
    const cache = new Map();

    return function (value) {
        // cache is accessible here
    };
}

The returned function remembers the cache even after memoize() has finished executing.

That's a closure.

So:

Closure
   ↓
Keeps cache accessible
   ↓
Memoization
   ↓
Reuse previous results


Important Limitation

Memoization isn't automatically beneficial for every function.

It has a cost:

Memory
   ↑
because results are stored in cache

If you cache unlimited unique inputs, the cache itself can grow significantly.

For example:

memoizedFunction(1);
memoizedFunction(2);
memoizedFunction(3);
...
memoizedFunction(1000000);

You could end up retaining a large amount of data.

So:

Memoization is a trade-off between computation time and memory usage.

We use more memory to avoid repeated calculations.


Currying vs Memoization

They solve completely different problems.

Currying:
→ Function transformation
→ Breaks arguments into multiple calls
→ Often uses closures
→ Example: add(a)(b)(c)

Memoization:
→ Performance optimization
→ Caches previous results
→ Often uses closures
→ Example: input → cached result


Interview Answers

What is memoization?

"Memoization is a performance optimization technique where we cache the result of a function based on its input and reuse that result when the same input occurs again. It's especially useful for expensive and pure functions, but it increases memory usage because the cached results need to be stored."

What is the relationship between currying and closures?

"In currying, each returned function can remember previously supplied arguments through closures. For example, after calling add(10), the returned function retains access to 10 even though the outer function has already finished."

# Debouncing vs Throttling

This is a high-value practical interview topic, especially if you're working with frontend applications, APIs, search boxes, scrolling, resizing, etc.

Both are techniques used to control how frequently a function executes when an event happens repeatedly.

1. Debouncing
Definition

Debouncing ensures that a function executes only after the events have stopped occurring for a specified amount of time.

In simple words:

"Wait until the user stops, then execute."

Example: Search box

Suppose the user types:

J
Ja
Jav
Java
JavaS
JavaSc
JavaScr

Without debouncing, you might send an API request for every keystroke.

J       → API call
Ja      → API call
Jav     → API call
Java    → API call
...

That's unnecessary.

With debouncing, we wait, for example, 500 ms after the last keystroke.

J
Ja
Jav
Java
JavaScript
          ↓
     user stops typing
          ↓
       500ms
          ↓
       API call
2. How Debouncing Works

Basic implementation:

function debounce(fn, delay) {
    let timer;

    return function (...args) {
        clearTimeout(timer);

        timer = setTimeout(() => {
            fn.apply(this, args);
        }, delay);
    };
}

Usage:

function search(value) {
    console.log("API call:", value);
}

const debouncedSearch = debounce(search, 500);

debouncedSearch("J");
debouncedSearch("Ja");
debouncedSearch("Jav");
debouncedSearch("Java");

Every new call clears the previous timer.

Only after 500 ms of no new call does search() execute.

3. Why clearTimeout()?

Suppose:

Call 1 → timer starts
Call 2 → previous timer cancelled
Call 3 → previous timer cancelled
Call 4 → previous timer cancelled

Only the final timer survives.

Final call
    ↓
wait 500ms
    ↓
execute

That's the core idea of debouncing.

4. Common Debouncing Use Cases

Use debouncing when you care about the final action after a burst of events.

Common examples:

Search input/API calls
Auto-save
Form validation
Window resize
Filtering user input

Example:

User typing → wait → API call

# Throttling
Definition

Throttling ensures that a function executes at most once during a specified time interval, even if the event keeps occurring continuously.

In simple words:

"Execute at a controlled rate."

For example, throttle to once every 1 second:

Event Event Event Event Event Event
 ↓
Function
 ↓
wait 1 sec
 ↓
Function
 ↓
wait 1 sec
 ↓
Function

The events can continue happening, but the function execution is limited.

6. Basic Throttle Implementation
function throttle(fn, delay) {
    let lastCall = 0;

    return function (...args) {
        const now = Date.now();

        if (now - lastCall >= delay) {
            lastCall = now;
            fn.apply(this, args);
        }
    };
}

Usage:

function handleScroll() {
    console.log("Scroll handled");
}

const throttledScroll = throttle(handleScroll, 1000);

Even if the scroll event fires hundreds of times, handleScroll() executes at most once per second with this simple implementation.

7. Debounce vs Throttle

This is the most important part to remember.

Good for auto-save	Good for mouse movement
Good for final resize calculation	Good for continuous position tracking

9. Important Interview Question
Can you explain debounce with setTimeout?

Good answer:

Debouncing uses a timer to delay execution. Every time the event occurs, we clear the previous timer and create a new one. Therefore, the function executes only when no new event occurs for the specified delay.

Explain throttling?

Throttling limits how frequently a function can execute. Even if an event fires continuously, the function is allowed to execute only once during the specified interval.

10. Debouncing and Closures

Notice our debounce implementation:

function debounce(fn, delay) {
    let timer;

    return function (...args) {
        clearTimeout(timer);

        timer = setTimeout(() => {
            fn.apply(this, args);
        }, delay);
    };
}

The returned function remembers:

fn
delay
timer

even after debounce() has finished.

That's because of a closure.

This is a good interview connection:

Debouncing is commonly implemented using closures because the returned function needs to retain the timer between calls.

11. Why ...args and apply()?

In:

return function (...args) {
    ...
    fn.apply(this, args);
};

...args collects all arguments passed to the returned function.

For example:

debouncedSearch("JavaScript");

means:

args = ["JavaScript"]

apply() then calls the original function with:

this → original context
args → arguments array

This makes the debounce utility reusable with different functions and arguments.

Interview Answer

If the interviewer asks:

"What is the difference between debounce and throttle?"

Say:

Both are techniques to control the frequency of function execution. Debouncing delays execution until the events stop for a specified period, so it's useful for things like search inputs and auto-save. Throttling limits execution to at most once within a specified interval, so it's useful for continuous events like scrolling, mouse movement, or window resizing.

One-line memory trick:
Debounce  → "Wait until it stops."
Throttle  → "Limit how often it runs."
