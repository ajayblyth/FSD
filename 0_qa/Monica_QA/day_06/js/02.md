# Error Handling 


JavaScript provides error handling mechanisms so we can detect, handle, and respond to runtime errors without crashing the entire application unexpectedly.

The main concepts are:

try
catch
finally
throw
Custom errors
1. try and catch

Put code that might produce an error inside try.

If an error occurs, JavaScript transfers control to catch.

try {
    const result = 10 / 0;
    console.log(result);
} catch (error) {
    console.log("Something went wrong");
}

A more realistic example:

try {
    const data = JSON.parse("invalid json");
    console.log(data);
} catch (error) {
    console.log("Invalid JSON");
}

The catch block receives the error object.

catch (error) {
    console.log(error.name);
    console.log(error.message);
}

For example:

SyntaxError
Unexpected token...
2. finally

finally executes whether an error occurs or not.

try {
    console.log("Trying");
} catch (error) {
    console.log("Error");
} finally {
    console.log("Cleanup");
}

Output:

Trying
Cleanup

If an error occurs:

try {
    throw new Error("Something failed");
} catch (error) {
    console.log(error.message);
} finally {
    console.log("Cleanup");
}

Output:

Something failed
Cleanup
Common use

finally is useful for cleanup operations, such as:

Closing a resource
Resetting loading state
Releasing something after an operation
3. throw

throw allows us to manually generate an error.

throw new Error("Something went wrong");

You can throw an error based on a condition:

function withdraw(balance, amount) {
    if (amount > balance) {
        throw new Error("Insufficient balance");
    }

    return balance - amount;
}

Then handle it:

try {
    console.log(withdraw(1000, 1500));
} catch (error) {
    console.log(error.message);
}

Output:

Insufficient balance
4. Error Object

JavaScript provides the Error object.

const error = new Error("Something went wrong");

console.log(error.name);
console.log(error.message);
console.log(error.stack);

Typical properties:

name
message
stack

stack is particularly useful for debugging because it shows where the error occurred.

5. Custom Errors

We can create our own error types by extending Error.

class ValidationError extends Error {
    constructor(message) {
        super(message);
        this.name = "ValidationError";
    }
}

Now:

function registerUser(age) {
    if (age < 18) {
        throw new ValidationError("User must be 18 or older");
    }

    return "Registration successful";
}

Handling it:

try {
    registerUser(16);
} catch (error) {
    if (error instanceof ValidationError) {
        console.log("Validation failed:", error.message);
    } else {
        console.log("Unexpected error:", error);
    }
}

This is useful when different errors need different handling.

6. try...catch with async/await

This is especially important in modern JavaScript.

async function getUsers() {
    try {
        const response = await fetch("/users");
        const users = await response.json();

        console.log(users);
    } catch (error) {
        console.log("Failed to fetch users:", error);
    }
}

If the asynchronous operation rejects, the catch block handles it.

This is commonly used when working with APIs.

Important Interview Point: throw vs return

Don't confuse them.

return

Returns a value normally:

function test() {
    return "Hello";
}
throw

Stops normal execution and signals an error:

function test() {
    throw new Error("Something failed");
}

The caller can handle it using try...catch.

Important: finally Executes Almost Always

For interview purposes, say:

finally executes regardless of whether an error occurs or not.

But there's an advanced point:

function test() {
    try {
        return 10;
    } finally {
        console.log("Finally");
    }
}

Output:

Finally

The finally block runs before the function actually returns.

The return value is still:

10

Also, avoid putting return inside finally, because it can override a previous return or even suppress an exception.

Interview Answer

If asked "How does error handling work in JavaScript?", you can say:

JavaScript uses try, catch, finally, and throw for error handling. We put potentially failing code inside try, handle the error in catch, and use finally for cleanup code that should run regardless of success or failure. We can use throw to manually generate errors, and for application-specific cases we can create custom error classes by extending the built-in Error class. With async/await, rejected asynchronous operations can also be handled using try-catch.

Quick mental model
try
 ↓
Code that might fail
 ↓
 ┌───────────────┐
 │ Error?        │
 └───────────────┘
      ↓ yes
    catch
      ↓
   Handle error
      ↓
   finally
      ↓
    Cleanup


# ES6+ Important Features

You've already covered several ES6 features earlier, so here we'll focus on the remaining ones from your list and make sure the interview-level understanding is clear.

## 1. Template Literals

Template literals use **backticks** `` ` ` `` instead of quotes. They allow us to embed expressions directly using `${}`.

const name = "Ajay";
const age = 25;

console.log(`My name is ${name} and I am ${age} years old.`);

Output:

My name is Ajay and I am 25 years old.

This is called **string interpolation**.

You can also write multiline strings:

const message = `
Hello Ajay,
Welcome to JavaScript.
`;

### Interview Answer

> **Template literals use backticks and allow string interpolation using `${}`. They also support multiline strings, making them more convenient than traditional string concatenation.**

---

# 2. Default Parameters

Default parameters allow us to provide a default value when an argument is **not provided or is explicitly `undefined`**.

function greet(name = "Guest") {
    console.log(`Hello ${name}`);
}

greet("Ajay");
greet();

Output:

Hello Ajay
Hello Guest

Important:

greet(undefined); // Guest

But:

greet(null); // null

`null` does **not** trigger the default value.

### Interview Point

> **Default parameters are used when the corresponding argument is `undefined` or not provided.**

---

# 3. Optional Chaining `?.`

Optional chaining allows us to safely access properties when an intermediate value might be `null` or `undefined`.

Without it:

const user = {};

console.log(user.address.city);

This throws:

TypeError

because `user.address` is `undefined`.

With optional chaining:

console.log(user.address?.city);

Result:

undefined

No error is thrown.

### Nested Example

const user = {
    address: {
        city: "Bangalore"
    }
};

console.log(user.address?.city);

Output:

Bangalore

You can also use it with functions:

user.getName?.();

This means:

> Call `getName()` only if it exists and is callable.

### Interview Answer

> **Optional chaining `?.` allows us to safely access properties, methods, or array elements when an intermediate value may be null or undefined. Instead of throwing a TypeError, it returns undefined.**

---

# 4. Nullish Coalescing `??`

`??` provides a fallback value when the left side is specifically:

null
undefined

Example:

const name = null;

console.log(name ?? "Guest");

Output:

Guest

But:

const age = 0;

console.log(age ?? 18);

Output:

0

This is important because `??` **doesn't treat all falsy values as missing**.

## `??` vs `||`

A very common interview question:

const value = 0;

console.log(value || 10); // 10
console.log(value ?? 10); // 0

Why?

`||` checks for **falsy** values:

false
0
""
null
undefined
NaN

`??` checks only:

null
undefined

### Practical Example

Suppose `0` is a valid value:

const quantity = 0;

const result = quantity ?? 1;

Result is `0`.

That's often what we want.

---

# 5. Modules — `import` / `export`

Modules allow us to split JavaScript code into separate files and share functionality between them.

### Export — `math.js`

export function add(a, b) {
    return a + b;
}

### Import — `app.js`

import { add } from "./math.js";

console.log(add(10, 20));

## Named Export

export const name = "Ajay";
export function greet() {}

Import:

import { name, greet } from "./user.js";

## Default Export

export default function greet() {
    console.log("Hello");
}

Import:

import greet from "./user.js";

With a default export, the importing name doesn't have to match the original name.

### Named vs Default

| Named Export                 | Default Export            |
| ---------------------------- | ------------------------- |
| Can have multiple per file   | One default per module    |
| Import uses `{}`             | No `{}`                   |
| Import name normally matches | Import name can be chosen |

---

# 6. Iterators

An **iterator** is an object that provides a way to access values one at a time.

It follows the iterator protocol, which requires a `next()` method.

const numbers = [10, 20, 30];

const iterator = numbers[Symbol.iterator]();

console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());

Result conceptually:

{ value: 10, done: false }
{ value: 20, done: false }
{ value: 30, done: false }
{ value: undefined, done: true }

The important properties are:

value → current value
done  → whether iteration is finished

Arrays, strings, Maps, and Sets are examples of **iterable objects**.

---

# 7. Generators

Generators provide a convenient way to create iterators.

A generator function uses:

function*

and `yield`.

Example:

function* numbers() {
    yield 10;
    yield 20;
    yield 30;
}

const generator = numbers();

console.log(generator.next());
console.log(generator.next());
console.log(generator.next());
console.log(generator.next());

Output:

{ value: 10, done: false }
{ value: 20, done: false }
{ value: 30, done: false }
{ value: undefined, done: true }

## What Makes `yield` Different?

`yield` **pauses the generator's execution**.

function* test() {
    console.log("First");

    yield 10;

    console.log("Second");

    yield 20;

    console.log("Third");
}

When:

const gen = test();

the function doesn't execute all the way through.

Then:

gen.next();

runs until the first `yield`.

Next:

gen.next();

continues from where it paused.

So:

next()
 ↓
run
 ↓
yield
 ↓
pause
 ↓
next()
 ↓
resume

---

# Iterator vs Generator

Worth remembering.

### Iterator

An object that follows the iterator protocol:

{
    next() {
        return {
            value: ...,
            done: ...
        };
    }
}

### Generator

A convenient way to create an iterator:

function* generator() {
    yield 1;
    yield 2;
}

So:

> **Every generator produces an iterator, but not every iterator is created using a generator.**

## Interview Summary

If asked about these ES6+ features, you can say:

> **Template literals provide interpolation and multiline strings. Default parameters provide fallback values for undefined arguments. Optional chaining safely accesses potentially missing properties, while nullish coalescing provides a fallback specifically for null or undefined. ES modules allow us to organize code using import and export. Iterators provide a standard way to retrieve values one at a time, while generators provide a convenient way to create iterators using `function*` and `yield`.**

# Map, Set, WeakMap, WeakSet

These are collection data structures in JavaScript. The main difference is how they store data and what kind of values they allow.

---

## 1. Map

A Map stores data as key-value pairs, similar to an object, but it has some important differences.

const userMap = new Map();

userMap.set("name", "Ajay");
userMap.set("age", 25);

console.log(userMap.get("name")); // Ajay
console.log(userMap.get("age"));  // 25

### Important Map methods

map.set(key, value)
map.get(key)
map.has(key)
map.delete(key)
map.clear()
map.size

Example:

const users = new Map();

users.set(1, "Ajay");
users.set(2, "Rahul");

console.log(users.has(1));    // true
console.log(users.get(2));    // Rahul
console.log(users.size);      // 2

---

## Why use Map instead of Object?

A Map can use any value as a key.

const map = new Map();

const user = { id: 1 };

map.set(user, "Ajay");

console.log(map.get(user)); // Ajay

The object itself is the key.

With a normal object, keys are generally strings or symbols.

---

### Map maintains insertion order

const map = new Map();

map.set("a", 1);
map.set("b", 2);
map.set("c", 3);

for (const [key, value] of map) {
    console.log(key, value);
}

Output follows insertion order:

a 1
b 2
c 3

### Interview answer

Map is a collection of key-value pairs where keys can be of any type. It provides methods like set, get, has, and delete, maintains insertion order, and is useful when we need dynamic key-value storage.

---

# 2. Set

A Set stores unique values.

const numbers = new Set();

numbers.add(10);
numbers.add(20);
numbers.add(10);

console.log(numbers);

Result:

Set { 10, 20 }

The duplicate 10 is ignored.

### Common methods

set.add(value)
set.has(value)
set.delete(value)
set.clear()
set.size

Example:

const skills = new Set(["Java", "JavaScript"]);

skills.add("React");
skills.add("Java");

console.log(skills.size); // 3

---

## Common use: Remove duplicates

const numbers = [1, 2, 2, 3, 3, 4];

const uniqueNumbers = [...new Set(numbers)];

console.log(uniqueNumbers);

Result:

[1, 2, 3, 4]

### Interview answer

Set is a collection that stores unique values. If the same value is added multiple times, it is stored only once. It's commonly used for duplicate removal and fast membership checks.

---

# 3. WeakMap

This is where interviewers usually go deeper.

A WeakMap is similar to Map, but it has an important restriction:

WeakMap keys must be objects or non-registered symbols.

For typical interview examples, remember object keys.

const weakMap = new WeakMap();

const user = {
    name: "Ajay"
};

weakMap.set(user, "User data");

console.log(weakMap.get(user));

This works.

But:

weakMap.set("name", "Ajay");

throws an error because "name" is a primitive.

---

## Why is it called "Weak"?

The key is held weakly.

Suppose:

let user = {
    name: "Ajay"
};

const weakMap = new WeakMap();

weakMap.set(user, "some data");

Now:

user = null;

If there are no other references to the original object, it can become eligible for garbage collection.

The WeakMap does not prevent that object from being garbage collected.

That's the important meaning of "weak".

---

## WeakMap has no normal iteration

Unlike Map, you cannot do:

weakMap.size

or:

for (const item of weakMap) {}

WeakMap is intentionally not enumerable.

Why?

Because garbage collection can happen at unpredictable times, so exposing its complete contents would create problems with reliable enumeration.

---

# 4. WeakSet

WeakSet is similar to Set, but it stores objects weakly.

const weakSet = new WeakSet();

const user = {
    name: "Ajay"
};

weakSet.add(user);

console.log(weakSet.has(user)); // true

But:

weakSet.add("Ajay");

is invalid because WeakSet is for objects (with the same non-registered-symbol nuance, but object values are the practical interview case).

Like WeakMap, WeakSet:

- Is not normally iterable
- Doesn't have a size property
- Holds objects weakly

---

# Map vs Object

Very common interview question.

Map:
- Keys can be any type
- Has size
- set(), get(), has()
- Easily iterable
- Maintains insertion order
- Designed specifically for key-value collections

Object:
- Keys are strings/symbols
- No direct size
- Property syntax / methods
- Can be iterated using methods like Object.entries()
- Modern objects have defined property-order rules, but they're not designed primarily as maps
- General-purpose object

### When would you use Map?

If you're explicitly building a key-value collection, Map is usually the better semantic choice.

---

# Map vs WeakMap

This is probably the most important comparison.

Map:
- Keys can be any value
- Strong references to keys
- Iterable
- Has size
- Useful for general key-value storage

WeakMap:
- Keys must be objects or non-registered symbols
- Weak references to object keys
- Not iterable
- No size
- Useful for associating metadata with objects

### Practical WeakMap example

Suppose you want to store private metadata for DOM elements:

const metadata = new WeakMap();

const button = document.querySelector("button");

metadata.set(button, {
    clicked: true
});

If the button is removed and no other reference exists, the associated entry can eventually disappear through garbage collection.

This helps avoid unnecessarily keeping objects alive.

---

# Set vs WeakSet

Set:
- Stores values
- Iterable
- Has size
- Strong references
- Can contain primitives

WeakSet:
- Stores objects
- Not iterable
- No size
- Weak references
- Object-focused

---

## Important Interview Question

### Why can't we iterate over WeakMap?

Good answer:

WeakMap keys are held weakly and can become eligible for garbage collection when there are no other strong references. Since garbage collection timing is not predictable, exposing all WeakMap entries through iteration or a reliable size would not be well-defined. Therefore WeakMap is intentionally non-iterable.

---

## Interview-level takeaway

If the interviewer asks "When would you use WeakMap?", a strong practical answer is:

I'd use WeakMap when I need to associate additional data with objects without preventing those objects from being garbage collected. A common example is storing metadata or private-looking associated data for objects whose lifetime should determine the lifetime of that metadata.
