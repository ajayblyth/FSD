#  What is `useMemo()`? EXPENSIVE CALCUALTION

> **"useMemo is a React Hook that we use to memoizes the result of an expensive calculation. It allows React to reuse a previously calculated value instead of recalculating it on every render, when its dependencies haven't changed."**

### Basic example

Suppose we have an expensive calculation:

const result = expensiveCalculation(number);

Every time the component renders, the calculation runs again.

We can use:

const result = useMemo(() => {
return expensiveCalculation(number);
}, [number]);

Now React recalculates it when `number` changes.

number changes
↓
calculate again

number doesn't change
↓
reuse previous result

### Important

`useMemo` memoizes a **value/result**.

Think:

> **useMemo → remembers a value**

---

## Example

function ProductList({ products, search }) {
const filteredProducts = useMemo(() => {
console.log("Filtering...");

return products.filter(product =>
product.name.toLowerCase().includes(search.toLowerCase())
    );
  }, [products, search]);

return (
\<div>
      {filteredProducts.map(product => (
\<p key={product.id}>{product.name}\</p>
      ))}
\</div>
  );
}

If some unrelated state changes, React can reuse the existing `filteredProducts` result as long as `products` and `search` haven't changed.

# useMemo() — EventHub My Events Example

The **My Events** page is a good example to understand *why* `useMemo` exists.

Suppose EventHub gets the organizer's events:

const [events, setEvents] = useState([...]);
const [search, setSearch] = useState("");
const [filter, setFilter] = useState("all");

You might need to calculate:

events
  ↓
filter by All / Upcoming / Drafts / Past
  ↓
filter by search text
  ↓
filteredEvents
  ↓
display cards

---

## Without useMemo

const filteredEvents = events
  .filter(event => {
    // status/date filtering
  })
  .filter(event =>
    event.title.toLowerCase().includes(search.toLowerCase())
  );

This calculation happens **every time the component renders**.

For example, suppose you have:

1000 events

and the organizer changes some unrelated UI state:

setSomething(true);

The component re-renders.

Even though:

events = same
search = same
filter = same

React still executes:

1000 events
   ↓
filter
   ↓
search

again.

---

## With useMemo

const filteredEvents = useMemo(() => {
  return events
    .filter(event => {
      // status/date filtering
    })
    .filter(event =>
      event.title.toLowerCase().includes(search.toLowerCase())
    );
}, [events, search, filter]);

Now React remembers the **result**.

First render
events + search + filter
        ↓
calculate
        ↓
filteredEvents
        ↓
React remembers it

If an unrelated state changes:

Unrelated state changes
        ↓
Component re-renders
        ↓
events ❌ unchanged
search ❌ unchanged
filter ❌ unchanged
        ↓
Reuse previous filteredEvents

But if the organizer changes the search:

search changes
     ↓
Dependency changed
     ↓
Run filtering again
     ↓
Save new result

---

## So what's the actual benefit?

Imagine:

events = 5,000

and filtering involves several operations.

### Without useMemo

Every render
     ↓
filter 5,000 events
     ↓
filter again for search

### With useMemo

Only when events/search/filter change
     ↓
filter 5,000 events

Unrelated re-renders can reuse the existing result.

## Important 2nd use 
2. It also preserves the reference of the memoized value

For example:

const data = useMemo(() => {
  return { name: "Ajay" };
}, []);

React creates the object once and reuses that same object reference on later renders.

Why does that matter?

Because JavaScript objects are compared by reference, not just their contents.

{ name: "Ajay" } === { name: "Ajay" }

is:

false

They are two different objects.

But:

const data = useMemo(() => ({ name: "Ajay" }), []);

means React keeps the same data reference between renders.

# 21. What is `useCallback()`?

> **"useCallback is a React Hook that memoizes a function reference. It allows React to reuse the same function between renders unless its dependencies change, which is useful when passing callbacks to memoized child components."**

Example:
const handleClick = useCallback(() => {
console.log("Clicked");
}, []);

The function reference is preserved between renders.

### Think:

useMemo
→ memoizes a value OF expensive calculation

useCallback
→ memoizes a function

That's one of the most important things to remember.
---

# Why does function identity matter?

Consider:

function Parent() {
const handleClick = () => {
console.log("Clicked");
  };

return \<Child onClick={handleClick} />;
}

Every time `Parent` renders, this creates a **new function object**.

Even though the function code looks the same:

Render 1 → function A
Render 2 → function B
Render 3 → function C

So from React's perspective:

A !== B

If `Child` is memoized with `React.memo`, that new function prop can cause the child to render again.

We can use:

const handleClick = useCallback(() => {
console.log("Clicked");
}, []);

Now React can reuse the same function reference while the dependencies remain unchanged.

# useCallback() — EventHub Real-World Example

A realistic EventHub example is the **My Events page**, where the parent renders many `EventCard` components.

Each card has a **Delete Event** button.


MyEvents
   │
   ├── EventCard 1 → Delete
   ├── EventCard 2 → Delete
   └── EventCard 3 → Delete

## Without useCallback

### `MyEvents.jsx`

import { useState } from "react";
import EventCard from "./EventCard";

function MyEvents({ events }) {
  const [search, setSearch] = useState("");

  const handleDelete = (eventId) => {
    console.log("Deleting:", eventId);
  };

  return (
    <>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
      />

      {events.map((event) => (

        <EventCard
          key={event._id}
          event={event}
          onDelete={handleDelete}
        />

      ))}
    </>
  );
}

export default MyEvents;

Every time `MyEvents` re-renders, a **new function reference** is created:


Render 1 → handleDelete = Function A
Render 2 → handleDelete = Function B
Render 3 → handleDelete = Function C

Even though the function does the same thing.

If `EventCard` uses:

export default React.memo(EventCard);

the changed function reference can cause the child to re-render.

---

# With useCallback

import { useCallback, useState } from "react";
import EventCard from "./EventCard";

function MyEvents({ events }) {
  const [search, setSearch] = useState("");

  const handleDelete = useCallback((eventId) => {
    console.log("Deleting:", eventId);
  }, []);

  return (
    <>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
      />

      {events.map((event) => (
        <EventCard
          key={event._id}
          event={event}
          onDelete={handleDelete}
        />
      ))}
    </>
  );
}

export default MyEvents;

Now React can reuse the **same function reference** while dependencies haven't changed:


Render 1 → Function A
Render 2 → Function A
Render 3 → Function A

So a memoized `EventCard` can avoid unnecessary re-renders when its other props haven't changed.

---

## `EventCard.jsx`

import React from "react";

function EventCard({ event, onDelete }) {
  return (
    <div>
      <h3>{event.title}</h3>

      <button onClick={() => onDelete(event._id)}>
        Delete
      </button>
    </div>
  );
}

export default React.memo(EventCard);

### Why this is useful in EventHub

If `MyEvents` has many event cards and the organizer changes unrelated UI such as the search input:


MyEvents re-renders
       ↓
Without useCallback
new handleDelete function
       ↓
memoized EventCards may re-render

With `useCallback`:


MyEvents re-renders
       ↓
same handleDelete reference
       ↓
React.memo can skip unnecessary EventCard renders

**Important:** `useCallback` doesn't automatically prevent re-renders. It is useful when **function reference stability matters**, especially with `React.memo` or Hook dependencies.

## Easy Interview Definition

> **useCallback is a React Hook that memoizes a function, allowing React to reuse the same function reference between renders until its dependencies change.**

Remember:


useMemo
→ remembers a VALUE / calculated result

useCallback
→ remembers a FUNCTION / function reference


# 22. What is `React.memo()`?

### Interview-style introduction

> **"React.memo is a higher-order component used to memoize a functional component. If the component receives the same props, React can skip rendering it and reuse the previous result."**

Example:

const User = React.memo(function User({ name }) {
console.log("User rendered");

return \<h2>{name}\</h2>;
});

Suppose:

Parent
├── count changes
└── User receives same name

Normally, the child can render again when the parent renders.

With:

React.memo(User)

React can skip the child render when its props haven't changed.

---

## But here's an important interview detail

`React.memo` performs a **shallow comparison of props by default**.

Primitive values are straightforward:

<User name="Ajay" />

But objects and arrays are references.

For example:

const user = {
  name: "Ajay"
};

\<User user={user} />

If a new object is created on every parent render:

const user = {
  name: "Ajay"
};

then the reference changes.

So even though:

name = Ajay

is the same, the object itself is a new reference.

That's where `useMemo` can become useful.

# 23. How `useMemo`, `useCallback`, and `React.memo` Work Together

This is **very interview-worthy**.

Imagine:

Parent
↓
Memoized Child

Parent has:

const data = useMemo(() => {
return { name: "Ajay" };
}, []);

const handleClick = useCallback(() => {
console.log("Clicked");
}, []);

Then:

<Child
data={data}
onClick={handleClick}
/>

and:

const Child = React.memo(function Child({ data, onClick }) {
return \<h2>{data.name}\</h2>;
});

Now:

* `React.memo` → prevents unnecessary child rendering when props are unchanged.
* `useMemo` → keeps the **object/value reference** stable.
* `useCallback` → keeps the **function reference** stable.

### The mental model

React.memo
↓
"Should I render this child?"

useMemo
↓
"Keep this value/object stable."

useCallback
↓
"Keep this function stable."

# Important: Don't overuse memoization

This is a common interview follow-up.

You should **not** automatically use:

useMemo()
useCallback()
React.memo()

everywhere.

They themselves add complexity and have a cost.

Use them when they provide a meaningful benefit, such as:

* Expensive calculations
* Large lists
* Memoized child components
* Stable object/array references
* Stable callback references when needed

A good interview answer:

> "I use memoization selectively. I don't add useMemo or useCallback everywhere because unnecessary memoization can add complexity without providing a real performance benefit."

# 24. `useEffect()` vs `useMemo()`

This is a very common interview question.

### Interview-style introduction

> **"The main difference is that useEffect is used for side effects, while useMemo is used to memoize a calculated value. useEffect runs after rendering to synchronize with external systems, whereas useMemo calculates and returns a value during rendering."**

### Compare them

| `useEffectuseMemo`                              |                                      |
| ----------------------------------------------- | ------------------------------------ |
| Handles side effects                            | Memoizes a calculated value          |
| Used for API calls, subscriptions, timers, etc. | Used for expensive calculations      |
| Doesn't return a calculated value for rendering | Returns a memoized value             |
| Runs after rendering                            | Calculation happens during rendering |
| Used to synchronize with external systems       | Used for performance optimization    |

### Example

API call:

useEffect(() => {
fetchUsers();
}, []);

Calculation:

const total = useMemo(() => {
return calculateTotal(items);
}, [items]);

### Very important

Don't use `useMemo` as a replacement for `useEffect`.

Bad thinking:

> "I need to run some code when a value changes, so I'll use useMemo."

Instead:

* **Need a side effect? →** **`useEffect`**
* **Need a calculated value? →** **`useMemo`**

# One More Important Distinction

Interviewers sometimes ask:

> "Is `useMemo` used to prevent re-renders?"

The precise answer is:

**Not directly.**

`useMemo` memoizes a **value**.

`React.memo` is the one that can skip rendering a component when its props haven't changed.

`useCallback` memoizes a **function reference**.

So:

useMemo
→ value

useCallback
→ function

React.memo
→ component rendering

This distinction is worth remembering.

---

# Quick Interview Revision

### `useMemo`

> Memoizes the result of a calculation so it can be reused when dependencies haven't changed.

### `useCallback`

> Memoizes a function reference so the same function can be reused between renders when dependencies haven't changed.

### `React.memo`

> Memoizes a component and can skip rendering when its props are unchanged.

### Together

useMemo      → stable value
useCallback  → stable function
React.memo   → skip unnecessary child render

### `useEffect` vs `useMemo`

useEffect → side effects
useMemo   → calculated values
