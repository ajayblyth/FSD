# React Interview Preparation — Part 4: Performance

Now we move into a very common interview cluster:

**`useMemo`** **→** **`useCallback`** **→** **`React.memo`** **→ how they work together →** **`useEffect`** **vs** **`useMemo`**

The key is to understand **what problem each one solves**, because interviewers often ask them together.

---

#  What is `useMemo()`?

> **"useMemo is a React Hook that memoizes the result of a calculation. It allows React to reuse a previously calculated value instead of recalculating it on every render, when its dependencies haven't changed."**

### Basic example

Suppose we have an expensive calculation:

const result = expensiveCalculation(number);

Every time the component renders, the calculation runs again.

We can use:

const result = useMemo(() => {
return expensiveCalculation(number);
}, [number]);

Now React recalculates it when `number` changes.

number changes
↓
calculate again

number doesn't change
↓
reuse previous result

### Important

`useMemo` memoizes a **value/result**.

Think:

> **useMemo → remembers a value**

---

## Example

function ProductList({ products, search }) {
const filteredProducts = useMemo(() => {
console.log("Filtering...");

return products.filter(product =>
product.name.toLowerCase().includes(search.toLowerCase())
    );
  }, [products, search]);

return (
\<div>
      {filteredProducts.map(product => (
\<p key={product.id}>{product.name}\</p>
      ))}
\</div>
  );
}

If some unrelated state changes, React can reuse the existing `filteredProducts` result as long as `products` and `search` haven't changed.

# 21. What is `useCallback()`?

### Interview-style introduction

> **"useCallback is a React Hook that memoizes a function reference. It allows React to reuse the same function between renders unless its dependencies change, which is useful when passing callbacks to memoized child components."**

Example:

const handleClick = useCallback(() => {
console.log("Clicked");
}, []);

The function reference is preserved between renders.

### Think:

useMemo
→ memoizes a value

useCallback
→ memoizes a function

That's one of the most important things to remember.

---

# Why does function identity matter?

Consider:

function Parent() {
const handleClick = () => {
console.log("Clicked");
  };

return \<Child onClick={handleClick} />;
}

Every time `Parent` renders, this creates a **new function object**.

Even though the function code looks the same:

Render 1 → function A
Render 2 → function B
Render 3 → function C

So from React's perspective:

A !== B

If `Child` is memoized with `React.memo`, that new function prop can cause the child to render again.

We can use:

const handleClick = useCallback(() => {
console.log("Clicked");
}, []);

Now React can reuse the same function reference while the dependencies remain unchanged.

# 22. What is `React.memo()`?

### Interview-style introduction

> **"React.memo is a higher-order component used to memoize a functional component. If the component receives the same props, React can skip rendering it and reuse the previous result."**

Example:

const User = React.memo(function User({ name }) {
console.log("User rendered");

return \<h2>{name}\</h2>;
});

Suppose:

Parent
├── count changes
└── User receives same name

Normally, the child can render again when the parent renders.

With:

React.memo(User)

React can skip the child render when its props haven't changed.

---

## But here's an important interview detail

`React.memo` performs a **shallow comparison of props by default**.

Primitive values are straightforward:

<User name="Ajay" />

But objects and arrays are references.

For example:

const user = {
  name: "Ajay"
};

\<User user={user} />

If a new object is created on every parent render:

const user = {
  name: "Ajay"
};

then the reference changes.

So even though:

name = Ajay

is the same, the object itself is a new reference.

That's where `useMemo` can become useful.

# 23. How `useMemo`, `useCallback`, and `React.memo` Work Together

This is **very interview-worthy**.

Imagine:

Parent
↓
Memoized Child

Parent has:

const data = useMemo(() => {
return { name: "Ajay" };
}, []);

const handleClick = useCallback(() => {
console.log("Clicked");
}, []);

Then:

<Child
data={data}
onClick={handleClick}
/>

and:

const Child = React.memo(function Child({ data, onClick }) {
return \<h2>{data.name}\</h2>;
});

Now:

* `React.memo` → prevents unnecessary child rendering when props are unchanged.
* `useMemo` → keeps the **object/value reference** stable.
* `useCallback` → keeps the **function reference** stable.

### The mental model

React.memo
↓
"Should I render this child?"

useMemo
↓
"Keep this value/object stable."

useCallback
↓
"Keep this function stable."

---

# Important: Don't overuse memoization

This is a common interview follow-up.

You should **not** automatically use:

useMemo()
useCallback()
React.memo()

everywhere.

They themselves add complexity and have a cost.

Use them when they provide a meaningful benefit, such as:

* Expensive calculations
* Large lists
* Memoized child components
* Stable object/array references
* Stable callback references when needed

A good interview answer:

> "I use memoization selectively. I don't add useMemo or useCallback everywhere because unnecessary memoization can add complexity without providing a real performance benefit."

# 24. `useEffect()` vs `useMemo()`

This is a very common interview question.

### Interview-style introduction

> **"The main difference is that useEffect is used for side effects, while useMemo is used to memoize a calculated value. useEffect runs after rendering to synchronize with external systems, whereas useMemo calculates and returns a value during rendering."**

### Compare them

| `useEffectuseMemo`                              |                                      |
| ----------------------------------------------- | ------------------------------------ |
| Handles side effects                            | Memoizes a calculated value          |
| Used for API calls, subscriptions, timers, etc. | Used for expensive calculations      |
| Doesn't return a calculated value for rendering | Returns a memoized value             |
| Runs after rendering                            | Calculation happens during rendering |
| Used to synchronize with external systems       | Used for performance optimization    |

### Example

API call:

useEffect(() => {
fetchUsers();
}, []);

Calculation:

const total = useMemo(() => {
return calculateTotal(items);
}, [items]);

### Very important

Don't use `useMemo` as a replacement for `useEffect`.

Bad thinking:

> "I need to run some code when a value changes, so I'll use useMemo."

Instead:

* **Need a side effect? →** **`useEffect`**
* **Need a calculated value? →** **`useMemo`**

---

# One More Important Distinction

Interviewers sometimes ask:

> "Is `useMemo` used to prevent re-renders?"

The precise answer is:

**Not directly.**

`useMemo` memoizes a **value**.

`React.memo` is the one that can skip rendering a component when its props haven't changed.

`useCallback` memoizes a **function reference**.

So:

useMemo
→ value

useCallback
→ function

React.memo
→ component rendering

This distinction is worth remembering.

---

# Quick Interview Revision

### `useMemo`

> Memoizes the result of a calculation so it can be reused when dependencies haven't changed.

### `useCallback`

> Memoizes a function reference so the same function can be reused between renders when dependencies haven't changed.

### `React.memo`

> Memoizes a component and can skip rendering when its props are unchanged.

### Together

useMemo      → stable value
useCallback  → stable function
React.memo   → skip unnecessary child render

### `useEffect` vs `useMemo`

useEffect → side effects
useMemo   → calculated values
