# 9. What is `useState()`?

### Interview-style introduction

> "useState is a React Hook that allows a functional component to store and manage data that can change over time. When we update that state using its setter function, React re-renders the component so the updated value is reflected in the UI dynamically."

### Basic example

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <>
      <h2>{count}</h2>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </>
  );
}

Here:

count       → current state
setCount    → function used to update state
0           → initial value

So:

const [count, setCount] = useState(0);

means:

> Create a state variable called `count`, initially `0`, and give me `setCount` to update it.

### Important

Don't modify state directly:

count = count + 1; // ❌

Use:

setCount(count + 1); // ✅

Because React needs the state update to know that it should update the UI.

---

## Updating State Using the Previous State

Sometimes the new state depends on the previous state.

For example:

const [count, setCount] = useState(0);

If we do:

setCount(count + 1);
setCount(count + 1);
setCount(count + 1);

We might expect the count to become:

0 → 1 → 2 → 3

But all three updates are using the same `count` value from the current render.

If `count` is `0`, they are effectively:

setCount(1);
setCount(1);
setCount(1);

So the result is:

1

### Functional Updater

When the new state depends on the previous state, use the functional updater:

setCount(prev => prev + 1);

For example:

### src/App.jsx — Functional Updater Example

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(prev => prev + 1);
    setCount(prev => prev + 1);
    setCount(prev => prev + 1);
  }

  return (
    <>
      <h2>{count}</h2>

      <button onClick={handleClick}>
        Increase
      </button>
    </>
  );
}

export default Counter;
Now React can process each update using the latest previous value:

0
↓
prev = 0 → 1
↓
prev = 1 → 2
↓
prev = 2 → 3

Result:

3

### Why do we use `prev`?

`prev` represents the previous/latest state value provided to that state update.

So:

setCount(prev => prev + 1);

means:

> Take the previous state value and increase it by 1.

### When should we use the `prev` pattern?

Use the functional updater whenever the new state depends on the previous state.

Counter:

setCount(prev => prev + 1);

Decrement:

setCount(prev => prev - 1);

Boolean toggle:

setIsOpen(prev => !prev);

Array:

setUsers(prev => [...prev, newUser]);

Object:

setUser(prev => ({
  ...prev,
  age: prev.age + 1
}));

### Easy rule to remember

If the new value does NOT depend on the previous value:

setName("Ajay");

If the new value DOES depend on the previous value:

setCount(prev => prev + 1);

Think:

New state depends on old state?
        ↓
      YES
        ↓
Use prev
        ↓
setState(prev => ...)

---

## State can hold different types

### String

const [name, setName] = useState("");

### Number

const [age, setAge] = useState(25);

### Boolean

const [isOpen, setIsOpen] = useState(false);

### Array

const [users, setUsers] = useState([]);

### Object

const [user, setUser] = useState({
  name: "Ajay",
  age: 25
});

# 10. What causes a React component to re-render?

This is an important interview question.

### Interview-style introduction

> **"A component generally re-renders when its state changes, when its parent re-renders, or when the context value it consumes changes. Changes to its props can also cause it to render with the new values."**

The major cases you should remember:

### 1. State update

setCount(count + 1);

The component re-renders.

---

### 2. Parent re-renders

If:

Parent
↓
Child

and Parent re-renders, the Child normally gets rendered again as part of that process.

This is one reason `React.memo` can sometimes be useful.

---

### 3. Props change

If a parent passes new/different props to a child, the child can re-render.

<User name={name} />

If `name` changes, the child receives the new prop.

---

### 4. Context value changes

If a component consumes a Context and its relevant Context provider value changes, the consumer can re-render.

---

### Important clarification

**A re-render does NOT mean the entire webpage/DOM is recreated.**

React re-runs the component's rendering logic and then determines what actual DOM changes are necessary.

This distinction is commonly useful in interviews.

# 11. What are React Hooks?

> **"Hooks are functions provided by React that allow functional components to use features such as state, side effects and context. They were introduced in React 16.8."**

Some important Hooks:

| HookPurpose   |                                    |
| ------------- | ---------------------------------- |
| `useState`    | Manage state                       |
| `useEffect`   | Handle side effects                |
| `useRef`      | Store a mutable value / access DOM |
| `useContext`  | Access Context                     |
| `useMemo`     | Memoize a calculated value         |
| `useCallback` | Memoize a function                 |

We've already seen:

useState
useContext

Now we'll focus on `useEffect`.

### Important Rules of Hooks

Hooks should:

* Be called at the **top level** of a component or custom Hook.
* Not be called inside loops, conditions, or nested functions.
* Generally be called from React function components or custom Hooks.

❌ Don't:

if (isLoggedIn) {
const [user, setUser] = useState(null);
}

✅ Do:

const [user, setUser] = useState(null);

if (isLoggedIn) {
// use user
}

The reason is that React relies on Hooks being called in the **same order on every render**.
 if we don't follow this rule, React can lose track of which state belongs to which Hook.
Think of Hooks like numbered boxes

React internally treats them conceptually like:

Box 1 → useState
Box 2 → useEffect
Box 3 → useState

Every render, React expects:

Box 1 → same Hook
Box 2 → same Hook
Box 3 → same Hook

If you put a Hook inside a condition:

if (condition) {
    useState();
}

sometimes you give React:

Render 1:
Box 1 → useState
Box 2 → useEffect

and sometimes:

Render 2:
Box 1 → useEffect

The positions no longer match.

That's the core reason

Hooks aren't identified by the variable name. React keeps track of Hooks based on their call order.

# 12. What is `useEffect()`?

This is one of the **highest-priority React interview topics**.

### Interview-style introduction
Normal rendering = Props/State → JSX/UI

Anything like API calls, timers, event subscriptions, localStorage, or changing the browser DOM is outside that normal rendering process and is generally treated as a side effect.


“A side effect is an operation that happens outside the normal rendering of a component, such as making an API call, setting a timer, adding an event listener, or interacting with browser storage.”

> **"useEffect is a React Hook used to perform side effects in a component. For example, we can use it for API calls, subscriptions, timers, event listeners, or synchronizing React state with something outside the component."**

The important word is:

> **Side effect**

A side effect is something that happens outside simply calculating the UI.

Examples:

* API request
* `setInterval`
* `setTimeout`
* Browser event listener
* Subscription
* Updating document title
* Working with external systems

When Strict Mode is on, React will run one extra development-only setup+cleanup cycle before the first real setup. This is a stress-test that ensures that your cleanup logic “mirrors” your setup logic and that it stops or undoes whatever the setup is doing. If this causes a problem, implement the cleanup function.
---

## Basic syntax

useEffect(() => {
// side effect
}, []);

Example:

import { useEffect } from "react";

function App() {
useEffect(() => {
console.log("Component rendered");
  }, []);

return \<h1>Hello\</h1>;
}

#3 13. Dependency Array in `useEffect`

This is extremely important because interviewers commonly ask:

> "When does useEffect run?"

The answer depends on the dependency array.

There are **three important cases**.

---

## Case 1 — No dependency array

useEffect(() => {
console.log("Effect");
});

The effect runs **after every render**.

Render
↓
Effect
↓
State update
↓
Render
↓
Effect

---

## Case 2 — Empty dependency array

useEffect(() => {
console.log("Effect");
}, []);

It runs after the component's initial mount.

Common use:

useEffect(() => {
fetchUsers();
}, []);

This is commonly used when you want to perform something when the component initially appears.

### Important interview nuance

In **development with React Strict Mode**, you may see an effect run more than once during development. Don't confuse that development behavior with the basic dependency rule.

---

## Case 3 — Dependencies

import { useEffect, useState } from "react";

function User({ userId }) {
  useEffect(() => {
    console.log("User changed");
  }, [userId]);

  return <h2>User ID: {userId}</h2>;
}

function App() {
  const [userId, setUserId] = useState(1);

  return (
    <div>
      <User userId={userId} />

      <button onClick={() => setUserId(userId + 1)}>
        Change User
      </button>
    </div>
  );
}

export default App;
The effect runs after the initial render and when `userId` changes.

For example:

userId = 1
↓
Effect

userId = 1
↓
No dependency change

userId = 2
↓
Effect runs again

---

## Easy interview table

| DependencyEffect runs |                                      |
| --------------------- | ------------------------------------ |
| No array              | After every render                   |
| `[]`                  | After initial mount                  |
| `[value]`             | Initial mount + when `value` changes |

That's the part you should remember.

## 14. `useEffect()` Cleanup

Another important interview point.

Sometimes an effect creates something that needs to be cleaned up.

Example:

useEffect(() => {
const timer = setInterval(() => {
console.log("Running");
  }, 1000);

return () => {
clearInterval(timer);
  };
}, []);

The function returned from `useEffect` is the **cleanup function**.

Cleanup is important for things such as:

* Timers
* Event listeners
* Subscriptions
* Connections

Conceptually:

Effect starts
↓
Something is created
↓
Component unmounts / dependency changes
↓
Cleanup runs

### Example with event listener

useEffect(() => {
const handleResize = () => {
console.log(window\.innerWidth);
  };

window\.addEventListener("resize", handleResize);

return () => {
window\.removeEventListener("resize", handleResize);
  };

}, []);

# 15. What is `useRef()`?

### Interview-style introduction

“useRef is a React Hook used to store a value between renders without causing a re-render when the value changes. It can also be used to access a DOM element directly.”

There are two major uses you should know.

---

## Use 1 — Accessing a DOM element

Example:

import { useRef } from "react";

function App() {


const inputRef = useRef(null);
const focusInput = () => {
inputRef.current.focus();
  };


return (
<>
\<input ref={inputRef} />
\<button onClick={focusInput}>
        Focus
\</button>
\</>
  );
}

Here:

inputRef.current

refers to the actual input element.

So we can call:

inputRef.current.focus();

---

## Use 2 — Store a value without causing a re-render

const countRef = useRef(0);

Update it:

countRef.current = countRef.current + 1;

Changing:

countRef.current

**does not cause the component to re-render.**

Then why useRef?
Because sometimes we don't need the value displayed on the UI.
For example:
const timerRef = useRef(null);

timerRef.current = setInterval(...);

We just need to remember the timer ID between renders. We don't need to display the timer ID on the screen.
---

# `useState` vs `useRef`

Very common interview question:

| `useStateuseRef`             |                                                                           |
| ---------------------------- | ------------------------------------------------------------------------- |
| Stores state                 | Stores a mutable value/reference                                          |
| Updating it causes re-render | Updating `.current` doesn't cause re-render                               |
| Used for UI data             | Often used for DOM references or values that shouldn't trigger UI updates |
| Access with variable         | Access with `.current`                                                    |

Easy way to remember:

> **If changing the value should update the UI → state.**

> **If I need to remember a value but don't want that change itself to trigger a render → ref.**
