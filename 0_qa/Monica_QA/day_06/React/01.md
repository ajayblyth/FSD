# 1. What is React.js?

> **"Basically, React is a JavaScript library used for building user interfaces, especially interactive web applications.
It allows us to break the UI into small, reusable components and efficiently update the UI when data changes."**

### Concept
The main idea was to build a UI using **components**.
For example, an e-commerce application can be divided into:

App
├── Navbar
├── ProductList
│ └── ProductCard
├── Cart
└── Footer

Each part can be a separate React component. When some data changes within a part, 
React updates the necessary part of the UI only instead of refreshing entire page.

### Why do we use React?

Without React, we may have to manually find DOM elements and update them using JavaScript.

React lets us describe:
"We tell React what the UI should look like by returning JSX from our components. When the component's state or props change, React renders the component again and updates the necessary parts of the DOM."


### Important interview point

React is technically a **library**, not a complete framework.
React is the core library that handles things like: Components, State ,Props ,Rendering logic etc.
Now because React mainly focuses on the **UI layer**. Things like routing, state management, etc. can be added using additional libraries.

# 3. What is JSX?

> "JSX stands for JavaScript XML. It allows us to write HTML-like syntax inside JavaScript code, which makes it easier to describe the UI in React. JSX is then transformed into regular JavaScript that React can understand."

Example:

const element = <h1>Hello Ajay</h1>;

It looks like HTML, but it's actually JSX syntax inside JavaScript.

### Why do we use JSX?

One major advantage of JSX is that we can write the UI structure and the JavaScript logic/data together inside the same component.

Without JSX, we would have to create and manipulate DOM elements using JavaScript:

const heading = document.createElement("h1");
heading.textContent = "Hello Ajay";

With JSX:

function App() {
  const name = "Ajay";

  return <h1>Hello {name}</h1>;
}

This makes the UI code easier to read, write, and maintain, because the UI and the data/logic used by that UI are kept together.

### Note

JSX is not HTML, and it is not directly understood as HTML by the browser.

A JSX compiler/transpiler converts JSX syntax into regular JavaScript that the browser/runtime can execute.

The commonly known tool is Babel.

The basic flow is:

JSX
↓
Babel / JSX transformation
↓
JavaScript
↓
React / React DOM
↓
Browser DOM

---

### JSX can contain JavaScript

We use {} to put JavaScript expressions inside JSX.

const name = "Ajay"; // JavaScript

return <h1>Hello {name}</h1>; // JSX, with JavaScript expression {name}

Output: Hello Ajay

Another example:
const age = 25;
return <p>{age + 5}</p>;

Output:

30

So the structure is:

JavaScript
↓
JSX
↓
JavaScript expression inside JSX using {}

---

### Important JSX rules

#### Class becomes `className`

<div className="container">

not:

<div class="container">

#### JavaScript expressions use `{}`

<h1>{name}</h1>

#### JSX must return one parent element

This:

return (
  <div>
    <h1>Hello</h1>
    <p>Welcome</p>
  </div>
);

works.

We can also use a Fragment:

return (
  <>
    <h1>Hello</h1>
    <p>Welcome</p>
  </>
);

# 5. Functional vs Class Components

> **"React supports both functional and class components. Earlier, class components were commonly used for state and lifecycle methods, but modern React mainly uses functional components with Hooks, so functional components are the preferred approach today."**

### Functional component

function User() {

return <h2>John</h2>;
}

It's simply a JavaScript function that returns JSX.

With Hooks:

function Counter() {

const [count, setCount] = useState(0);

return <h2>{count}</h2>;
}

---

### Class component

class User extends React.Component {

render() {
return <h2>John</h2>;
}
}

### Main difference

| FunctionalClass                  |                           |
| -------------------------------- | ------------------------- |
| JavaScript function              | JavaScript class          |
| Uses Hooks                       | Uses lifecycle methods    |
| Less code                        | More boilerplate          |
| Modern preferred approach        | Mostly legacy code        |
| Easier to reuse logic with Hooks | Uses class-based patterns |

### Interview point

You don't need to deeply learn class components for modern React interviews unless the company has a legacy React codebase.

# 6. Props vs State
In React, props are the properties/data that a parent passes to a child component.

"we use props when a parent component needs to pass data to a child component, whereas we use state when a component needs to manage its own changing data. Props are received from the parent, while state is managed inside the component and can be updated using its setter function."

# Props — Complete Example

### App.jsx — Parent

import User from "./components/User";

function App() {
  return 
  <User name="Ajay" />;
}

export default App;

### components/User.jsx — Child

function User(props) {
  return <h2>{props.name}</h2>;
}

export default User;

### How does the child get the props?

The parent passes the data here:

<User name="Ajay" />

name="Ajay" is a prop.

//React passes that prop to the User component.
So conceptually, React provides the child with:

{
  name: "Ajay"
}

That's why inside the child:

function User(props) {
  return <h2>{props.name}</h2>;
}

props.name gives: Ajay

### Flow
App.jsx
↓
<User name="Ajay" />
↓
React passes the prop
↓
User.jsx
↓
props.name
↓
"Ajay"

### Import/Export vs Props

import/export
→ Makes the component available between files.

props
→ Passes data from the parent component to the child component.

So:

App.jsx
   ↓
import/export
   ↓
User component is available

App.jsx
   ↓
props
   ↓
User receives data

Props are generally **read-only** from the child's perspective.

# State

"State is data that a component needs to remember and manage over time. When that data changes, React re-renders the component so the updated value can be reflected in the UI."

### Counter.jsx
import { useState } from "react";

function Counter() {

  const [count, setCount] = useState(0);

  return (
    <>
      <h2>{count}</h2>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </>
  );
}

export default Counter;

Here `count` is state.

The component can update it using:

setCount(...)

## Props in React#

Props stands for "properties".

Props are values/data passed from a parent component to a child component.

The important point is that props are not limited to one type of value. We can pass different JavaScript values as props.

## 1. String Props

Parent:

<User name="Ajay" />

Child:

function User(props) {
  return <h2>{props.name}</h2>;
}

Here:

name → prop name
"Ajay" → prop value

---

## 2. Number Props

Parent:

<User age={25} />

Child:

function User(props) {
  return <p>{props.age}</p>;
}

For numbers, we use `{}` because we are passing a JavaScript value.

---

## 3. Boolean Props

Parent:

<User isLoggedIn={true} />

Child:

function User(props) {
  return <p>{props.isLoggedIn ? "Logged In" : "Not Logged In"}</p>;
}

Boolean props are commonly used when we want to control some behavior or UI.

---

## 4. Array Props

Passing arrays is very common, especially when creating reusable list components.

Parent:

const fruits = ["Apple", "Mango", "Orange"];

<List items={fruits} />

Child:

function List(props) {
  return (
    <ul>
      {props.items.map(fruit => (
        <li key={fruit}>{fruit}</li>
      ))}
    </ul>
  );
}

Here:

items → prop name
fruits → array being passed

The child accesses the array using:

props.items

---

## 5. Object Props

Objects are also very commonly passed as props.

Parent:

const user = {
  name: "Ajay",
  age: 25,
  city: "Bangalore"
};

<User user={user} />

Child:

function User(props) {
  return (
    <>
      <h2>{props.user.name}</h2>
      <p>{props.user.age}</p>
      <p>{props.user.city}</p>
    </>
  );
}

Here:

user → prop name
user object → prop value

The child accesses the object using:

props.user

Then its properties:

props.user.name
props.user.age
props.user.city

---

## 6. Function Props

We can also pass a function as a prop.

This is very common when a child needs to communicate with its parent.

Parent:

function App() {

  const handleClick = () => {
    console.log("Button clicked");
  };

  return <Button onClick={handleClick} />;
}

Child:

function Button(props) {
  return (
    <button onClick={props.onClick}>
      Click Me
    </button>
  );
}

Here:

onClick → prop name
handleClick → function being passed

The child can call the function:

props.onClick()

This allows the child to trigger logic that belongs to the parent.

---

## 7. JSX / React Element as a Prop

We can also pass JSX as a prop.

Parent:

<Card content={<h2>Hello Ajay</h2>} />

Child:

function Card(props) {
  return (
    <div>
      {props.content}
    </div>
  );
}

Here:

content → prop name
<h2>Hello Ajay</h2> → JSX being passed

# Destructuring Props

Instead of writing:

function User(props) {
  return (
    <>
      <h2>{props.name}</h2>
      <p>{props.age}</p>
    </>
  );
}

We commonly destructure the props:

function User({ name, age }) {
  return (
    <>
      <h2>{name}</h2>
      <p>{age}</p>
    </>
  );
}

This is very common in React because it makes the component code cleaner.

# 7. Prop Drilling

Now this naturally follows from Props.

> **"Prop drilling happens when we pass data from a parent component to a deeply nested child through multiple intermediate components, even when those intermediate components don't actually need the data."**

Consider:
App
↓
Navbar
↓
Menu
↓
Profile

Suppose `App` has:

const user = {
name: "Ajay"
};

`But `Profile` needs it.

We might have to do:
<App>
↓ user
\<Navbar>
↓ user
\<Menu>
↓ user
\<Profile>
`
Even though `Navbar` and `Menu` don't need `user`.

That's **prop drilling**.

### Why is it a problem?

With deeply nested components:

* Code becomes harder to maintain
* Intermediate components receive unnecessary props
* Changing the data flow becomes harder

And this leads naturally to:

> **Can we share data without passing props through every component?**

Yes.

That's where **Context API / useContext()** comes in.

---

# 8. useContext()

### Interview-style introduction

> **"useContext is a React Hook that allows a component to access shared data from a Context,
 without having to pass that data through every intermediate component using props. 
It's commonly used to avoid prop drilling."**

The basic flow is:

Context
↓
Provider
↓
Any nested component

## useContext — Complete Multi-File Example

### src/context/UserContext.jsx

import { createContext } from "react";

const UserContext = createContext();

export default UserContext;


### src/App.jsx

import UserContext from "./context/UserContext";
import Profile from "./components/Profile";

function App() {
  return (
    <UserContext.Provider value={{ name: "Ajay" }}>
      <Profile />
    </UserContext.Provider>
  );
}

export default App;


### src/components/Profile.jsx

import { useContext } from "react";
import UserContext from "../context/UserContext";

function Profile() {
  const user = useContext(UserContext);

  return <h2>{user.name}</h2>;
}

export default Profile;


### Flow

UserContext.jsx
      ↓
export default UserContext
      ↓
App.jsx
      ↓
UserContext.Provider
      ↓
Profile.jsx
      ↓
useContext(UserContext)
      ↓
{ name: "Ajay" }

The Provider provides the value through the UserContext, and any component inside that Provider can access that value using the same UserContext with useContext().

Context
   ↓
Provider provides the value
   ↓
Child component consumes the value using useContext()
### Important

Context file:
→ Creates the Context and exports it.

App.jsx:
→ Imports the Context and provides the data using Provider.

Profile.jsx:
→ Imports the Context and accesses the data using useContext().


Notice what we **didn't** have to do:
App
↓ props
Navbar
↓ props
UserMenu
↓ props
Profile

Instead:

        UserContext
             ↓
App → Navbar → UserMenu → Profile
                              ↓
                         useContext()

### Important distinction

Context doesn't mean:

> "We should never use props."

Props are still the normal way to pass data between parent and child.

Context is useful when **many components need access to the same data**, especially when passing it through many levels would create prop drilling.

Common examples:

* Logged-in user
* Theme
* Language
* Application settings

# Quick Interview Revision

### React

> React is a JavaScript library for building interactive user interfaces using reusable components.

### JSX

> JSX allows us to write HTML-like syntax inside JavaScript and makes UI code easier to write.

### Component

> A component is a reusable piece of UI, usually represented by a JavaScript function that returns JSX.

### Functional vs Class

> Functional components are JavaScript functions and use Hooks, while class components use classes and lifecycle methods. Functional components are preferred in modern React.

### Props

> Props are data passed from a parent component to a child and are read-only from the child's perspective.

### State

> State is data managed inside a component and can change over time, causing the component to re-render.

### Prop Drilling

> Prop drilling is passing data through multiple intermediate components just to reach a deeply nested component.

### useContext

> useContext allows components to access shared Context data directly without passing props through every intermediate component.
