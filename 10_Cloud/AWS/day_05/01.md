===================
What Is Lambda?
Give AWS a function; it runs on demand

A function

you write one small piece of code that does one job

On demand

it runs only when triggered - a request, event, or schedule

No server

no EC2 to launch, patch, or keep running

Pay per run

charged only while it runs; idle = free

EC2: rent a whole computer, keep it running. Lambda: give AWS a function, it runs only when called.

===========================
What 'Serverless' Means
There IS a server - you just don't manage it

Serverless does NOT mean no server. Code always needs a computer. It means AWS owns and hides the
server - you never see it.

No provisioning

nothing to launch or set up

No patching

AWS keeps it secure & updated

Auto-scaling

1 or 10,000 requests - AWS handles it

Scales to zero

no requests = nothing runs = free

The 'event' shape depends on the trigger: a test event is your JSON; an HTTP request is the request's details.

The Problem: Secrets in Your Code
A secret written anywhere is a secret waiting to leak

X

In the code

anyone who reads it (or Git history) sees the password

X

In a .env file

still plain text on the server

X

In env variables

visible to anyone who can view the config

X

Rotating

change it = edit every place it's written

The fix: never store the value yourself. Keep it in a vault, and fetch it only when needed.

The Solution: A Vault

Store once (encrypted); fetch at runtime by name

A vault

AWS stores your secret encrypted

By name

your code fetches it by name (rds/contacts-db)

At runtime

the value is fetched when the code runs, never written in it

IAM + rotation

only allowed identities read it; can auto-rotate

Like a bank locker for passwords: valuables stay in the locker; you open it only when you need something.
