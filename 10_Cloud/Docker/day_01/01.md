1. WHY DOCKER
------------------------------------------------------------------------------
Problem
• Same application behaves differently on different machines.
• Cause: Different OS, Node version, DB version, Different libraries/dependencies
=> "It works on my machine" problem.

Solution
Docker fixes this by packaging the app together with everything it needs, so it runs the same everywhere.

Result
• Runs the same on every machine.

2. IMAGE vs CONTAINER
------------------------------------------------------------------------------
IMAGE
• Read-only blueprint/template which is used to create containers with different versions (e.g. Node v20 and v24)
 at the same time, with no conflict..
• Built once, shared many times.
• Immutable (cannot be edited directly).
One image can create many containers.
On one machine you can run multiple containers with different versions (e.g. Node v20 and v24) at the same time, with no conflict.

• Contains instructions about the base image, application files, dependencies and configuration.
• Defines how the container should be created and which command to run when it starts.

CONTAINER
• Running instance of an image. (Instance = a real, usable copy created from a template or blueprint.)
— one bundle = your app + all its depen­dencies. Portable (runs the same on any machine/OS) and lightweight (shares the host OS kernel, starts in seconds).

Relationship

      Image (Class)
            │
      docker run
            │
            ▼
      Container (Object)

One image → Multiple containers

Example

Node Image
   │
   ├── Container 1 (Node 20)
   ├── Container 2 (Node 20)
   └── Container 3 (Node 20)

Different versions can run together.

Node 20 Container
Node 24 Container

No conflicts.

Comparison
-d	-ai
Background	     Foreground
Terminal free	Terminal attached
No live logs	Live logs/output visible
No interaction	Interactive
----------------------------------------------------
| Flag  | Purpose                                                             |
| ----- | ------------------------------------------------------------------- |
| `-it` | Start a **new** container with an interactive terminal.             |
| `-ai` | Start an **existing stopped** container and reattach your terminal. |
| `-d`  | Run a container in the **background** (detached).                   |

10. PORT BINDING
------------------------------------------------------------------------------

A container is isolated — its internal port is not reachable from your machine directly. 
Bind a host port to a container port to reach it. Need Port Mapping

-p HOST:CONTAINER

Example

docker run -p 8080:3306 mysql

Meaning

Host Port
8080

↓

Container Port
3306

Format

HOST : CONTAINER

Host Port
• Your choice

Container Port
• Fixed by application

Examples

Mongo
27017

MySQL
3306

Only ONE container can use a host port at a time.

Example

Container A
8080 → 3306

Container B
8080 → 3306

❌ Error

Use

8080
8081

instead.

14. MONGODB + MONGO EXPRESS (Manual)
------------------------------------------------------------------------------
to check the port
docker image inspect mongo    or check in docker hub

STEP 1

Run MongoDB

docker run -d \
-p 27017:27017 \
--name mongo \
--network mongo-network \
-e MONGO_INITDB_ROOT_USERNAME=root \
-e MONGO_INITDB_ROOT_PASSWORD=qwert \
mongo

STEP 2

Run Mongo Express

docker run -d \
-p 8081:8081 \
--name mongo-express \
--network mongo-network \
-e ME_CONFIG_MONGODB_ADMINUSERNAME=root \
-e ME_CONFIG_MONGODB_ADMINPASSWORD=qwert \
-e ME_CONFIG_MONGODB_URL="mongodb://root:qwert@mongo:27017" \
mongo-express

Check both are on the same network

Run:

1.docker network inspect mongo-network

. Stop both containers
docker stop mongo mongo-express

2. Remove both containers
docker rm mongo mongo-express

3. Remove the network
docker network rm mongo-network

. Why does Mongo Express need a URL?

Because Mongo Express is a client, not the database.

It needs to know:

"Where is the MongoDB server I should connect to?"

Important
------------------------------------------------------------------------------
• Both containers are connected to the same network (mongo-network).
• Therefore, Mongo Express can reach MongoDB using the container name
  'mongo' instead of an IP address.
• Open Mongo Express in your browser at:
  localhost:8081

15. DOCKER COMPOSE
------------------------------------------------------------------------------

Purpose

Run multiple containers from one YAML file.

Benefits

• Easy configuration
• Easy editing
• No long docker run commands

YAML

• Uses indentation
• Use spaces
• No tabs

------------------------------------------------------------------------------
mongodb.yaml
------------------------------------------------------------------------------

services:

  mongo:
    image: mongo

    ports:
      - 27017:27017

    environment:
      - MONGO_INITDB_ROOT_USERNAME=root
      - MONGO_INITDB_ROOT_PASSWORD=qwert

  mongo-express:
    image: mongo-express

    ports:
      - 8081:8081

    environment:
      ME_CONFIG_MONGODB_URL:
        mongodb://root:qwert@mongo:27017/

      ME_CONFIG_BASICAUTH_USERNAME: root
      ME_CONFIG_BASICAUTH_PASSWORD: qwert
